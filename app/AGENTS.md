# 화면과 라우트 (`app/`)

## 맡는 것

화면 경로와 서버 라우트 핸들러다.

- 화면: 시작, 로그인, 체류 설정, 조건 입력·동의, 병원 연결, 병원 안내, 오늘, 전체 일정, 하루 일정,
  장소 상세, 한국어 카드, 긴급 연락, 더보기, 설정, 개인정보 고지, 보호자 링크 만들기·열기, 도움말(`/help`), 시안 보드
- 라우트 핸들러(`app/api/`): 일정, 교체 후보, 소개 문장, 주소 검색, 장소 상세, 지침 연결,
  로그인·세션, 상태 확인
- 앱 셸, 매니페스트, 서비스 워커 등록
- 토큰과 기능별 스타일 파일

## 맡지 않는 것

- 판정 규칙 — `src/engine/`, `src/stay/`
- 요청 검증·조립·로그 — `lib/server/`
- 저장과 변화 감지 — `lib/store/`, `lib/trip/`
- 재사용 부품 — `components/`

## 항상 지켜야 하는 것

- **모든 라우트 핸들러는 로그인 가드를 지난다.** 예외는 로그인 흐름과 상태 확인 경로뿐이다.
  새 경로를 만들 때 가드를 빠뜨리면 로그인 없이 열린다.
- 화면은 엔진을 직접 부르지 않는다. 라우트 핸들러를 통해 부른다. 판정 경로가 두 벌이 되면 결과가 어긋난다.
- **긴급 연락은 모든 화면에서 바닥에 붙어 있다.** 로그인 전·로그인 만료·오프라인에서도 보인다.
  내비가 있으면 다섯째 칸, 없으면 하단 긴급 바다. **떠 있는 버튼으로 만들지 않는다** —
  본문 위에 얹히면 누를 수 있는 요소를 덮고, 그 자리를 누른 사람이 긴급 전화를 걸게 된다.
- 보기 전용 상태에서는 화면에 '보기 전용 — 로그인이 필요합니다'를 표시하고 생성·편집·연동·공유를
  막는다. 조용히 읽기 전용으로 만들지 않는다.
- 로그인이 만료되거나 오프라인이어도 **긴급 연락, 한국어 카드, 오늘·내일 일정과 복귀 마감,
  보호자 사본 안전 정보, 개인정보 고지**는 보기 전용으로 열린다.
- **API 응답을 서비스 워커 캐시에 넣지 않는다.** 판정 결과가 오래된 채로 되살아나면 안 된다.
- 위치 권한을 요청하는 코드를 만들지 않는다. 브라우저 수준 차단 헤더가 이중 방어로 걸려 있다.
- 지도 링크에는 목적지 이름·좌표만 넣는다. 출발지 매개변수를 넣으면 숙소 좌표가 지도 사업자에게 간다.
- 상태는 **색만으로 구분하지 않는다.** 문구와 아이콘을 함께 쓴다.
- 외출이 없는 날(`NO_TOURISM`)을 오류 스타일로 그리지 않는다. 정상 결과다.
- '안전합니다'라고 쓰지 않는다. 사유 코드는 상태와 항상 함께 보여준다.
- 시안 보드는 **고정 데모 데이터만** 쓰고 사용자 데이터를 읽지 않으며 내비에 노출하지 않는다.
  `test/design-board-boundary.test.js`가 저장소·알림 런타임 import를 막는다.

## 구현 방식

- 라우트 핸들러는 얇다 — 검증·조립·로그는 서버 부품에 맡기고 여기서는 연결만 한다.
- 화면 문구는 기능별 이름공간 파일에서 가져온다. 화면 파일에 문자열을 직접 쓰지 않는다.
- 스타일은 토큰 파일 + 기능별 파일 구조다. 화면 파일에 색·크기 값을 직접 쓰지 않는다.
- 하단 내비는 다섯 개다: 오늘 · 일정 · 조건 · 더보기 · 긴급.
- 예전 단일 외출 흐름 경로(`/plan`, `/result`)는 없다. 되살리지 않는다.

## 테스트

- 새 화면은 접근성 검사 위반 0건, 키보드 조작 가능, 200% 확대에서 깨지지 않음, 터치 대상 44px 이상을
  만족해야 한다.
- 360px에서 가로 스크롤이 없어야 하고, 320–1280px 범위에서 깨지지 않아야 한다.
- 모든 화면에서 위치 권한 요청이 **0건**임을 단언한다.
- 화면 테스트는 외부 호출 0건이어야 한다. 캐시를 미리 심고 네트워크 감시를 붙인 상태로 돈다.
- 새 라우트는 로그인 없이 불렀을 때 401이 나오는지 확인한다.
