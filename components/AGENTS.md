# 화면 부품 (`components/`)

## 맡는 것

여러 화면이 함께 쓰는 표시 부품이다. 버튼·배지·상태 배너·날짜 칩·하루 타임라인·장소 카드·식사 칸·
예/아니오/모르겠음 입력·기간 편집기·전후 비교 시트·복귀 시트·하단 내비·긴급 버튼·한국어 카드·
빈 상태, 그리고 언어 전환과 설치 안내.

## 맡지 않는 것

- 판정·계산 — `src/`
- 저장·서버 호출·변화 감지 — `lib/`
- 경로와 화면 구성 — `app/`

## 항상 지켜야 하는 것

- **출처 영역을 시각적으로 나눈다**: 병원 발행 / 본인 체크 / 앱의 판정·추정 / 관광공사 원문 / AI 소개.
  사용자가 "누가 한 말인지" 구분할 수 없으면 앱의 추정이 병원 지시처럼 보인다.
- 배지 다섯 종을 정해진 뜻으로만 쓴다: '추정', '기본값 적용', '운영 확인 필요', '병원 연동 데모',
  '보기 전용'.
- **상태를 색만으로 구분하지 않는다.** 문구와 아이콘을 함께 쓴다.
- 본문 16px 이상, 터치 대상 44px 이상, 대비는 접근성 기준 AA를 만족한다.
- 이동시간·보행 부담·식이 판단에는 **'추정' 표시**를 붙인다. 확정처럼 보이게 하지 않는다.
- 영업 중이라고 표시하지 않는다. 근거가 없으면 '운영 확인 필요'다.
- 외출이 없는 상태를 오류처럼 그리지 않는다.
- 즉시 복귀 시트는 자동으로 열리고 **끌 수 없다.** 뒤로가기는 시트만 닫는다.
- 외출의 돌아갈 곳은 **한 규칙**(`trip/viewModel.js` `returnTargetOf`)에서 읽는다. 타임라인·오늘 화면의
  `returnPlaceOf` 도 여기서 읽는다. 화면마다 병원을 따로 찾으면 같은 외출이 다른 병원으로 보인다.
- 상태 상자의 행동 줄은 `trip/viewModel.js` `dayActionKey` 한곳이 사유별로 고르고, 복귀 마감 이름(하루 활동 종료면
  '오늘 활동 종료')은 `deadlineCopyOf` 한곳이 고른다. 오늘 화면·하루 일정·시안 보드가 같은 함수를 쓴다.
- 일정 갱신 실패 알림(`trip/UpdateFailedNotice.js`)은 **저장 일정이 있을 때만** 띄운다. 저장 일정이 없으면 빈 상태
  (`trip/NoPlanState.js`) 하나만 두고, 실패 원인별 문구(`viewModel.js` `noPlanBodyKey`)와 다시 시도 하나를 보인다.
  운영자에게 알려야 하는 실패(`AUTH`·`SELF_LIMIT`)인지는 `needsOperatorContact` 한곳이 판단하고, 그때 알림과 빈 상태에
  도움말·문의 링크(`trip/HelpContactLink.js`)를 둔다. 문의 값(`NEXT_PUBLIC_SAFEHOUR_CONTACT`)이 빌드에 있으면 '문의하기'(`/help#contact`),
  없으면 '도움말 보기'(`/help`)다.
- 보호자 받은 일정(`guardian/GuardianCopyView.js`)은 표시만 한다(저장소를 읽지 않는다, 시안 보드 경계 테스트가 막는다).
  머리 바로 아래 '오늘 환자 복귀 마감' 카드는 `guardian/copyView.js` `todayReturnSummary` 한곳이 고른다: 오늘(KST) 마감 가운데
  아직 지나지 않은 가장 가까운 것, 모두 지났으면 가장 늦게 지난 것. 오늘이 사본 날짜 밖이면 카드가 없다. 같은 시각·장소 마감은
  `dedupePatientReturns` 로 한 줄로 합친다. 오늘을 맨 앞에 펼치고 다른 날짜는 `<details>` 로 접는다. 오늘이 사본 날짜 밖이면
  모두 펼친다. 카드는 아래 줄의 값을 다시 보여 줄 뿐이고 새 문구로 상태를 해석하지 않는다.
- 서버 알림의 '돌아왔어요'(`trip/ReturnedConfirm.js`)는 표시 규칙을 `trip/returnedView.js` 하나에서 읽는다.
  - 그리는 조건: 이 기기의 지켜보기가 켜져(`ON`) 있고 그 외출의 확인할 마감(`backTargetOf`)이 있을 때. 갈아 끼움 직후에는 실패 줄만
    그린다. 서버가 스위치가 꺼졌다고 답했을 때만 숨기고, 설정을 읽는 중이거나 읽지 못했으면 숨기지 않는다. 지켜보기 레코드가 없으면
    아무것도 그리지 않고 설정도 묻지 않는다.
  - 두는 곳은 오늘 외출 카드, 마감 지남 시트, 외출 중 재계획 시트다. 시트는 오늘(KST) 날짜일 때만 두고(`sheetShowsConfirm`), 이미 열린
    마감 지남 시트는 자정을 넘겨도 닫힐 때까지 둔다. 누르면 확인 신호만 보내고 시트를 닫거나 일정을 바꾸지 않는다.
  - 단계마다 버튼·줄·되돌리기가 표로 정해져 있다. '전달했어요'는 서버가 기록했다고 답한 단계(SENT)에서만 나온다. 되돌리기는 되돌리기
    마감 전까지만 보이고, 마감이 지나도록 대기 중이면 보호자에게 직접 연락하라는 줄로 바꾼다. 줄은 안전 문구라 두 언어 병기이고
    `role="status"` 안에 있다. 앱은 환자가 돌아왔는지 판단하지 않으므로 줄도 단정하지 않는다.
  - 버튼이나 되돌리기가 사라질 때 포커스를 상태 줄로 옮긴다. 설정의 서버 알림 절(`settings/ServerPushSection.js`)은 끄기·서버 지우기 뒤
    결과 줄로, 보호자 링크 동의 화면(`guardian/GuardianCreate.js`)은 링크를 만든 뒤 결과 제목으로 옮긴다. 이 포커스 이동에는 DOM 단위
    테스트가 없다(`docs/engineering-notes.md` '화면 훅과 포커스 이동에는 단위 테스트가 없다').
- 설정의 '서버 알림' 절은 보일지와 버튼을 누를 수 있는지를 `settings/serverPushView.js` 하나가 정한다. 열린 확인 시트는 설정 화면이
  들고 있고, 절이 숨거나 끌 레코드가 사라지면 그 상태를 비운다(남기면 다른 절이 `inert`로 막힌 채 남는다). 처리 중에는 누른 버튼을
  `disabled`가 아니라 `loading`으로 막아 포커스를 지킨다.
- 보호자 링크 동의 화면의 서버 알림 항목은 표시·처음 체크·결과 문구를 `guardian/serverPush.js`가 고른다. 배지를 두지 않고 법률 검토 안내
  줄(`conditions.consentLegalReview`)을 쓴다.
- 받은 일정 화면의 '앱이 닫혀 있어도 받기' 항목(A-3)은 세 겹이다. 실행기 훅(`useGuardianPush`)을 부르고 기기 설정·보기 전용 신호를 읽는
  곳은 `guardian/GuardianPushItem.js` 하나이고, 무엇을 그릴지는 `guardian/guardianPushView.js`(`guardianPushViewModel`, 순수), 그리기는
  `guardian/GuardianPushItemView.js`다(둘 다 저장소를 읽지 않는다, 테스트가 묶는다). 상태 조회의 주기 묻기도 `GuardianPushItem.js`가
  내보내는 `useGuardianServerStatus` 한 곳만 건다.
  - 상태 13가지(`PUSH_ITEM_STATE`)와 순서: 구독이 없으면 기간 끝(`GONE`), 켜는 중, 지원 판별(차단, 아이폰 둘, 지원 안 됨), 준비 확인 실패,
    켤 수 있음. 구독이 있으면 서버 쉼(`PAUSED`), 다른 기기가 가져감(`MOVED`), 다시 켜기, 받는 중. 기기 알림 스위치가 꺼졌으면 구독
    기록이 남아 있어도 켜진 것으로 그리지 않는다. `MOVED`인 지켜보기에는 다시 켜기 대신 '이 휴대폰에서 다시 받기'만 둔다.
  - 켤 수 없는 상태(아이폰 안내, 지원 안 됨, 차단, 기간 끝)는 스위치 대신 같은 이름의 제목을 둔다. 실행기가 일하는 중이면 두 스위치를
    `disabled`가 아니라 `aria-disabled`로 막고(포커스가 남는다) 버튼은 `loading`이다.
  - 상태 줄은 `role="status"`, 결과 줄은 실패면 `role="alert"`, 그 밖은 `role="status"`이고 두 칸은 늘 있다. 모든 실행기 결과
    (`PUSH_RESULT`)에 결과 줄 문구가 있다(`PUSH_RESULT_LINE`, 빠지면 테스트가 깨진다). 결과 줄은 지금 상태와 맞을 때만 보인다: 지난
    켜짐, 다른 기기가 가져감, 함께 있음 결과를 그와 어긋나는 상태 옆에 두지 않는다(`resultFitsState` 한 곳). 상태 줄과 같은 문구면 한
    번만 보인다. 실패 문구는 켜기 기준이라, `GuardianPushItem.js`가 누름마다 시작한 동작(on, off, mute, renew, takeOver)과 돌려받은 결과를
    기록하고 그 결과가 지금 `lastResult`와 같을 때만 `lastAction`으로 넘긴다(`actionForResult`, 계정이나 지켜보기가 바뀌면 지운다). 받는
    중의 함께 있음 실패는 `guardian.muteFailed`, 구독이 남은 끄기 실패는 `guardian.pushOffFailed`다. 이 맞추기는 실행기의 바탕 길이
    `OFF_UNSENT`, `PERMISSION_LOST`, `GONE`만 남긴다는 데 기댄다(`lib/notify/guardianPush.js`의 `lastResults` 주석).
  - 누른 부품이 결과로 사라지면(켜기가 차단·지원 안 됨·기간 끝으로 끝남, 다시 켜기·다시 받기 성공) 포커스를 항목 제목(`tabIndex -1`),
    스위치가 있는 상태면 켜기 스위치로 옮긴다. 사용자가 다른 곳으로 옮긴 뒤면 건드리지 않는다. 동의 줄, 결과의 `alert` 칸, 안전
    Callout은 `HIDDEN`이 아니면 늘 그리고, 단위 테스트가 원문 구조로 묶는다(JSX 렌더러가 없다).
  - 보기 전용이면 스위치를 잠그고 로그인 줄과 로그인 버튼(`/login?returnTo=%2Fg`)을 둔다. 로그인 버튼은 받은 일정 화면에 한 번만 보인다:
    기기 알림 스위치(`AlertsToggle`)가 버튼을 보이는 때(`shouldShowReadOnly`이고 오프라인이 아님)는 항목이 줄만 둔다(`loginElsewhere`).
    오프라인이면 로그인을 권하지 않고 연결 안내만 둔다. 세션 확인 전(오프라인 말고)에는 항목을 그리지 않는다(`shouldShowReadOnly`).
  - 동의 문장과 법률 검토 줄(`consentLines`)은 늘 보이고, 도착 비보장·위치 줄과 끄기 대기 줄은 두 언어 병기다. 아이폰 다섯 단계는 순서
    목록 하나로 묶는다(`pushLineSegments`).
- 받은 일정의 줄마다 꼬리표와 줄 안 안내는 `guardian/returnStatus.js`의 `returnRowView` 한 곳이 고른다. 복귀 확인 꼬리표(한국어 "'돌아왔어요' 누름")는 환자가
  돌아왔어요를 눌렀다는 표시(판정 아님)다. 상태 조회 날짜가 줄 날짜와 같고 확인 목록에 그 마감이 있을 때만 붙고(`confirmedFor`),
  `state-together` 토큰과 체크 아이콘, 글자로 그린다. 꼬리표는 늘 '앱은 위치를 몰라 실제로 돌아왔는지는 알 수 없다'는 안내
  (`guardian.confirmedHelp`, 두 언어 병기)와 함께 보인다. 확인된 줄은 '마감 지남' 꼬리표, 연락 안내, 줄 안의 전화 버튼 대신 이 안내를
  보이고(마감 전 줄과 맨 위 오늘 카드도 같다), 그날 절 아래에 서버 확인 시각 줄(`serverCheckedAt`, `guardian.statusAsOf`)을 둔다. 화면
  아래 긴급 절(119, 1330)은 이 규칙과 무관하게 늘 그대로다. `serverStatus`가 없으면 예전과 같은 마크업이다(시안 보드).
- 받은 링크 붙여넣기 절(`guardian/PasteLink.js`)의 펼침과 받아들인 뒤 포커스는 `guardian/pasteView.js`가 정한다: 사본도 여는 중인
  링크도 없을 때만 펼치고, 여는 중인 링크가 있어도 숨기지 않고 접어 둔다. 받아들이면 입력란을 비우고 접으며, 포커스는 PIN 입력 제목,
  로그인 안내 제목, 상태 줄, 사본 제목 순으로 처음 있는 곳에 둔다(`PASTE_FOCUS_ORDER`). 입력란은 `form` 안의 `textarea`이고
  `maxLength`는 `PASTE_MAX_CHARS`, `autoComplete="off"`, `spellCheck={false}`, `name`이 없다. 버튼 이름은 '링크 열기'(`guardian.pasteOpen`)다.
- 안전 문구는 병기 규칙이 고른 두 언어로 보여준다. 부품 안에서 언어 조건문을 따로 만들지 않는다.
- 문구는 기능별 이름공간 파일에서 가져온다. 부품 파일에 문자열을 직접 쓰지 않는다.
- 색·크기·간격·모서리·그림자는 **토큰만** 쓴다. 값을 직접 쓰면 디자인이 화면마다 갈라진다.

## 구현 방식

- 부품은 표시만 한다. 데이터를 직접 가져오지 않고 속성으로 받는다 — 그래야 시안 보드가 고정
  데모 데이터로 같은 부품을 그릴 수 있다.
- 모달·시트는 공통 훅을 쓴다. 열림 상태·포커스 가두기·뒤로가기 처리를 부품마다 새로 만들지 않는다.
- 사진은 원본 URL을 **참조만** 한다. 서버에서 받아 가공하는 이미지 컴포넌트를 쓰지 않는다.
- 사진이 없으면 유형별 일러스트를 쓴다.

## 테스트

- 상태 배너는 네 상태 × 사유 코드 조합으로 문구와 아이콘이 함께 나오는지 확인한다.
- 배지가 붙는 조건을 각각 고정한다 — 특히 '기본값 적용'과 '추정'.
- 부품 단위로 접근성 검사를 돌리고, 화면 테스트에서 키보드 조작과 확대를 확인한다.
- 시안 보드가 사용자 데이터를 읽지 않는지 확인한다.
