# 화면 부품 (`components/`)

## 맡는 것

여러 화면이 함께 쓰는 표시 부품이다. 버튼·배지·상태 배너·날짜 칩·하루 타임라인·장소 카드·식사 칸·
예/아니오/모르겠음 입력·기간 편집기·전후 비교 시트·복귀 시트·하단 내비·긴급 버튼·한국어 카드·
빈 상태, 그리고 언어 전환과 설치 안내.

## 맡지 않는 것

- 판정·계산 — `src/`
- 저장·서버 호출·변화 감지 — `lib/`
- 경로와 화면 구성 — `app/`

## 항상 지켜야 하는 것

- **출처 영역을 시각적으로 나눈다**: 병원 발행 / 본인 체크 / 앱의 판정·추정 / 관광공사 원문 / AI 소개.
  사용자가 "누가 한 말인지" 구분할 수 없으면 앱의 추정이 병원 지시처럼 보인다.
- 배지 다섯 종을 정해진 뜻으로만 쓴다: '추정', '기본값 적용', '운영 확인 필요', '병원 연동 데모',
  '보기 전용'.
- **상태를 색만으로 구분하지 않는다.** 문구와 아이콘을 함께 쓴다.
- 본문 16px 이상, 터치 대상 44px 이상, 대비는 접근성 기준 AA를 만족한다.
- 이동시간·보행 부담·식이 판단에는 **'추정' 표시**를 붙인다. 확정처럼 보이게 하지 않는다.
- 영업 중이라고 표시하지 않는다. 근거가 없으면 '운영 확인 필요'다.
- 외출이 없는 상태를 오류처럼 그리지 않는다.
- 즉시 복귀 시트는 자동으로 열리고 **끌 수 없다.** 뒤로가기는 시트만 닫는다.
- 안전 문구는 병기 규칙이 고른 두 언어로 보여준다. 부품 안에서 언어 조건문을 따로 만들지 않는다.
- 문구는 기능별 이름공간 파일에서 가져온다. 부품 파일에 문자열을 직접 쓰지 않는다.
- 색·크기·간격·모서리·그림자는 **토큰만** 쓴다. 값을 직접 쓰면 디자인이 화면마다 갈라진다.

## 구현 방식

- 부품은 표시만 한다. 데이터를 직접 가져오지 않고 속성으로 받는다 — 그래야 시안 보드가 고정
  데모 데이터로 같은 부품을 그릴 수 있다.
- 모달·시트는 공통 훅을 쓴다. 열림 상태·포커스 가두기·뒤로가기 처리를 부품마다 새로 만들지 않는다.
- 사진은 원본 URL을 **참조만** 한다. 서버에서 받아 가공하는 이미지 컴포넌트를 쓰지 않는다.
- 사진이 없으면 유형별 일러스트를 쓴다.

## 테스트

- 상태 배너는 네 상태 × 사유 코드 조합으로 문구와 아이콘이 함께 나오는지 확인한다.
- 배지가 붙는 조건을 각각 고정한다 — 특히 '기본값 적용'과 '추정'.
- 부품 단위로 접근성 검사를 돌리고, 화면 테스트에서 키보드 조작과 확대를 확인한다.
- 시안 보드가 사용자 데이터를 읽지 않는지 확인한다.
