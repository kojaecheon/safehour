### C2 상세 — 호출 이력을 어떻게 남길 것인가

요강은 "로컬 DB 저장 대신 실시간 호출" 을 요구하고, 제출한 인증키의 **개발 기간 내
호출건수**로 실제 활용을 검증한다. SafeHour 는 실시간 호출이지만 두 가지가 호출량을 낮춘다.

- 응답 캐시 TTL 15분 (`src/tour-api/client.js`)
- 변화 이벤트 재계산이 **0콜** (클라이언트가 후보를 되돌려 보내 재판정만 수행)

둘 다 설계 의도이자 장점이지만, 심사 측 관점에서는 "호출이 적은 서비스" 로 보일 수 있다.
대응은 호출을 부풀리는 것이 아니라 **정상적인 검증 활동의 흔적을 제출 키에 남기는 것**이다.

1. 제출할 인증키를 지금 **하나로 확정**하고, 이후 모든 실API 검증을 그 키로 수행한다.
2. **주 1회 이상** 다음 한 줄을 실행한다. 실API 검증 3종이 돌고 누적 호출표가 갱신된다.

   ```bash
   npm run usage:weekly
   ```

3. 산출물 `docs/API_USAGE_SNAPSHOT.md` 는 자동 생성이다 — 오퍼레이션별·일자별 누적,
   성공률, 응답 코드 분포, **인증키 비기록 검사**(로그에 키가 남으면 exit 1)를 담는다.
   `logs/tour-api/` 는 Git 제외이므로, 로그가 없는 환경에서 실행해도 기존 표를 덮지 않는다.
4. 기능설명서 4번 항목에 **캐시·재계산 0콜이 설계상 의도**임을 한 문장으로 적는다.
   설명하지 않으면 감점 요인, 설명하면 "데이터 활용 적절성" 의 근거가 된다.

현재 로컬 누적은 **24콜 / 2일**(2026-08-14~15)로 얇다. 키를 확정하는 즉시 주 1회 루틴을
시작해야 개발 기간(07.27~09.21) 이력이 쌓인다 — **소급이 불가능한 항목**이다.

### C2-1. 인증키 — 무엇을 확정해야 하나

요강 제출항목 4: **"신청자 인증키(인코딩, 디코딩키) 일체 및 운영계정(대표 1개) 신청여부 체크"**
그리고 **"인증키 통해 활용 API별 서비스 개발 기간 내 호출건수 확인"**.

| # | 확정할 것 | 왜 |
| --- | --- | --- |
| 1 | **어느 계정의 키인가** | 공공데이터포털은 계정당 인증키가 하나다. 팀원이 여럿이면 "누구 이름으로 활용신청했는가" 를 정해야 하고, **그 키로 나간 호출만 인정**된다 |
| 2 | **인코딩키·디코딩키 두 값** | 요강이 "일체" 를 요구한다. 포털 마이페이지에서 두 값을 그대로 복사한다 (특수문자가 없으면 두 값이 같을 수 있다) |
| 3 | **활용신청이 4개 서비스 모두 승인됐는가** | `KorService2` · `EngService2` · `KorWithService2` · 기상청 `VilageFcstInfoService_2.0`. 승인되지 않은 서비스는 호출 이력이 남지 않는다 |
| 4 | **운영계정 신청 여부 (선택)** | 승인 대기가 있으므로 **하려면 지금**. 대표 1개만 신청 가능 — 권고: `KorService2`(후보 조회의 근간, 호출량 최다) |
| 5 | **배포본 환경변수를 같은 키로 통일** | 로컬과 Vercel 이 다른 키면 이력이 갈린다. 제출하는 키는 하나다 |

**주의**: `logs/tour-api/counter-*.json` 은 SafeHour 자체 카운터이며 **심사 근거가 아니다.**
심사는 공공데이터포털에 남은 호출 이력을 본다. 서버리스 인스턴스마다 `/tmp` 가 독립이라
배포본 호출은 로컬 카운터에 잡히지 않으므로, **포털 마이페이지의 실제 누적 건수**를 확인해야 한다.

### 3.2 기능설명서 — 항목별 원천

**기능설명서는 선택이 아니다.** 제출항목 5번이며, 요강은 세 곳에서 같은 말을 한다.

- 지정 양식을 쓰지 않으면 "심사 대상에서 제외될 수 있습니다"
- 양식 내 필수 항목을 임의로 누락·변경해도 "심사 대상에서 제외될 수 있습니다"
- 유의사항: "입력 항목 및 첨부파일 등이 누락될 경우 심사에서 제외될 수 있습니다"

**배점 관점에서 더 중요하다.** 나머지 제출물은 전부 폼 입력과 URL 한 줄이다.
심사위원이 서비스를 직접 눌러 확인할 수 있는 것은 **구현성 30점**뿐이고,
**기획력 30점 + 발전성 20점 = 50점**은 기능설명서의 1번(지정과제 선택 이유·기획 방향),
2번(해시태그 연계), 6번(차별성·발전계획)에서만 판정된다.
데이터 활용 20점도 4번 항목과 인증키 호출 이력이 근거다.

즉 **1차 심사 100점 중 절반 이상이 이 문서 하나로 결정된다.** PDF 로 변환해 제출한다.
