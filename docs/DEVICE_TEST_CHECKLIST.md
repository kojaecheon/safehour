# 실기기 검증 체크리스트 (AC018 · AC019)

자동 검사(axe 8화면, 키보드 4건, 반응형 7건)가 통과한 뒤에도 남는 것들이 있다.
**실제 폰에서만 드러나는 문제**와 **스크린리더 사용성**은 사람이 직접 봐야 한다.
이 문서는 그 검증을 폰 하나로 15분 안에 끝내기 위한 순서다.

- 대상 URL: `https://safehour.vercel.app`
- 자동 검사가 이미 덮은 것: WCAG A/AA 위반, 키보드 조작, 320–1280px 레이아웃, 44px 터치 대상
- **이 문서가 덮는 것**: 실기기 렌더링, 실제 터치감, 안드로이드 뒤로가기, 스크린리더 낭독
- 결과 기록: 각 항목 옆에 `OK` / `NG(무엇이)` 를 적고, 이 파일을 그대로 커밋한다

| # | 확인 | 결과 |

## 2. 안드로이드 뒤로가기 (3분 · 안드로이드 필수)

AX-011 에서 재설계한 부분이다. E2E 로 고정했지만 **실제 하드웨어 뒤로가기 버튼**은
브라우저마다 동작이 다를 수 있다.

| # | 확인 | 결과 |
| --- | --- | --- |
| 2-1 | "즉시 복귀 안내"를 열고 뒤로가기 → **시트만 닫히고 결과 화면에 남는다** | |
| 2-2 | 위에서 뒤로가기를 한 번 더 → 조건 입력 화면으로 간다 | |
| 2-3 | "환자 호출"로 시트 2개를 겹쳐 열고 뒤로가기 → **하나씩** 닫힌다 | |
| 2-4 | 시트의 "확인" 버튼으로 닫은 뒤 뒤로가기 → 조건 입력으로 간다 (시트가 다시 뜨지 않는다) | |

> 2-1 이 실패하면 **안전 지시를 읽는 도중 페이지를 떠난다.** 가장 위험한 결함이라
> 다른 항목이 다 통과해도 이것만은 반드시 확인한다.
> iOS 는 하드웨어 버튼이 없으므로 **스와이프 뒤로가기**로 같은 항목을 확인한다.

## 5. 스크린리더 (AC019 · 5분)

- **iOS**: 설정 → 손쉬운 사용 → VoiceOver (또는 측면 버튼 3번)
- **안드로이드**: 설정 → 접근성 → TalkBack

| # | 확인 | 결과 |
| --- | --- | --- |
| 5-1 | 결과 화면 진입 시 **판정 상태가 먼저 낭독된다** (추천 목록보다 앞) | |
| 5-2 | 각 추천 카드에서 장소명·이동시간·체류시간이 순서대로 읽힌다 | |
| 5-3 | "즉시 복귀 안내" 버튼을 찾는 데 **5초 이내** (D02-VQ002) | |
| 5-4 | 시트를 열면 포커스가 시트 안으로 들어가고, 배경 내용이 읽히지 않는다 | |
| 5-5 | 시트를 닫으면 포커스가 원래 버튼으로 돌아온다 | |
| 5-6 | 제외 사유가 "왜 빠졌는지" 이해되게 읽힌다 | |

> 5-1 이 실패하면 시각장애 사용자가 NO_TOURISM 상태를 모른 채 목록만 듣는다.
> 5-3 은 **초시계로 재는 것**을 권한다. 체감과 실측이 자주 다르다.

## 6. 실패 시 처리

- **결함을 발견하면**: 이 표에 `NG(증상)` 를 적고, 재현 절차와 함께
  `docs/AX_BACKLOG.md` 에 항목을 추가한다. 화면 녹화가 있으면 가장 좋다.
- **판단이 애매하면**: 고치지 말고 기록만 한다. 안전 판정에 영향이 없는
  미관 문제와, 안전 지시 전달을 막는 문제는 우선순위가 다르다.
- **2-1 이 실패하면 다른 작업보다 먼저 고친다.**
