# SafeHour 전문 승인(signoff) 체크리스트 (AX-106)

- 연결: D07 정책 전체, D09-RG001–RG008, HOLD001–HOLD005, AC020
- 상태: **담당자 미지정** — 이 문서는 "무엇을 승인받아야 하는가"의 목록이며,
  승인 자체는 사람이 한다. 에이전트는 승인자를 대신하지 않는다.

## 우선순위 — 무엇이 무엇을 막는가 (2026-08-26 판정)

**5개 영역 중 공모전 제출 자체를 막는 것은 없다.** 제출물 10개 항목(팀 정보·서비스명·
개요·유형·지정과제·URL·테스트 계정·인증키·활용 API 목록·기능설명서)에 전문가 승인
증빙이 없고, 1차 배점(구현성 30·기획력 30·데이터 활용 20·발전성 20)에도 없다.

막는 것은 **출시**다. 아래 5개 중 하나라도 조건부·불가면 D09 HOLD 가 유지된다.

| 순위 | 영역 | 언제까지 | 안 하면 잃는 것 |
| --- | --- | --- | --- |
| 1 | **5. 콘텐츠·다국어** (영문 안전 문구 검수) | **08.30** (W2 기한) | 심사위원이 English 토글을 누르면 미검수 안전 문구가 그대로 보인다. **확인된 오역 있음** — 아래 |
| 2 | **1. 의료 경계** (안전 임계값) | 자문 섭외 08.31 → **09.07 동결 전 판정** | 24h/72h 충돌의 정본 값을 정할 근거가 없다. 근거 없이 동결하거나 결함을 안고 간다 |
| 3 | **2. 개인정보** | 2.10 판단은 **09.07 동결 전** | 사유 코드 유지 여부가 코드에 닿는다. 동결 후에는 못 뒤집는다 |
| 4 | **4. 법무·약관** | 요청서 발송 08.31 | 리드타임이 가장 길지만 마감 점수에 닿는 통로가 거의 없다. 잃는 것은 실환자 오픈 시점 |
| 5 | **3. 위치정보** (문의 2540) | 재문의·발송일 기록 09.06 | 회신이 와도 09.07 동결까지 지도를 붙일 수 없다. 미연동은 의도적 안전 설계로 서술한다 |

### 지금 확인된 영문 오역 — 1순위인 이유

| | 한국어 | 영어 | 문제 |
| --- | --- | --- | --- |
| `SPLIT_NEARBY` | 보호자**만** 근거리 활동이 가능합니다 | Companion **may** take a nearby activity | 한국어는 "환자는 안 된다"는 배타. 영어는 "보호자가 해도 된다"는 허가일 뿐 **환자 가부를 말하지 않는다.** 외국인 환자가 같이 나갈 수 있다 |

안전 문구의 의미가 어긋나면 다국어가 오히려 위험이 된다. 검수자 지정이 이번 주 기한인
이유가 이것이다.

### 이 체크리스트가 묻지 않는 것 — §1 의 구멍

§1(의료 경계) 6개 항목은 전부 **"앱이 의료 판단처럼 보이는가"** 를 묻는다.
**"앱이 쓰는 숫자가 의학적으로 타당한가"를 묻는 항목이 없다.**

코드에 박힌 안전 임계값 넷은 아무도 임상적으로 승인한 적이 없다.

| 값 | 어디에 | 무엇을 정하는가 |
| --- | --- | --- |
| 조건 유효 **24시간** | `src/engine/safetyGate.js` | 병원 지침이 언제부터 못 믿을 것이 되는가 |
| 최소 활동 창 **45분** | `src/engine/recommend.js` | 이 아래로는 외출을 권하지 않는다 |
| 환자 가산 **10분** | `src/engine/slaCalculator.js` | 회복기 환자의 복귀 여유 |
| 교통 변동 **25%** | `src/engine/slaCalculator.js` | 이동 지연 대비 |

코드 주석이 스스로 "현장 측정 후 보정 필요"라고 적었고, 계획 유효기간 72시간과
조건 최신성 24시간이 충돌하는 미해결 결함도 여기 걸린다(`docs/PRD.md` Part 4 ⑤).

**자문의를 앉혀도 이 질문을 받지 못한다 — 체크리스트가 묻지 않으니까.**
아래 §1 에 1.7 항목으로 추가했다.

## 이 문서를 쓰는 법

1. 아래 5개 영역마다 **책임자 이름을 적는다.** 한 사람이 여러 영역을 겸해도 된다.
2. 책임자는 해당 절의 확인 항목을 보고 **판정**한다 — 통과 / 조건부 / 불가.
3. 판정과 근거를 표에 남긴다. 근거는 "확인했다"가 아니라 **무엇을 보고 그렇게
   판단했는지**여야 한다.
4. 조건부·불가가 하나라도 있으면 출시하지 않는다 (D09 HOLD).

확인에 필요한 실제 산출물은 각 항목에 경로·URL 로 달아두었다. 담당자가 코드를
읽지 않아도 판단할 수 있게 하는 것이 이 문서의 목적이다.

**운영 URL: https://safehour.vercel.app**

## 1. 의료 경계

> 이 서비스가 의료 판단을 하는 것으로 보이는가? 의료법상 문제가 있는가?

**책임자: [지정 필요]** · 후보: 협력 병원 의료진, 자문 의사

| # | 확인 항목 | 근거 자료 | 판정 |
| --- | --- | --- | --- |
| 1.1 | 앱이 증상·회복 단계를 **해석하지 않는가** | D07-POL001. 코드에 증상 파싱 없음 — 병원이 준 조건을 그대로 입력받아 판정 | |
| 1.2 | "회복 단계", "안전합니다" 같은 **단정 표현이 없는가** | D03 용어 계약. 화면 문구는 "현재 입력 조건을 통과함"으로 표현 | |
| 1.3 | 면책 문구가 **모든 결과 화면에 보이는가** | 결과 화면 하단 "SafeHour는 의료진의 판단을 대체하지 않습니다" | |
| 1.4 | 위험신호 입력 시 **앱이 진단하지 않고 차단만 하는가** | RISK_SIGNAL 이벤트 → 해석 없이 즉시 미추천 | |
| 1.5 | **의료기관 알선**으로 해석될 여지가 없는가 (의료법 §27) | D07-POL003. 병원 검색·순위·평점·추천 기능 없음. 기준점은 사용자가 직접 입력 | |
| 1.6 | 추천 0건일 때 안내가 **의료적 지시가 아닌가** | "병원 연락 또는 숙소 대기" — 판단은 병원에 맡김 | |
| 1.7 | 안전 임계값 넷이 **의학적으로 타당한가** | 조건 유효 **24시간**·최소 활동 **45분**·환자 가산 **10분**·교통 변동 **25%**. **전부 설계값이며 임상 근거가 없다** — 코드 주석이 "현장 측정 후 보정 필요"라고 적었다. 계획 유효기간 72시간과 조건 최신성 24시간이 충돌하는 미해결 결함 포함 (`docs/PRD.md` Part 4 ⑤) | |

**직접 확인 방법**: 운영 URL 에서 조건 입력 → 결과 화면의 문구를 읽어본다.
"외출이 허용되지 않았습니다"를 선택하면 미추천 화면과 사유가 보인다.

## 2. 개인정보

> 무엇을 수집하고 얼마나 보관하는가? 동의는 적법한가?

**책임자: [지정 필요]** · 후보: 개인정보보호 담당자, 외부 자문

| # | 확인 항목 | 근거 자료 | 판정 |
| --- | --- | --- | --- |
| 2.1 | 수집 항목이 **최소한인가** | D07-POL008. 병원 조건(금식·외출·동행 등 boolean), 복귀 시각, 기준점 좌표 | |
| 2.2 | **이름·연락처·진단명·증상 원문을 받지 않는가** | 입력 화면에 해당 필드 없음. 병원 안내문 원문(rawText)은 MVP 에서 미수집 | |
| 2.3 | 서버가 **저장하지 않는가** | 판정은 stateless. 세션·조건·판정 결과를 **다시 조회할 수 있는 형태로** 저장하지 않음. 판정 상태·사유 코드는 비식별 운영 로그로만 남음 (`docs/API_CONTRACT.md`, ADR-0002) | |
| 2.4 | 단말 저장(sessionStorage)의 **보존 범위가 적절한가** | 입력 draft 와 판정 결과가 탭 종료 시 소멸. **명시적 삭제 수단 있음 (AX-210)** — 전 화면 하단 "이 기기에서 내 정보 지우기", 확인 후 삭제 + 전체 새로고침으로 메모리 사본까지 폐기. 저장 키 목록은 `lib/session.js` 가 단일 정의 | |
| 2.5 | 로그에 **개인정보가 남지 않는가** | 인증키·GPS·병원 원문·이름·연락처를 로그 금지 항목으로 고정. 판정 로그는 `test/decision-log.test.js`, TourAPI 호출 로그는 `test/tour-api-limits.test.js` 가 검증 (기준점 좌표는 `REDACTED` 로 가림) | |
| 2.6 | 분석 이벤트 **동의 정책** | **해소 — ADR-0002 Accepted.** 사용자 행동 분석 계측을 하지 않으므로 선택 동의 대상이 없다. 남는 것은 서비스 운영 로그뿐 | |
| 2.7 | 개인정보 처리방침 **고지 화면** | **구현됨 (AX-211)** — `/privacy`. 수집·미수집·저장위치·제3자 전송·면책·출처를 한국어·영어로 고지. 본문 정본은 `src/i18n/legal.js`. **책임자·문의처·분쟁관할은 미지정 — 판단 필요** | |
| 2.8 | **로그인으로 받는 정보가 최소인가** | Google `openid` 만, Kakao 선택 동의 0개. 이메일·이름·프로필 미요청. 세션은 서명 쿠키(서버 DB 없음)이고 토큰을 저장하지 않는다 — ADR-0004, `test/auth.test.js` 36건 | |
| 2.9 | 로그인 상태를 **사용자가 지울 수 있는가** | "이 기기에서 내 정보 지우기" 가 로그아웃까지 수행 (E2E 로 고정) | |
| 2.10 | 판정 **사유 코드**를 남기는 것이 적절한가 | ADR-0002 「사유 코드는 "건강 상세"인가」. POL001 이 위반 탐지 수단으로 지정했고, 세션 식별자 없이 코드만 남는다. **판단 필요** | |

**결정이 필요한 것**: 2.7 의 **책임자·문의처 지정**과 2.10(사유 코드 판단).
2.4 는 AX-210, 2.7 의 화면은 AX-211, 2.6 은 ADR-0002 로 해소됐다.
