# 시스템 구성

## 전체 모양

브라우저에서 도는 Next.js(App Router) 모바일 웹 하나다. 서버는 **상태를 저장하지 않는 계산기**이고,
사용자 데이터는 **브라우저 영구 저장소에만** 있다. 데이터베이스는 없다.

```
브라우저(기기 저장소: 체류·확정 일정·동의·보호자 사본)
   │  체류에서 좌표·조건만 뽑은 요청(PlanStay)
   ▼
Next.js 라우트 핸들러 (무상태)
   │            ├─ 관광공사 TourAPI  (장소 후보, 국문 + 무장애 + 선택 언어)
   │            ├─ 기상청 단기예보    (오늘~모레, 실외 적합 판단)
   │            ├─ 행정안전부 주소·좌표 (UTM-K → WGS84 변환은 서버가 직접 한다)
   │            └─ Gemini REST       (소개 문장 전용, 기본 꺼짐)
   ▼
규칙 엔진 (순수 함수, 결정적)
   │
   ▼  하루 일정 + 전후 비교
브라우저가 받아서 저장하고 화면에 그린다
```

데이터베이스가 없는 것은 결정이다 — 서버에 저장소를 두면 판정 결과와 조건 값이 서버에 남고,
"조건 값은 계산 뒤 버린다"는 약속이 깨진다. 서버 저장은 앞으로 검토할 수 있지만, 지금 구조는
그것 없이 완결돼 있다.

서버 알림(ADR-0012)이 그 첫 예외다. 스위치가 꺼진 채 코드에만 들어와 있고, 켜면 Upstash Redis에 네 가지 레코드만 둔다.
조건 값과 판정 결과는 여기에도 담지 않는다. 판정은 여전히 기기와 무상태 라우트가 하고, 서버 알림은 기기가 이미 확정한
복귀 마감 시각만 받는다(아래 '서버 알림이 도는 길').

서버는 요청을 받아 계산하고 응답한 뒤 아무것도 남기지 않는다. 남기는 건 stdout 한 줄짜리 판정 로그뿐이고,
그 줄에는 좌표·날짜·장소 이름·주소·조건 값·계정 키·병원 정보가 들어가지 않는다.

## 요청 하나가 도는 길 — 일정 만들기

1. 화면이 기기 저장소에서 체류를 읽는다.
2. 클라이언트가 체류를 **허용 목록으로 깎아** `PlanStay`로 만든다. 숙소 이름·주소, 병원 이름·전화,
   연동 코드, 병원 안내문은 여기서 빠진다. 서버는 좌표와 조건 값만 본다.
3. `POST /api/itinerary/plan`이 로그인 가드를 지나고, 요청 본문에서 허용 목록 밖 필드를 버린다.
4. 날짜마다 그날 적용되는 조건 기간을 모아 **항목별로 가장 엄격한 값**으로 합성하고, 값마다 출처를 붙인다.
5. 합성 결과로 날짜를 분류한다(자유일 / 제한 없음 선언일 / 제한일 / 휴식일 / 입력 필요).
6. 그날 숙소 좌표를 기준점으로 관광공사 후보를 받아 게이트(휴무·실내·자외선·기상·열·물·식이)를 통과시킨다.
7. 고정 블록(병원 일정, 숙소 복약) 사이의 빈 구간에 외출을 만들고, 복귀 계산식·보행 누적·이동 한도를
   만족할 때까지 정거장을 줄이거나 뺀다.
8. 이전 일정이 함께 왔으면 날짜별 전후 비교를 채운다.
9. 응답을 클라이언트가 기기에 저장한다. 다음에 열 때는 변화가 감지되지 않는 한 저장본을 그대로 쓴다.

판정 엔진은 **결정적**이다 — 난수와 현재 위치를 읽지 않고, 현재 시각조차 인자로 받는다.
그 인자를 채우는 것은 라우트 계층이고, 값은 **서버 시계(한국 표준시)**에서 온다. 요청 본문에
시각이 실려 와도 서버는 읽지 않는다: 클라이언트가 보낸 시각을 믿으면 '오늘'을 옮겨 매일 확인
게이트와 지난 날짜 보호를 우회할 수 있다. 그래서 "같은 입력 → 같은 결과"는 **같은 날 안에서** 성립한다.

## 서버 알림이 도는 길 (ADR-0012, 스위치 꺼짐)

앱이 닫혀 있어도 보호자 기기에 '복귀 확인이 없다'는 알림이 가게 하는 경로다. `SAFEHOUR_SERVER_PUSH`가 꺼져 있으면 쓰기 경로는
503이고 기기 알림(갈래 1)만 동작한다. 계약은 `docs/contracts.md` '서버 알림'에 있다.

```
환자 기기(watchId·쓰기 토큰·출국일, 날짜별 HH:MM 목록, 돌아왔어요)
보호자 기기(watchId, 푸시 구독, 오늘 함께 있음)
   │
   ▼
/api/watch* 라우트 (스위치가 켜졌을 때만 쓴다)
   │            ├─ Upstash Redis  (네 레코드: 키는 HMAC, 구독은 봉인)
   │            └─ QStash         (마감 + 10분에 /api/watch/due를 깨우는 예약)
   ▼
/api/watch/due (서명 확인, HSETNX로 보낼 권리)
   │
   ▼
푸시 서비스(FCM·Mozilla·Apple·Windows, 본문은 암호화)
   │
   ▼
보호자 기기
```

1. 환자 기기가 지켜보기를 등록한다(`POST /api/watch`). `watchId`와 쓰기 토큰은 기기가 만든다. 서버는 `watchId`의 HMAC(저장 키)와
   토큰의 SHA-256만 둔다. `watchId`는 PIN으로 암호화한 보호자 사본에 실려 보호자에게 간다.
2. 환자 기기가 날짜별 복귀 마감 `HH:MM` 목록을 올린다(`PUT /api/watch/deadlines`, 늘 최신 전체). 서버는 날짜 기록을 바꾸고
   오늘·내일의 걸리지 않은 마감마다 QStash에 '마감 + 10분에 `/api/watch/due`를 불러 달라'는 예약을 건다. 더 뒤의 날짜는
   하루 1회 예약(Vercel Cron, 00:10 KST)이 어제·오늘·내일 색인을 보고 건다.
3. 보호자 기기가 푸시 구독을 올린다(`POST /api/watch/subscribe`). 서버는 구독을 봉인해 지켜보기마다 하나만 둔다.
4. 예약이 오면 `/api/watch/due`가 서명을 확인하고, 그 마감에 확인('돌아왔어요')도 '오늘 함께 있음'도 없으면 `HSETNX`로 보낼
   권리를 얻어 보호자에게 "확인이 없다" 알림을 한 번 보낸다. 판정표는 `docs/contracts.md`의 `POST /api/watch/due`.
5. 환자가 '돌아왔어요'를 누르면(`POST /api/watch/back`) 확인을 적는다. 이미 마감 지남 알림이 나갔으면 복귀 확인 알림을 보낸다.

서버가 하는 일은 "이 시각까지 확인이 왔는가"를 보는 것뿐이다. 마감 시각을 계산하거나, 늦었다고 판정하거나, 조건을 해석하지 않는다.
알림 문구는 '확인이 없다'는 사실만 쓴다.

## 부품 지도

| 위치 | 역할 | 의존 방향 |
| --- | --- | --- |
| `src/domain/states.js` | 날짜 상태·사유 코드의 닫힌 집합 | 아무것도 참조하지 않는다 |
| `src/stay/` | 체류·조건 기간의 순수 규칙. 합성, 날짜 분류, 오늘 게이트 덧씌우기, 조정 가능한 기본값 | 상태 집합만 참조 |
| `src/engine/` | 하루 일정 생성, 외출 조립, 교체 후보, 재계획, 전후 비교 | 체류 규칙 + 후보 + 이동 추정 |
| `src/tour-api/` | 관광공사 조회·캐시·언어 매칭, 후보 신호(실내·보행 부담·식이·휴무) 추정 | 외부 HTTP |
| `src/adapters/` | 이동시간 추정(택시·대중교통), 기상 조회, 주소 검색, 좌표 변환 | 외부 HTTP |
| `src/recovery/` | 병원 지침 게이트웨이(허용 목록), 안내문, 연결 | 체류 규칙 |
| `src/guardian/` | 보호자 스냅샷 최소화, PIN 키 유도·암호화, 링크 조립, 잠금 | 브라우저 표준 암호 기능 |
| `src/auth/` | 소셜 로그인 흐름, 서명 쿠키 세션, 불투명 계정 키 유도 | Node 암호 기능 |
| `src/i18n/` | 4개 언어 사전, 언어 결정, 안전 문구 병기 규칙 | 없음 |
| `src/push/` | 웹 푸시 프로토콜: VAPID 서명(RFC 8292), 본문 암호화(RFC 8291 aes128gcm), endpoint 허용 목록, 보내기 | Node 암호 기능 + 외부 HTTP(푸시 서비스) |
| `lib/server/` | 라우트 핸들러가 쓰는 조립·검증·로그·운영 스위치 | 위 모두 |
| `lib/server/watch/` | 서버 알림(ADR-0012): 저장소(REST)·키·봉인·횟수 제한·레코드, 예약 어댑터, 예약 걸기·처리, 환자·보호자 동작, 문구, 설정 | `src/push/` + `src/stay/`의 시각 도우미·기본값 + `src/i18n/` 입구(문구 파일만) + 외부 HTTP(Upstash·QStash) |
| `lib/store/` | 기기 저장소 읽기·쓰기, 계정 이름공간, 보기 전용 신호 | 브라우저 저장소 |
| `lib/trip/` | 변화 감지와 재계획 조정, 서버 호출, 표시 가공 | 기기 저장소 + 서버 라우트 |
| `lib/notify/` | 알림 예약과 기기 알림 | 기기 저장소 |
| `app/` | 화면과 라우트 핸들러 | 위 모두 |
| `components/` | 화면 부품 | 문구·스타일·클라이언트 조정 |

의존은 **한 방향**이다: 순수 규칙 → 엔진 → 어댑터 → 서버 라우트 → 클라이언트 조정 → 화면.
반대로 가면(예: 순수 규칙이 브라우저 저장소를 읽으면) 단위 테스트가 브라우저 없이 돌지 못하고,
서버와 클라이언트가 같은 규칙을 다르게 계산하게 된다.

## 경계를 넘는 것과 넘지 않는 것

**기기 → 서버로 넘어가는 것**: 좌표(숙소·병원), 날짜, 조건 항목 값, 언어, 이전 일정, 편집 기록, 데모 사건.
**넘어가지 않는 것**: 숙소·병원 이름과 주소 글자, 병원 전화, 연동 코드, 병원 안내문 원문, 계정 식별자.
허용 목록은 클라이언트와 서버 **양쪽에** 있다. 클라이언트가 실수로 더 보내도 서버가 버린다.

**서버 → 외부로 넘어가는 것**: 관광공사·기상청에는 기준점 좌표와 반경이 간다. 지도 사업자에게는
아무것도 가지 않는다 — 지도는 외부 링크이고 목적지 이름·좌표만 담는다. Gemini에는 공개 장소 이름·유형·
시각과 관심사·이동 강도만 간다.

**서버에 남는 것**: 사용자 데이터는 없다. 파일로 남는 것은 관광공사 호출 기록과 응답 캐시 둘뿐이고,
둘 다 저장 전에 기준점 좌표를 지운다. 호출 한도를 세려면 필요한 기록이다.

**서버 알림이 켜졌을 때 넘는 값** (ADR-0012, 지금은 꺼져 있다)

- 기기에서 서버로: 환자 기기는 `watchId`, 쓰기 토큰, 출국일(`YYYY-MM-DD`), 날짜별 복귀 마감 `HH:MM` 목록, '돌아왔어요'의 날짜·시각을
  보낸다. 보호자 기기는 `watchId`, 푸시 구독(endpoint·p256dh·auth), 언어, `subId`를 보낸다. 장소·좌표·조건 값·외출 내용은 가지 않는다.
- 서버에서 Upstash Redis로: 네 레코드(지켜보기, 봉인한 구독, 날짜 기록, 횟수 계수기)와 소유 집합·날짜 색인. 키는 모두 HMAC이고
  구독은 AES-256-GCM으로 봉인한다. 토큰은 SHA-256만 둔다. 요청은 REST(`Authorization: Bearer`)로 간다.
- 서버에서 QStash로: 예약 본문 `{ k: 저장 키, d: 날짜, t: 시각 }`, 보낼 시각, 중복 제거 id, 미리보기 배포 보호 우회 헤더.
- 서버에서 푸시 서비스로: 암호화한 본문(제목·문구·`/g`·태그)과 VAPID 서명, `TTL: 3600`, `Urgency: high`, `Topic`(HMAC 32자).
  푸시 서비스는 본문을 풀 수 없다. 받는 쪽 주소는 허용 목록의 푸시 서비스 호스트뿐이다.
- 서버에 남는 것: 위 네 레코드와 보조 키 둘(소유 집합, 날짜 색인)뿐이고 TTL로 사라진다(지켜보기·구독은 출국일 끝 + 7일,
  날짜 기록과 색인은 그 날짜 끝 + 1일, 계수기는 창 길이 + 60초).

## 외부 의존

| 대상 | 없으면 어떻게 되나 |
| --- | --- |
| 관광공사 TourAPI | **일정을 만들지 못한다** — 조회 실패(키 없음·호출 한도 포함)는 502이고 기존 일정도 바꾸지 않는다. 조회는 됐는데 통과한 후보가 0개인 것은 다른 이야기이고, 그때는 그날이 `NO_TOURISM` + `NO_CANDIDATE`인 정상 결과다 |
| 기상청 단기예보 | 기상은 '확인 불가'가 되고 판정에 반영하지 않는다. 막지 않는다 |
| 행정안전부 주소·좌표 | 주소 검색이 503으로 막힌다. 데모 로그인 모드에서는 고정 데모 주소를 준다 |
| Gemini | 소개 문장이 정해진 템플릿 문장이 된다. 기본값이 이쪽이다 |
| 소셜 로그인 제공자 | 로그인할 수 없다. 이미 로그인했던 기기는 보기 전용으로 긴급·카드·오늘 일정을 계속 본다 |
| Upstash Redis (서버 알림) | 서버 알림 쓰기·조회가 503(`SAFEHOUR_SERVER_PUSH_UNAVAILABLE`)이다. 지우기와 구독 해지도 저장소가 있어야 된다. 기기 알림(갈래 1)과 일정 만들기는 영향을 받지 않는다 |
| QStash (서버 알림) | 예약을 걸지 못한다. 마감 올리기는 성공하고 `armFailed`로 걸지 못한 수를 알린다. 다음 업로드나 하루 1회 예약이 다시 건다 |
| 푸시 서비스 (FCM·Mozilla·Apple·Windows) | 그 알림이 나가지 않는다. 429·5xx·네트워크 오류면 예약 처리가 503으로 답해 QStash가 다시 부른다. 404·410이면 구독을 지운다 |
| Vercel Cron (서버 알림) | 하루 1회 예약이 돌지 않아 모레 이후 날짜의 예약이 걸리지 않는다. 환자 기기가 업로드할 때마다 오늘·내일 것은 걸린다 |

외부가 죽어도 **긴급 연락과 한국어 안내 카드는 항상 열린다**. 이 둘은 서버도 네트워크도 필요 없다.
