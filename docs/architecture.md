# 시스템 구성

## 전체 모양

브라우저에서 도는 Next.js(App Router) 모바일 웹 하나다. 서버는 **상태를 저장하지 않는 계산기**이고,
사용자 데이터는 **브라우저 영구 저장소에만** 있다. 데이터베이스는 없다.

```
브라우저(기기 저장소: 체류·확정 일정·동의·보호자 사본)
   │  체류에서 좌표·조건만 뽑은 요청(PlanStay)
   ▼
Next.js 라우트 핸들러 (무상태)
   │            ├─ 관광공사 TourAPI  (장소 후보, 국문 + 무장애 + 선택 언어)
   │            ├─ 기상청 단기예보    (오늘~모레, 실외 적합 판단)
   │            ├─ 행정안전부 주소·좌표 (UTM-K → WGS84 변환은 서버가 직접 한다)
   │            └─ Gemini REST       (소개 문장 전용, 기본 꺼짐)
   ▼
규칙 엔진 (순수 함수, 결정적)
   │
   ▼  하루 일정 + 전후 비교
브라우저가 받아서 저장하고 화면에 그린다
```

데이터베이스가 없는 것은 결정이다 — 서버에 저장소를 두면 판정 결과와 조건 값이 서버에 남고,
"조건 값은 계산 뒤 버린다"는 약속이 깨진다. 서버 저장은 앞으로 검토할 수 있지만, 지금 구조는
그것 없이 완결돼 있다.

서버는 요청을 받아 계산하고 응답한 뒤 아무것도 남기지 않는다. 남기는 건 stdout 한 줄짜리 판정 로그뿐이고,
그 줄에는 좌표·날짜·장소 이름·주소·조건 값·계정 키·병원 정보가 들어가지 않는다.

## 요청 하나가 도는 길 — 일정 만들기

1. 화면이 기기 저장소에서 체류를 읽는다.
2. 클라이언트가 체류를 **허용 목록으로 깎아** `PlanStay`로 만든다. 숙소 이름·주소, 병원 이름·전화,
   연동 코드, 병원 안내문은 여기서 빠진다. 서버는 좌표와 조건 값만 본다.
3. `POST /api/itinerary/plan`이 로그인 가드를 지나고, 요청 본문에서 허용 목록 밖 필드를 버린다.
4. 날짜마다 그날 적용되는 조건 기간을 모아 **항목별로 가장 엄격한 값**으로 합성하고, 값마다 출처를 붙인다.
5. 합성 결과로 날짜를 분류한다(자유일 / 제한 없음 선언일 / 제한일 / 휴식일 / 입력 필요).
6. 그날 숙소 좌표를 기준점으로 관광공사 후보를 받아 게이트(휴무·실내·자외선·기상·열·물·식이)를 통과시킨다.
7. 고정 블록(병원 일정, 숙소 복약) 사이의 빈 구간에 외출을 만들고, 복귀 계산식·보행 누적·이동 한도를
   만족할 때까지 정거장을 줄이거나 뺀다.
8. 이전 일정이 함께 왔으면 날짜별 전후 비교를 채운다.
9. 응답을 클라이언트가 기기에 저장한다. 다음에 열 때는 변화가 감지되지 않는 한 저장본을 그대로 쓴다.

판정 엔진은 **결정적**이다 — 난수와 현재 위치를 읽지 않고, 현재 시각조차 인자로 받는다.
그 인자를 채우는 것은 라우트 계층이고, 값은 **서버 시계(한국 표준시)**에서 온다. 요청 본문에
시각이 실려 와도 서버는 읽지 않는다: 클라이언트가 보낸 시각을 믿으면 '오늘'을 옮겨 매일 확인
게이트와 지난 날짜 보호를 우회할 수 있다. 그래서 "같은 입력 → 같은 결과"는 **같은 날 안에서** 성립한다.

## 부품 지도

| 위치 | 역할 | 의존 방향 |
| --- | --- | --- |
| `src/domain/states.js` | 날짜 상태·사유 코드의 닫힌 집합 | 아무것도 참조하지 않는다 |
| `src/stay/` | 체류·조건 기간의 순수 규칙. 합성, 날짜 분류, 오늘 게이트 덧씌우기, 조정 가능한 기본값 | 상태 집합만 참조 |
| `src/engine/` | 하루 일정 생성, 외출 조립, 교체 후보, 재계획, 전후 비교 | 체류 규칙 + 후보 + 이동 추정 |
| `src/tour-api/` | 관광공사 조회·캐시·언어 매칭, 후보 신호(실내·보행 부담·식이·휴무) 추정 | 외부 HTTP |
| `src/adapters/` | 이동시간 추정(택시·대중교통), 기상 조회, 주소 검색, 좌표 변환 | 외부 HTTP |
| `src/recovery/` | 병원 지침 게이트웨이(허용 목록), 안내문, 연결 | 체류 규칙 |
| `src/guardian/` | 보호자 스냅샷 최소화, PIN 키 유도·암호화, 링크 조립, 잠금 | 브라우저 표준 암호 기능 |
| `src/auth/` | 소셜 로그인 흐름, 서명 쿠키 세션, 불투명 계정 키 유도 | Node 암호 기능 |
| `src/i18n/` | 4개 언어 사전, 언어 결정, 안전 문구 병기 규칙 | 없음 |
| `lib/server/` | 라우트 핸들러가 쓰는 조립·검증·로그·운영 스위치 | 위 모두 |
| `lib/store/` | 기기 저장소 읽기·쓰기, 계정 이름공간, 보기 전용 신호 | 브라우저 저장소 |
| `lib/trip/` | 변화 감지와 재계획 조정, 서버 호출, 표시 가공 | 기기 저장소 + 서버 라우트 |
| `lib/notify/` | 알림 예약과 기기 알림 | 기기 저장소 |
| `app/` | 화면과 라우트 핸들러 | 위 모두 |
| `components/` | 화면 부품 | 문구·스타일·클라이언트 조정 |

의존은 **한 방향**이다: 순수 규칙 → 엔진 → 어댑터 → 서버 라우트 → 클라이언트 조정 → 화면.
반대로 가면(예: 순수 규칙이 브라우저 저장소를 읽으면) 단위 테스트가 브라우저 없이 돌지 못하고,
서버와 클라이언트가 같은 규칙을 다르게 계산하게 된다.

## 경계를 넘는 것과 넘지 않는 것

**기기 → 서버로 넘어가는 것**: 좌표(숙소·병원), 날짜, 조건 항목 값, 언어, 이전 일정, 편집 기록, 데모 사건.
**넘어가지 않는 것**: 숙소·병원 이름과 주소 글자, 병원 전화, 연동 코드, 병원 안내문 원문, 계정 식별자.
허용 목록은 클라이언트와 서버 **양쪽에** 있다. 클라이언트가 실수로 더 보내도 서버가 버린다.

**서버 → 외부로 넘어가는 것**: 관광공사·기상청에는 기준점 좌표와 반경이 간다. 지도 사업자에게는
아무것도 가지 않는다 — 지도는 외부 링크이고 목적지 이름·좌표만 담는다. Gemini에는 공개 장소 이름·유형·
시각과 관심사·이동 강도만 간다.

**서버에 남는 것**: 사용자 데이터는 없다. 파일로 남는 것은 관광공사 호출 기록과 응답 캐시 둘뿐이고,
둘 다 저장 전에 기준점 좌표를 지운다. 호출 한도를 세려면 필요한 기록이다.

## 외부 의존

| 대상 | 없으면 어떻게 되나 |
| --- | --- |
| 관광공사 TourAPI | **일정을 만들지 못한다** — 조회 실패(키 없음·호출 한도 포함)는 502이고 기존 일정도 바꾸지 않는다. 조회는 됐는데 통과한 후보가 0개인 것은 다른 이야기이고, 그때는 그날이 `NO_TOURISM` + `NO_CANDIDATE`인 정상 결과다 |
| 기상청 단기예보 | 기상은 '확인 불가'가 되고 판정에 반영하지 않는다. 막지 않는다 |
| 행정안전부 주소·좌표 | 주소 검색이 503으로 막힌다. 데모 로그인 모드에서는 고정 데모 주소를 준다 |
| Gemini | 소개 문장이 정해진 템플릿 문장이 된다. 기본값이 이쪽이다 |
| 소셜 로그인 제공자 | 로그인할 수 없다. 이미 로그인했던 기기는 보기 전용으로 긴급·카드·오늘 일정을 계속 본다 |

외부가 죽어도 **긴급 연락과 한국어 안내 카드는 항상 열린다**. 이 둘은 서버도 네트워크도 필요 없다.
