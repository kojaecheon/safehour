# 도메인 규칙

모든 시각은 한국 표준시 기준이다. 날짜는 `YYYY-MM-DD`, 시각은 `HH:MM`이다.

## 이 제품이 하지 않는 판단

앱은 **의료 판단을 만들지 않는다.** 증상·시술 종류·회복 단계를 묻지 않고, 받은 값을 해석하거나
완화하지도 않는다. 사용자가 고른 항목을 그대로 적용할 뿐이다.

'조건 통과'는 **입력된 조건을 만족한다**는 뜻이고 '안전하다'는 뜻이 아니다. 화면·문구·코드 어디에도
'안전합니다'라고 쓰지 않는다. 이 둘을 섞으면 앱이 의료 판단을 한 것이 된다.

## 체류

한 계정·한 기기에 활성 체류는 하나다. 새 여행을 시작하려면 현재 체류를 지운다.

저장을 **거부하는** 조건:

- 출국일이 입국일보다 빠르다
- 체류가 45박을 넘는다(조정 가능)
- 수술·시술 유형(`PROCEDURE`) 병원 일정이 하나도 없다
- 숙소 구간의 날짜가 서로 겹친다

수술·시술 일정을 필수로 두는 이유는 **수술 후 경계일**이 여기서 나오기 때문이다. 경계일은 가장 이른
수술·시술 일정의 날짜이고, 이 날짜를 모르면 수술 뒤 날짜가 제한 없는 자유일로 만들어진다.

- 입국일 일정 시작 = 도착 시각 + 입국 수속 90분 + 공항→그날 숙소 이동 추정
- 출국일 일정 마감 = 출발 시각 − 공항 도착 여유 3시간 − 그날 숙소→공항 이동 추정 − 여유 30분
- 이 창 밖에는 일정을 만들지 않고 사유는 `OUTSIDE_STAY_WINDOW`다
- 출국일의 외출은 짐이 있는 그날 숙소로 돌아오는 것으로 계산한다

출국일로부터 7일이 지난 뒤 **앱을 처음 여는 시점에** 그 계정의 체류 데이터를 모두 지운다.
화면 문구는 "출국 7일이 지난 뒤 앱을 처음 열 때 삭제됩니다"라고 쓴다. "자동으로 삭제됩니다"라고
쓰면 앱을 열지 않는 사용자에게 거짓말이 된다.

## 숙소와 병원

**날짜 D의 숙소**는 D일 밤을 묵는 숙소다(체크인 ≤ D < 체크아웃). 출국일만 예외로 전날 밤 숙소를 쓴다.
숙소가 없는 날짜는 `NEEDS_INPUT` + `LODGING_REQUIRED`이고 일정을 만들지 않는다. 현재 위치로 대신하지
않는다 — 기준점은 사용자가 고른 고정 좌표뿐이다.

병원은 여러 곳일 수 있다. 앱은 병원 **목록·검색 추천·순위·평점을 보여주지 않는다.** 주소 검색은
사용자가 직접 친 검색어로만 한다. 병원을 추천하는 순간 이 앱은 의료기관 알선이 된다.

병원 일정 블록 = [시작 − 숙소→병원 이동 − 도착 여유 10분, 종료 + 병원→숙소 이동]. 이 구간에는
외출을 만들지 않는다. 종료 시각이 없으면 수술·시술 240분, 진료 90분으로 보고 '예상 종료'로 표시한다.

복귀 장소가 병원인 외출은 **그 복귀가 가리키는 병원**으로 계산한다. 병원이 여러 곳일 수 있으므로
(직접 등록한 곳, 연동으로 더해진 곳) 아무 병원이나 골라 계산하지 않는다.

어느 병원인지 찾지 못했을 때의 처리는 두 가지로 갈린다. 즉시 복귀로 외출을 잘라내고 다시 계산하는
경우에는 **계산을 포기하고 기존 값을 그대로 둔다** — 틀린 숫자보다 낫다. 재계획 중 복귀 지점을 잡는
경우에는 **숙소 좌표로 떨어진다** — 복귀 자체를 못 잡으면 그날 일정을 만들 수 없기 때문이고, 숙소는
기본 복귀 장소다. 어느 쪽도 다른 병원을 고르지는 않는다.

병원 일정 **직전 마지막 외출은 그 병원에서 끝난다.** 복귀 장소가 그 병원이고 마감은 일정 시작 시각이며,
도착 여유 10분은 복귀 계산식에서 한 번만 더한다. 같은 구간의 **그보다 앞선 외출은 숙소로 돌아와 쉰다** —
마감은 숙소에서 병원으로 출발해야 하는 시각이고 마감 이유는 `APPOINTMENT`다. 앞선 외출까지 병원에서
끝내면 환자가 병원에서 두 시간 넘게 기다리게 된다.

## 조건 기간

조건 기간은 **날짜 범위 하나에 적용되는 제한조건 묶음**이다. 출처는 본인 체크(`SELF`) 또는 병원
발행(`HOSPITAL`)이고, 시작일·종료일 모두 포함이다. 같은 날짜를 여러 기간이 덮어도 된다.

**자유 서술 입력칸은 없다.** 정해진 항목만 받는다. 환자가 한국어 안내문을 스스로 해석해서 적는 순간
오역 책임이 앱으로 넘어온다.

각 항목의 답은 세 종류다.

| 답 | 뜻 | 처리 |
| --- | --- | --- |
| 값 있음 | 그 값이 적용된다 | 그대로 적용 |
| 아니오 | 병원이 그런 안내를 하지 않았다 | 제한 없음 |
| 모르겠음 | 사용자가 모른다 | 가장 엄격한 기본값 + '기본값 적용' 표시 |

'아니오'와 '모르겠음'을 **반드시 구분한다.** 구분하지 않으면 혼자 온 환자는 '동행 필요' 기본값 때문에
외출이 전부 막히고, 식이 기본값 때문에 식당이 거의 전부 빠진다.

항목과 '모르겠음' 기본값:

| 항목 | 값 | '모르겠음' | 기본값 |
| --- | --- | --- | --- |
| 외출 허용 | `ALLOWED` / `INDOOR_ONLY` / `FORBIDDEN` | **고를 수 없음** | — |
| 복귀 시각·장소 | 시각 + 숙소/병원, 또는 '병원이 정하지 않음' | **고를 수 없음** | — |
| 보행 한도 | 5–240분 / 아니오 | 가능 | 외출 1회 누적 15분 |
| 이동 한도 | 5–240분 / 아니오 | 가능 | 구간당 20분 |
| 자외선·열·물 피하기 | 예 / 아니오 | 가능 | 예(피함) |
| 동행 필요 | 예 / 아니오 | 가능 | 예 |
| 보호자가 곁을 지켜야 함 | 예 / 아니오 | 가능 | 예(보호자 단독 외출 불가) |
| 식사 제한 | 특정 시각까지 / 하루 종일 / 아니오 | 가능 | 하루 종일 |
| 식이 5종(매운·술·딱딱·뜨거운·날것) | 예 / 아니오 | 가능 | 예(피함) |
| 복약 시각 | 시각 목록(시각마다 '숙소에서 복용' 기본 예) / 아니오 | 가능 | 마감을 만들지 않고 '복약 시각 미입력' 경고 |

- 외출 허용과 복귀 시각은 **필수**다. 비어 있으면 그 기간은 저장되지 않는다.
- 동행 필요가 '예'면 보호자 곁 지키기는 묻지 않고 '예'로 고정한다.
- 병원 발행 기간에는 '모르겠음'이 없다. 값 있음 또는 아니오뿐이다.
- 본인 체크 기간은 '제한 없음 기간'으로도 저장할 수 있다. 모든 항목이 아니오이고 복귀 시각이
  '병원이 정하지 않음'인 것과 같게 취급한다.

항목 이름은 **'예 = 제한, 아니오 = 제한 없음'** 방향으로 통일돼 있다. 보호자 항목을 '분리 허용'이
아니라 '곁을 지켜야 하나요'로 묻는 이유다. 방향이 섞인 항목을 하나라도 만들면, 답을 모를 때
엄격한 쪽으로 채우는 규칙이 그 항목에서만 반대로 동작한다.

## 날짜별 합성

날짜 D에 적용되는 기간은 두 가지다.

- 민감정보 동의가 유효할 때의 본인 체크 기간
- 철회되지 않았고 유효기간이 **D의 활동 종료 시각보다 늦은** 병원 기간.
  하루 도중에 만료되는 지침은 그날을 덮지 않는 것으로 본다(보수적 처리)

합성은 두 단계다. 먼저 '모르겠음'을 기본값으로 바꾸고 '기본값 적용' 표시를 붙인다. 그다음 **항목마다
가장 엄격한 값**을 고른다.

| 항목 | 엄격한 순서 |
| --- | --- |
| 외출 허용 | `FORBIDDEN` > `INDOOR_ONLY` > `ALLOWED` |
| 복귀 시각 | 설정된 시각 중 가장 이른 것(그 시각의 장소까지 함께) > '정하지 않음' |
| 보행·이동 한도 | 작은 값 > 제한 없음 |
| 예/아니오 항목 | 예 > 아니오 |
| 식사 제한 | 하루 종일 > 더 늦은 시각까지 > 더 이른 시각까지 > 없음 |
| 복약 | 모든 시각의 합집합. 같은 시각에 '숙소에서 복용'이 하나라도 예이면 예 |

기간 전체를 통째로 고르지 **않는다.** 예전 규칙("조건이 상충하면 추천하지 않음")은 기간이 겹치기 쉬운
대중형 사용에서 너무 자주 막혔다. 다만 **한 병원 기간 안의 모순**은 계속 막는다 — 같은 기간에
'동행 필요 = 예'와 '보호자 곁 지키기 = 아니오'가 함께 오면 그 기간이 덮는 날짜를
`CONFLICTING_CONDITION`으로 막는다. 본인 체크 화면은 그런 조합이 애초에 만들어지지 않게 한다.

적용된 값마다 **출처**(기간 id, 출처 종류, 기본값 여부)를 남기고 화면에 '병원 발행' / '본인 체크' /
'기본값 적용'으로 보여준다. 출처가 없는 값은 사용자가 왜 그렇게 됐는지 확인할 방법이 없다.

## 날짜 분류

| 분류 | 조건 | 결과 |
| --- | --- | --- |
| `FREE` | 경계일 이전이고 적용되는 기간이 없음 | 제한 없이 생성. 회복기 가산 버퍼 없음 |
| `DECLARED_FREE` | 적용되는 기간이 모두 '제한 없음 기간' | 자유일처럼 생성하되 '본인 체크: 제한 없음' 표시, 매일 확인 대상 |
| `RESTRICTED` | 적용되는 기간이 있고 합성 결과 외출이 금지가 아님 | 조건 안에서 생성 |
| `REST_DAY` | 합성 결과 외출 금지 | 환자 외출 없음. 병원 일정과 보호자 일정만 |
| `NEEDS_INPUT` | 경계일 이후인데 적용 기간 없음, 또는 숙소 없음 | 일정 없음 |

`NEEDS_INPUT` 사유는 동의 없음(`SENSITIVE_CONSENT_REQUIRED`), 지침 만료
(`HOSPITAL_PLAN_EXPIRED_INPUT_REQUIRED`), 숙소 없음(`LODGING_REQUIRED`), 그 밖(`CONDITION_INPUT_REQUIRED`)이다.

**경계일 이전의 빈 날짜는 자유일이다.** 수술 전에는 지킬 병원 조건이 아직 없으므로 병원 조건 게이트를
거치지 않는다. 나머지 게이트(휴무, 관광 활동 아님, 기상, 데이터 신뢰)는 그대로 적용한다.
**경계일 이후의 빈 날짜는 입력 필요다.** 수술 뒤 날짜를 조건 없이 자유일로 만들면 안 된다.

병원 값을 본인 체크로 **자동으로 옮기지 않는다.** 지침이 만료된 날짜는 "병원에서 새 지침을 받거나
본인 체크로 입력하세요"라고 안내한다. 만료된 병원 값을 계속 쓰면 앱이 병원 안내를 연장한 셈이 된다.

## 매일 확인

오늘이 체류 기간 안이고 오늘을 덮는 본인 체크 기간이 하나 이상이면(제한 없음 선언일 포함) 그날 처음
오늘 화면에 들어올 때 "오늘 조건이 그대로인가요?"를 묻는다.

- 확인 전: 오늘 일정은 보여주되 '확인 필요'를 상단에 고정하고, 길찾기와 장소 이동을 비활성화한다.
  오늘 상태는 `STANDBY`, 사유는 `DAILY_CHECK_PENDING`이다.
- '그대로예요' → 그날 자정까지 확인 완료.
- '바뀌었어요' → 조건 편집으로 보내고, 저장하면 재계획한 뒤 확인 완료.
- 미래 날짜는 매일 확인 대상이 아니다.
- 병원 기간만 덮는 날은 매일 확인을 하지 않는다. 대신 앱을 열 때 저장된 코드로 지침을 다시 받아
  버전 변경·철회·만료를 확인하고, 확인하지 않은 중요 안내가 있으면 `STANDBY` + `PLAN_UNCONFIRMED_UPDATE`다.

병원 지침의 최신성은 **"유효기간 안이고 철회되지 않음"**으로만 판정한다. 받은 지 24시간이 지났는지는
보지 않는다 — 유효기간이 한 달인 지침을 24시간 뒤에 만료로 취급하면 병원이 정한 기간과 앱이 정한
기간이 어긋난다. 본인 체크의 최신성은 매일 확인이 대신한다.

## 하루 일정 생성

활동 시간은 09:00–21:00(조정 가능)이고 입국일·출국일은 위 창으로 자른다. 고정 블록은 병원 일정 블록과
'숙소에서 복용' 복약 시각이며, 복약 후 15분이 지나야 다음 외출을 시작할 수 있다.

외출은 **그날 숙소에서 출발해 정거장 1곳 이상을 거쳐 복귀 장소로 돌아온다.** 고정 블록과 마감 사이
빈 구간에만 만들고, 구간이 45분 미만이면 만들지 않는다(`DEPARTURE_WINDOW_TOO_SHORT`).

**복귀 계산식** — 외출 단위로 계산하고, 이 식을 만족하지 못하면 외출을 만들 수 없다.

```
출발 + 호출·대기 5분 + Σ이동 + Σ체류 + 교통 변동 25%×Σ이동
     + 도착 여유 10분 + (제한일의 환자만) 회복기 가산 10분  ≤  마감
```

맞추기 위해 체류를 줄일 수 있지만 **정거장당 15분 미만으로는 줄이지 않는다.** 15분도 못 머무를
장소는 방문이 아니다.

마감은 다음 중 가장 이른 것이고, 어느 것이 마감을 만들었는지 이유를 함께 기록한다.

| 마감 후보 | 이유 코드 |
| --- | --- |
| 합성된 복귀 시각(그 장소로 복귀) | `RETURN_TIME` |
| 다음 '숙소에서 복용' 복약 시각(숙소로 복귀) | `MEDICATION` |
| 다음 병원 일정(마지막 외출은 그 병원으로, 앞선 외출은 숙소로) | `APPOINTMENT` |
| 활동 종료 | `DAY_END` |
| 출국일 마감 | `DEPARTURE` |

**보행 한도는 외출 1회 누적이다.** 정거장별로 적용하면 여러 곳을 묶을수록 총 보행이 늘어난다.
Σ정거장 보행 부담 추정 + Σ도보 구간 이동 ≤ 보행 한도이고, 넘으면 정거장을 줄이거나 뺀다
(`WALK_LIMIT_EXCEEDED`). **이동 한도는 구간당**이다 — 출발·정거장 사이·복귀 각각이 한도 이하여야 한다
(`TRAVEL_LIMIT_EXCEEDED`). 두 한도는 그 값이 있는 날에만 적용한다.

이동수단은 **제한일에 택시, 자유일에 대중교통**이다. 지하철 계단과 환승 보행을 정확히 잴 수 없어
회복기에는 택시로 가정한다. 모든 이동시간에 '추정' 표시를 붙인다.

검색 반경은 그날 숙소 기준으로 제한일 3km, 자유일 10km다. 정거장 수는 '느긋하게'가 외출당 2곳·하루
3곳, '보통'이 외출당 3곳·하루 5곳이다(식사 정거장 포함).

**식사 칸**은 점심 11:30–13:30, 저녁 17:30–19:30이다. 외출이 식사 칸과 겹치고 그 시각에 식사가
가능하면 식당 1곳을 배치한다. 통과한 식당이 없으면 식사 칸은 '추천 장소 없음'이고 **이것은 정상
결과다** — 다른 정거장으로 메우지 않고 사유를 함께 보여준다. 식사 칸에 카페·전통찻집은 넣지 않는다.

순위는 게이트를 통과한 후보만 대상으로 관심사 일치 → 복귀 여유 → 보행 부담 → 같은 날 유형 다양성
순이다. 인기·광고·제휴 점수는 없다. 같은 장소는 체류 중 한 번만 자동 배치한다(사용자가 직접 고른
경우는 예외). **같은 입력이면 같은 결과가 나온다.**

동행 필요가 '예'인데 동반 보호자가 없으면 그날 환자 외출은 0개이고 사유는 `ESCORT_REQUIRED`다.

**보호자 단독 외출**은 네 조건이 모두 맞을 때만 만든다: 동반 보호자 있음, 합성된 '곁 지키기'가 아니오,
동행 필요 아님, 그 구간에 환자가 쉬는 중. 보호자 외출에는 환자 조건(보행·식이·자외선·열·물)을
적용하지 않고, 환자가 숙소에 있는 구간 안에서만 만들며 환자의 병원 일정 블록과 겹치지 않는다.
자유일·제한 없음 선언일에는 보호자 단독 외출을 만들지 않는다 — 그런 날 보호자는 환자와 함께 다닌다.
보호자 외출의 이동은 택시 추정이고 검색 반경은 환자의 자유일 반경과 무관하게 3km다.

**날짜 상태**는 네 가지이고 앞쪽이 더 보수적이다.

| 상태 | 조건 |
| --- | --- |
| `NO_TOURISM` | 외출이 하나도 없음(휴식일, 입력 필요, 동행 필요 미충족, 서비스 중단 등) |
| `STANDBY` | 외출 가능 구간은 있는데 통과한 후보가 없음(`NO_CANDIDATE`) |
| `SPLIT_NEARBY` | 환자 외출은 없고 보호자 외출만 있음 |
| `TOGETHER` | 환자 외출이 1개 이상 |

사유 코드는 상태와 **항상 함께** 보여준다. 상태만 보여주면 사용자는 왜 못 나가는지 모른다.

## 장소 후보와 필터

출처는 관광공사 하나뿐이다. 항상 국문과 무장애 정보를 조회하고, 선택 언어가 영어·일본어·중국어면
그 언어 서비스를 더한다. 선택 언어 서비스가 없거나 실패하면 영문으로, 영문도 없으면 국문을 보여주고
'번역 필요'를 표시한다. 언어 간 매칭은 같은 장소 id이거나 같은 유형이면서 20m 이내일 때만 한다 —
**제목이 비슷하다고 같은 장소로 보지 않는다.**

**게이트**

| 게이트 | 규칙 |
| --- | --- |
| 관광 활동 아님 | 숙박 유형은 제외한다. 의료 시설도 정거장이 되지 않는다 — **한국어 원문 이름과 분류 코드로만** 판단하고, 한국어 원문이 없는 후보는 분류 코드만으로 본다. 표시 언어 이름을 보면 같은 장소가 언어에 따라 다르게 판정된다 |
| 휴무 | **닫힘 근거가 있을 때만** 제외한다. 정기 휴무 요일이 그 일정 날짜의 요일과 정확히 맞거나 행사 기간 밖이면 제외(`CLOSED`). 근거가 없으면 '운영 확인 필요'로 표시하고 열려 있다고 단정하지 않는다 |
| 실내·자외선·기상 | 실내 여부를 **모르는** 후보는 실내 전용이 필요하거나 기상이 나쁠 때 제외한다 |
| 열 노출 | 사우나·찜질·스파·온천·한증 단서가 있으면 제외(`HEAT_EXPOSURE`) |
| 물 | 수영장·워터파크·온천·수상레저 단서가 있으면 제외(`WATER_ACTIVITY`) |

열·물은 **단서가 없으면 노출이 없는 것으로 본다.**

**식이 필터는 식당·카페 후보에만 적용하고 항목마다 기준이 다르다.** 다섯 항목을 모두 '모르면 제외'로
하면 관광공사 데이터에 메뉴 정보가 드물어 수술 후 식사 칸이 거의 전부 빈다.

| 항목 | 규칙 |
| --- | --- |
| 술 | 주점 유형 식당을 제외한다(`DIET_RESTRICTED`) |
| 매운 음식·날음식 | 대표 메뉴·취급 메뉴·이름·세부 유형 단서로 판단해 해당 단서가 있으면 제외한다. **판단할 단서가 없어도 제외한다**(`MENU_UNKNOWN`). 카페·전통찻집 유형은 '해당 없음' 단서로 본다. 판단 결과는 '추정'으로 표시한다 |
| 뜨거운 음식·딱딱한 음식 | **제외하지 않는다.** 그 식당 카드에 주문용 한국어 카드를 연결한다 |
| 식사 제한 | 제한 시간 동안 식음 후보를 제외한다(`FASTING_REQUIRED`) |

관광공사 원문과 앱의 추정값은 **같은 필드에 섞지 않는다.** 이미지는 URL과 저작권 구분만 쓰고
파일을 내려받지 않는다.

## 전체 일정 확정과 변화 대응

체류 설정이 끝나면 전체 일정을 **한 번** 만들어 확정 일정으로 기기에 저장한다. 변화가 감지되지 않으면
당일에도 저장본을 그대로 쓴다.

변화 원천은 체류·숙소·병원 일정·동반 보호자·관심사·강도 수정, 조건 기간 변경, 동의 철회, 매일 확인의
'바뀌었어요', 기상 예보, 연동 지침의 버전 변경·철회·만료, 데모 사건이다. **언어 변경만 예외**로
재판정하지 않고 표시만 다시 쓴다 — 정거장·시각·상태는 그대로이고 전후 비교도 만들지 않는다.
판정 결과가 언어에 따라 달라지면 그건 결함이다.

**재계획 규칙**

1. 영향받은 날짜를 **게이트 1단계부터** 다시 판정한다. 부분 보정하지 않는다.
2. 지난 날짜와, 오늘 중 시작 시각이 이미 지난 정거장은 건드리지 않는다.
3. 사용자가 고정한 장소는 게이트를 통과하면 유지한다.
4. 사용자가 지운 장소는 그날 자동 채움에 다시 넣지 않는다.
5. 통과하지 못한 정거장은 **자동으로 다른 후보로 대체**한다. 대체 후보가 없으면 체류를 줄이거나
   정거장을 빼고, 그래도 안 되면 외출을 취소한다.

**알림만 하고 일정은 그대로 두는 재계산은 금지다.** 날짜마다 빠진 곳·들어온 곳·대체된 곳·줄어든 곳·
취소된 외출·상태 변경·새 마감·사유를 전후 비교로 기록하고, 사용자가 볼 때까지 '변경됨'을 표시한다.
**변화가 필요한데 전후 비교가 비어 있으면 실패로 처리한다.**

**오늘 게이트 덧씌우기** — 매일 확인 대기와 확인하지 않은 병원 중요 안내는 **저장된 확정 일정을
바꾸지 않는다.** 오늘 일정을 보여주는 시점에 같은 순수 함수로 덧씌워 상태를 `STANDBY`로 낮추고 이동
동작을 막는다. 확인이 끝나면 덧씌우기만 사라진다. 저장본을 고치면 확인 한 번에 확정 일정이 바뀌어
'변화가 없으면 저장본을 그대로 쓴다'는 규칙과 충돌한다.

**즉시 복귀** — 환자 호출, 외출 중 지침 철회, 외출 중 지침 만료가 일어나면 오늘 남은 일정을 비우고
즉시 복귀 시트를 자동으로 띄운다. **이 동작은 끌 수 없다.** 뒤로가기는 시트만 닫는다. 즉시 복귀
상태는 날짜가 바뀌거나, 원인이 사라지거나(사건 초기화, 유효한 지침이 다시 오늘을 덮음) 할 때만 풀린다.
원인이 풀리면(즉시 복귀 원인과 휴무·기상·병원 일정 변경·교통 지연 등 `LIFTABLE_CAUSES` 전부) 그 원인으로 비우거나
줄인 남은 시간을 지금 이후로 다시 짠다. 이미 출발한 외출과 도착한 정거장은 그대로다. 이때 보호자 외출은 원인 없는
하루의 보호자 외출 중 지금 이후에 출발하고 다시 짠 하루의 장소·보호자 외출과 겹치지 않는 것을 더해 환자 일정에 맞춰
다시 검증한다. 남은 시간 일정은 하루 정거장 한도를 모르고 짜므로, 환자 외출이 한도로 잘린 뒤 보호자 몫이 비지 않게
하려는 것이다(예: 환자 호출을 13:58에 초기화하면 보호자 저녁 외출도 돌아온다).
원인이 풀린 것이 아니어도 오늘을 지금부터 새로 짜는 재계획(다시 만들기, 고친 결과 외출이 하나도 남지 않은 하루)은 같은
방식으로 보호자 외출을 다시 채운다. 비울 원인이 없을 때만이고, 이미 출발한 외출은 옮기지 않는다.
외출 중 재계획으로 이미 늦은 경우(아래)도 같은 즉시 복귀다. 원인 판정은 엔진 한곳(`returnNowCauses`)에서만
하고, 원인 목록은 `RETURN_NOW_CAUSES` 하나다.

**외출 중 재계획으로 이미 늦음** (사유 `OUTING_OVERDUE`)

- 켜짐: 오늘을 다시 계산할 때, 이전 오늘 일정에서 외출 중이던(출발 시각 ≤ 지금 < 그 외출이 끝나는 시각) 환자
  외출이 다시 계산한 결과 여유가 음수이면 켜진다. 여유 음수는 남은 정거장을 줄이고도 복귀 마감을 맞출 수 없다는
  뜻이다. 원인은 가리지 않는다(병원 일정 앞당김, 병원 복귀 시각 변경, 교통 지연 사건).
- 이동 중(출발했고 첫 정거장 도착 전)인 외출도 같다. 이미 출발한 외출은 맞출 수 없어도 취소하지 않고 정거장 0개
  외출로 남기며(복귀 구간은 숙소에서 복귀 장소까지), 그 외출의 여유가 음수면 켜진다. 돌아갈 곳은 그 외출의 복귀 장소다.
  지금 창의 마감이 출발보다 이르면 정거장 0개 외출의 마감은 출발 시각이다. 이동한 시간과 상관없이 여유가 음수로
  일정하고, 바뀐 일정을 되돌리면 창의 마감으로 다시 잰다. 마감이 출발 뒤에 남아 있는 창(휴무로 비웠지만 바로 돌아가면
  맞출 수 있음)은 그 마감 그대로다.
  출발한 외출의 출발 시각은 재계획으로 옮기지 않는다. 화면은 정거장 0개 외출의 예상 귀가를 보이지 않고 복귀 마감만 보인다.
  동의 철회를 재계획하지 못해 기기에서 오늘을 입력 필요로 줄일 때도 이미 출발한 외출은 정거장 0개여도 id·복귀 장소·마감·
  여유와 함께 남긴다. 그래야 시트가 숙소가 아니라 그 외출의 돌아갈 곳을 보인다.
- 켜지지 않는 경우: 시간이 그냥 흘러 마감이 지난 것만으로는 켜지지 않는다. 외출 중이면 아직 마감 전이고, 입력이
  같으면 여유도 같다.
- 동작: 다른 즉시 복귀와 같다. 시작하지 않은 정거장을 비우고 날짜 상태는 `NO_TOURISM`, `returnNow`는 `true`다.
  시작된 정거장과 그 외출은 남는다.
- 유지: 이전 오늘 일정이 이 원인으로 즉시 복귀 중이면, 이미 출발한 그 외출의 여유가 다시 계산해도 음수인 동안
  유지한다. 외출 시간이 지났다고 저절로 풀리지 않는다. 즉시 복귀한 외출은 마감이 그때 시각으로 당겨져 저장되므로,
  여유는 새로 짠 하루의 값이 아니라 저장된 외출(정거장 그대로)을 지금 입력으로 다시 잰 값을 쓴다. 마감은 그 외출의
  출발 시각이 든 창에서 찾고, 지금 시각은 쓰지 않는다. 그런 창이 없으면 계속 늦은 것으로 본다.
- 해제: 바뀐 일정이 되돌려져(사건 초기화 등) 그 외출의 여유가 0 이상이 되면 풀리고, 다른 원인이 풀릴 때처럼
  지금 이후를 다시 짠다. 날짜가 바뀌어도 풀린다.
- 해제할 때 마감이 당겨진 외출(마감이 복귀 도착보다 이름)은 '끝난 외출'이 아니라 '다시 잴 외출'이다. 시작된
  정거장은 그대로 두고, 마감과 여유를 출발 시각이 든 지금 창으로 다시 잰다(유지 판정과 같은 창). 아직 밖에 있으면
  원인 없는 하루에서 같은 정거장을 든 외출의 그 뒤 정거장 중 지금 뒤에 도착하는 것을 되살린다. 출발 시각은 그대로이고,
  다시 잰 외출이 차지하는 시간에는 다른 외출을 짜지 않는다.

**시간이 흘러 마감이 지남** (시트만, 일정 유지)

- 앱이 열려 있으면 환자 외출의 복귀 마감 시각이 되는 순간(1분 안) '복귀 마감 시각이 지났어요' 시트를 띄운다.
  앱을 그 뒤에 열었으면 마감 + 60분 전까지만 띄운다(`DEFAULTS.notifications.returnPassedGraceMin`).
- **저장 일정을 바꾸지 않는다.** `returnNow`를 켜지 않고 남은 정거장도 그대로다. 판정을 새로 하지 않는 표시
  신호다(`lib/trip/overdue.js`). 그날이 이미 즉시 복귀 중이면 띄우지 않는다. 매일 확인 대기 중이어도 띄운다.
- 외출마다 한 번이다. 닫으면 그 외출로는 다시 뜨지 않고, 기기에 기억해(`overdueSeen`) 새로 고쳐도 다시 뜨지
  않는다. 날짜가 바뀌면 지운다. 마감이 같거나 더 이른 외출이 아직 창 안에 있으면 함께 닫힌다. 마감이 같으면
  나중에 출발한 외출을 보인다.
- 돌아갈 곳은 그 외출의 복귀 장소다. 숙소면 숙소 이름·주소, 병원이면 `hospitalId`로만 찾은 병원 이름·주소다.
  적힌 병원이 목록에 없으면 "정해 둔 장소"라고만 쓴다. 적힌 병원이 없고 그날 병원 일정이 모두 한 병원이면 그
  병원으로 보고, 두 병원이면 "정해 둔 장소"다. 경우 2(`OUTING_OVERDUE`)의 시트도 같은 규칙으로 장소를 보이고,
  숙소가 아니면 본문을 "아래 장소로"로 바꾼다. 다른 원인의 시트는 지금처럼 숙소다.
- 기기 알림: 환자 외출마다 마감 시각에 "복귀 마감이 지났어요" 알림(`RETURN_PASSED`)을 하나 더 낸다. 마감 뒤
  60분 안에 앱이 열리면 그때 한 번 내고, 이미 낸 알림 id는 기기에 기억한다.

## 사용자 편집

- **교체** — 정거장을 고르면 같은 시간 자리에 넣을 수 있는 후보를 최대 5개 보여준다. 고른 후보로
  외출 전체를 다시 검증하고(복귀 계산·보행 누적·이동 한도), 통과하지 못하면 넣을 수 없고 이유를
  보여준다. 교체한 장소는 '고정'이 된다.
- **삭제** — 정거장을 지우면 외출 시각을 다시 계산한다. 식사 칸 식당을 지우면 그 칸은 '비움'으로 두고
  **자동으로 다시 채우지 않는다.**
- **다시 만들기** — 범위는 '이 날짜' 또는 '오늘 이후 전체'이고 확인 대화를 거친다. 고정·삭제 기록을
  지우고 새로 만든다.
- 지난 날짜는 편집할 수 없다. 매일 확인 전인 오늘도 편집할 수 없다.

## 보호자

같은 기기에서는 하루 일정 화면의 환자/보호자 탭으로 본다. 다른 기기로는 **PIN 잠금 공유 링크**를 보낸다.

링크를 만들 때마다 공유 동의를 받고, 담기는 항목 목록을 동의 화면에 보여준다.

- **담는 것**: 만든 시각, 만료 시각(출국일 23:59), 언어, 날짜별 보호자 일정, 환자 복귀 마감과 복귀
  장소의 이름·주소, 동행 필요 여부, 보호자 단독 외출 가능 여부, 긴급 번호
- **담는 날짜** (2026-11-08): 만든 날(KST)부터 **7일**(`DEFAULTS.guardianLink.windowDays`), 출국일에서 멈춘다.
  입국 전에 만들어도 만든 날부터 7일 안의 체류 날짜만 담는다. 7일 뒤 날짜는 담지 않는다. 긴 체류에서도 링크가
  메신저 기준(8 KB) 안에 들도록 정한 규칙이다. 범위는 새 필드 없이 `days[].date`의 처음·끝으로 읽는다
- **담지 않는 것**: 조건 항목 세부(식이·복약·보행·자외선·열·물), 병원 이름·주소·전화, 병원 안내문,
  병원 일정. 환자 복귀 장소가 병원이면 이름은 일반 라벨 '병원'이고 주소는 비운다. 보호자 외출의
  마감 이유도 담지 않는다 — 마감 이유만으로 복약·병원 정황이 드러난다

보호자 외출은 환자 숙소로 돌아오므로 병원 주소가 없어도 복귀 기능은 그대로 동작한다.

사본이므로 **자동으로 갱신되지 않는다.** 보호자 화면 상단에 기준 시각을 표시하고, 환자 일정이 바뀌면
환자 화면에 '보호자 링크 다시 보내기'를 안내한다. 만료 시각이 지나면 표시하지 않고 삭제한다.

체류가 7일보다 길면 **환자가 새 링크를 다시 보낸다.** 링크 만들기 화면은 담는 범위('오늘부터 N일(날짜~날짜)')와,
그다음 날짜는 다음 주에 새 링크로 보내라는 문장을 동의 앞에 보여 준다. 보호자 화면은 기준 시각 옆에 담긴 범위를
보이고, 출국일이 범위 뒤면 그 뒤 일정은 새 링크로 받으라고 알린다. 범위가 다 지났으면(만료 전) 지난 범위와 새 링크
안내를 주의 안내로 띄운다. 만료 시각은 출국일 23:59 그대로다: 범위 끝에 만료시키면 사본이 지워져 보호자가 무엇을
받았고 왜 비었는지 알 수 없다. '다시 보내기' 판단(일정 지문)은 보낸 날의 7일 범위만 비교한다.

**복귀 마감 알림** (2026-11-07): 이 기기에 저장된 사본 가운데 **가장 최근에 가져온 사본 하나**의 오늘(KST) 환자
복귀 마감 시각마다 앱 안 배너를 한 번 낸다(`COMPANION_RETURN_PASSED`). 받은 일정 화면의 '복귀 마감 알림 받기'
스위치(기본 꺼짐, 설정 화면의 알림 스위치와 같은 기기 설정 `prefs.notifications`)를 켜 두었고 권한이 있으면 기기
알림도 함께 낸다. 스위치는 기기 알림만 가른다. 문구는 '일행'이라고 쓰고 마감 시각 하나만 넣는다. 마감 뒤 60분 안에 앱이 열리면 그때 한 번 내고, 60분이 지났으면 내지 않는다. 받은 일정
화면에서는 오늘의 지난 마감에 '마감 지남'(기호 + 글자), 아직인 마감에 '예정'을 붙이고, 지난 마감 아래에 연락
안내와 119·긴급 안내 버튼을 둔다. 표시는 그날이 끝날 때까지 남는다. 앱은 환자가 돌아왔는지 모르므로 "돌아오지
않았다"고 쓰지 않는다. 앱이 완전히 닫혀 있으면 알림이 오지 않을 수 있다(서버 푸시는 하지 않는다).

## 알림과 카드

알림은 권한을 설정에서 켤 때만 요청한다(보호자 받은 일정 화면의 스위치도 같은 설정이다). 복귀 마감
60·30분 전과 마감 시각, '숙소에서 복용' 복약 10분 전, '숙소 밖 복용' 복약은 그 시각, 병원 일정은 숙소에서
출발해야 하는 시각 15분 전에 알린다. 외출 중 재계획으로 즉시 복귀가 켜져 마감이 지금으로 당겨진 외출만 마감 지남
알림을 내지 않는다. 같은 날의 다른 외출과, 환자 호출·일정 철회·일정 만료로 즉시 복귀가 켜진 날의 외출은 실제 마감이
남아 있으므로 마감 시각 알림을 그대로 낸다.

**알림 문구에 조건 항목·병원 이름·복약 정보를 넣지 않는다.** 잠금 화면에 그대로 뜬다.
"18:00까지 숙소로 돌아갈 시간이에요" 정도로 쓴다. 알림 예약 항목도 같은 이유로 허용 목록 필드(id, kind, key,
time, at, expiresAt)만 가진다. 사본 id·장소 이름·주소를 항목에 넣지 않는다. 마감 시각 알림(환자의 '복귀 마감이
지났어요', 보호자의 '일행의 복귀 마감')은 시각이 지나도 마감 + 60분까지 예약에 남고, 이미 낸 것은 기기에 기억해
한 번만 낸다.

한국어 안내 카드(식이·이동·복귀·병원)는 **고정 문구**다. AI를 쓰지 않고, 사람이 검수할 대상이며,
로그인이 만료되거나 오프라인이어도 보여준다.

지도는 외부 링크로만 연다. 링크에는 **목적지 이름과 좌표만** 넣고 출발지 매개변수는 넣지 않는다.
숙소·병원 좌표는 어떤 지도 링크에도 들어가지 않는다 — 복귀 카드는 주소 글자만 보여준다.

## AI 소개 문장

하루 일정을 소개하는 짧은 글에만 쓴다. **배치·판정에는 관여하지 않는다.**

- 스위치와 키가 **둘 다** 있을 때만 동작한다. 기본은 꺼짐이다.
- 입력하는 것: 언어, 그날 정거장의 공개 장소 이름·유형·시각, 관심사 태그, 이동 강도.
- 입력하지 않는 것: 조건 항목, 병원·시술 정보, 숙소 이름·주소, 날짜, 계정 정보.
- 꺼져 있거나 실패·시간 초과·검사 불합격이면 정해진 템플릿 문장을 쓴다.
- 출력 검사에 하나라도 걸리면 템플릿으로 바꾼다: 200자 초과, 선택 언어의 문자 체계가 아님,
  안전·안심 단정, 영업 중 단정, 보장·순위 표현, 가격, 그리고 의료 언급.
- 의료 언급에는 회복·치료·약·수술뿐 아니라 **이 서비스의 진료 과목 어휘**(성형, 피부과, 미용 의료,
  보톡스, 필러, 레이저 등)가 네 언어 모두 들어간다. 대상 환자가 받은 시술을 문장이 드러내면
  그것만으로 의료 정보가 된다.
- 화면에 'AI가 쓴 소개'라고 표시하고 판정·사유 영역과 시각적으로 분리한다.

## 언어

지원 언어는 한국어·영어·일본어·중국어(간체)다. 사용자가 고른 언어가 우선이고, 없으면 브라우저
언어로 정한다(`ko*`→한국어, `ja*`→일본어, `zh*`→중국어, 그 외 전부 영어).

**안전 문구**(상태 메시지, 사유, 고지, 복귀 안내)는 선택 언어와 한국어를 **함께** 보여준다.
선택 언어가 한국어면 한국어+영어다. 환자와 보호자의 언어가 다를 수 있기 때문이다.

일본어·중국어 안전 문구는 **사람 검수가 끝나기 전까지 영어+한국어로** 보여준다. 일반 화면 문구는
번역을 그대로 쓴다. 검수 전 번역으로 안전 판정을 전하면 오역이 그대로 판정이 된다.

## 병원 연동

현재 실제 연동 병원은 0곳이고 데모 코드만 있다. '병원 연동 데모' 배지를 **상시** 표시한다 —
데모를 실제 연동처럼 보이게 하지 않는다.

- 지침은 기간 목록을 담는 v2 계약만 받는다. v1은 받지 않는다.
- 형식이 어긋나면 지침 전체를 거부하고, 허용 목록 밖 필드는 게이트웨이에서 버린다.
- 기간을 유효기간에 맞춰 잘라내지 않는다. 그대로 저장하고 날짜마다 적용 여부를 판정한다.
- 병원 안내문은 **표시 전용**이다. 번역·요약·편집하지 않고 판정에 쓰지 않는다.
- 같은 안내문 id라도 갱신 시각이 바뀌면 확인이 풀린다.
- 연동 병원의 환자 호출은 지침 필드가 아니다. 현재는 데모 사건으로만 다룬다.

## 운영 안전장치

**추천 중단 스위치**가 켜지면 일정 생성·재계획·교체 후보 조회가 모든 날짜를 정거장 없이
`NO_TOURISM` + `SERVICE_PAUSED`로 돌려준다. 스위치 상태는 응답에 드러내 사용자가 이유를 알 수 있게
한다 — 조용히 막지 않는다. 긴급 연락·카드·조건 화면은 계속 동작한다.

안전장치는 **더 안전한 쪽으로만** 움직인다. 추천을 강제로 켜는 스위치는 만들지 않는다.
