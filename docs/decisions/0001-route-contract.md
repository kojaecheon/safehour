# ADR-0001: D03 화면 계약의 라우트 구조

- 상태: Accepted
- 날짜: 2026-08-03
- 승인일: 2026-08-03
- 작업 ID: AX-003
- 연결 문서: D03-SCR001–SCR008, D03-NAV001–NAV004, D04-F013, D09-AC016·AC018
- 결정자: 플랫폼 PO (운영자 승인)

## 맥락

D03은 8개 화면에 각각 URL을 부여한다. 그러나 문서 상태는 `WORKING`이고 URL은 모두
"URL 후보"로 표기되어 있다. 현재 구현은 5개 라우트로 되어 있어 문서와 어긋난다.

| D03 화면 | D03 URL 후보 | 현재 구현 |
| --- | --- | --- |
| SCR001 시작·안전 안내 | `/` | `/` — 일치 |
| SCR002 기준점·복귀시간 | `/plan/location` | `/plan` 한 화면에 통합 |
| SCR003 병원 주의조건 | `/plan/condition` | 〃 |
| SCR004 역할·활동 모드 | `/plan/role` | 〃 |
| SCR005 판정 결과 | `/result` | `/result` — 일치 |
| SCR006 장소 상세 | `/place/{candidate_id}` | 없었음 (AX-005에서 신설) |
| SCR007 변화 전후 비교 | `/result/change` | `/result` 위 모달 시트 |
| SCR008 즉시 복귀 안내 | `/return` | `/result` 위 모달 시트 |

이 결정을 미루면 AX-004(E2E), AX-005(SCR006), AX-101(Figma 매핑), AX-202(화면·URL
대응표)가 모두 어느 URL을 기준으로 삼을지 알 수 없다.

### 제약

- 비로그인 MVP. 계정 기능은 1차 범위 제외(D03-NAV004). 상태는 `sessionStorage` 단일 슬롯
  (`safehour.result`)에만 있다.
- 판정은 stateless다. 서버는 세션도 판정 결과도 저장하지 않는다.
- D03-NAV004: "브라우저 뒤로가기 시 입력값을 유지한다", "의료·안전 차단 결과를
  뒤로가기로 우회할 수 없다".
- 2026-09-18 기능 동결. AX-004·007·105 등 다수 항목이 아직 대기 상태다.

## 선택지

### 1. D03 원안대로 8개 라우트로 분리

- 장점: 문서·구현 일치. 화면당 고정 URL이 생겨 증빙·Figma 매핑이 단순해진다.
  단계별 진입을 퍼널 지점으로 삼을 수 있다.
- 단점: `/plan` 3분할은 단계 간 draft 영속화를 **동작 전제조건**으로 만든다
  (현재 폼 상태는 `useState`뿐이고 저장되지 않는다). `/result/change`는 델타가
  직전 액션의 산물이라 URL로 재현할 수 없어 새로고침 시 빈 화면이 된다.
  `/return`을 라우트로 빼면 뒤로가기로 복귀 안내를 벗어날 수 있어 NAV004와 충돌한다.

### 2. 현행 5개 라우트 유지 + SCR006만 신설 (혼합)

- 장점: 재현 가능한 화면만 URL을 갖는다. 상세 조회의 지연·실패가 결과 화면에서 격리된다.
  안전 알림(변화·복귀)은 모달로 두어 뒤로가기 우회가 구조적으로 불가능하다.
  동결까지 남은 일정을 미구현 항목에 쓸 수 있다.
- 단점: D03 본문을 수정해야 한다. `/plan` 폼이 길어 360px에서 인지 부하가 있다.
  단계별 퍼널 계측을 라우트로 얻을 수 없다.

### 3. `/plan`만 분리하고 나머지는 현행 유지

- 장점: 모바일에서 한 화면 한 결정(D03 UX 원칙 3)에 가깝다.
- 단점: draft 영속화 비용은 그대로 발생하는데, 얻는 것은 입력 화면 분할뿐이다.

## 권고 (사람 승인 전)

**선택지 2 (혼합)** 를 권고한다. 세 관점(심사·제품 / 구현·안정성 / 접근성·UX)의
독립 판정 결과는 다음과 같았다.

| 항목 | 심사·제품 | 구현·안정성 | 접근성·UX | 결과 |
| --- | --- | --- | --- | --- |
| SCR002–004 | 통합 유지 | 통합 유지 | 분리 | 통합 유지 (2:1) |
| SCR006 | 별도 라우트 | 별도 라우트 | 별도 라우트 | **만장일치** |
| SCR007·008 | 모달 유지 | 모달 유지 | 모달 유지 | **만장일치** |

판단을 가른 기준은 하나다 — **URL로 다시 만들 수 있는 화면은 라우트로 빼고,
다시 만들 수 없는 화면은 모달로 둔다.**

- **SCR006은 라우트가 맞다.** 상세는 `candidate_id`로 다시 조회할 수 있고, 국문·영문
  각 3콜씩 최대 6콜의 신규 외부 호출을 일으킨다. 이 지연·실패를 결과 화면 위에 얹으면
  심사 메인 화면에서 터진다. 라우트로 빼면 실패가 격리되고 뒤로가기로 결과가 복원된다.
  D09-AC016(영문·국문 폴백) 증빙을 고정 URL로 캡처할 수 있다는 점도 크다.
- **SCR007은 라우트로 뺄 수 없다.** 델타(`before`/`after`)는 서버가 저장하지 않는
  직전 액션의 산물이라 URL 재방문으로 재현되지 않는다. 라우트로 빼면 새로고침 한 번에
  빈 화면이 되는 화면이 생긴다.
- **SCR008은 라우트로 빼면 안전 설계에 역행한다.** 즉시 복귀는 `returnNow` 판정에
  종속돼 자동 표시된다. 이를 `router.push`로 바꾸면 뒤로가기로 복귀 안내를 벗어날 수
  있어 NAV004("차단 결과를 뒤로가기로 우회할 수 없다")를 정면으로 위반한다.
- **`/plan` 통합 유지**는 2:1이다. 분리를 지지한 접근성 관점의 근거(360px 인지 부하,
  한 화면 한 결정)는 타당하지만, 분리가 요구하는 draft 영속화·부분 검증·단계 간 상태
  정합은 동결 전 일정에서 감당할 비용이 아니다. 다만 아래 보완 조건을 함께 채택한다.

### 보완 조건 (권고안 채택 시 함께 처리)

1. **화면 ID 대응 유지** — `/plan#location`, `/plan#condition`, `/plan#role` 앵커를
   각 `section`에 부여해 D03 화면 ID ↔ 구현 앵커 대응표를 만든다. AX-101·AX-202
   증빙이 그대로 살아난다.
2. **입력 유지(NAV004) 결함 수정** — 세 관점이 공통 지적. 현재 `/plan` 폼은 어디에도
   저장되지 않아 `/result`에서 돌아오면 전부 초기화된다. 이는 라우트 구조와 무관한
   기존 위반이며 통합 유지안에서도 반드시 고쳐야 한다.
3. **모달 뒤로가기 처리** — 시트가 열린 상태에서 안드로이드 뒤로가기를 누르면 시트가
   닫히는 대신 페이지를 떠난다. 즉시 복귀 시트에서 이 동작은 안전 지시를 잃게 한다.
   `history.pushState` + `popstate` 처리로 뒤로가기가 시트만 닫도록 한다.
4. **SCR006 차단 상태 가드** — 저장된 판정이 차단 상태이거나 `returnNow`면 상세 대신
   복귀 안내를 표시한다. 없으면 `/place`가 NAV004의 우회 경로가 된다.
5. **SCR007 증빙 보완** — 시트를 닫아도 결과 화면에 "마지막 변화 요약"을 잔존시켜
   AC010·AC012 증빙이 스크린샷 한 장에 의존하지 않게 한다.

## 결정

**선택지 2 (혼합) 를 채택한다.** 2026-08-03 운영자(플랫폼 PO)가 승인했다.

확정된 라우트 계약은 다음과 같다.

| 화면 | 확정 계약 | 원안 대비 |
| --- | --- | --- |
| SCR001 시작·안전 안내 | `/` | 유지 |
| SCR002–SCR004 입력 | `/plan` (앵커 `#location` `#condition` `#role`) | **변경** — 3개 URL → 1개 URL + 앵커 |
| SCR005 판정 결과 | `/result` | 유지 |
| SCR006 장소 상세 | `/place/{candidate_id}` | 유지 |
| SCR007 변화 전후 비교 | `/result` 내 모달 | **변경** — `/result/change` 라우트 폐기 |
| SCR008 즉시 복귀 안내 | `/result` 내 모달 | **변경** — `/return` 라우트 폐기 |

채택 이유는 권고 절에 적은 기준 그대로다 — URL로 다시 만들 수 있는 화면만 라우트를
갖는다. 델타는 서버가 저장하지 않아 URL 재현이 불가능하고, 즉시 복귀를 라우트로 빼면
뒤로가기로 안전 차단을 우회할 수 있어 D03-NAV004를 위반한다. `/plan` 분할이 요구하는
draft 영속화·부분 검증·단계 간 상태 정합은 2026-09-18 동결 전 일정에서 감당할 비용이
아니라고 판단했다.

보완 조건 5건은 AX-010으로 등록해 별도 이행한다. 특히 조건 2(입력 유지)는 이 결정과
무관한 기존 D03-NAV004 위반이므로 우선 처리한다.

## 영향

- **D03 문서**: 승인 시 SCR002–004의 URL 후보를 `/plan`(앵커 병기)으로, SCR007·SCR008을
  "결과 화면 내 모달"로 수정한다. SCR006은 원안(`/place/{candidate_id}`) 유지.
- **구현**: SCR006은 AX-005에서 이미 신설됐다(PR #3). 보완 조건 2·3·4·5는 후속 작업이 필요하다.
- **개인정보**: 보완 조건 2(draft 저장)는 금식·외출 허용 등 병원 조건을 단말에 남긴다.
  제출·차단 시 명시적 삭제 규칙이 필요하고 D07-POL008 검토 대상이다.
- **호출량**: `/place` 진입마다 최대 6콜이 발생한다. AX-006의 800 경고 / 1,000 차단
  경계와 부딪힐 수 있어, 시연 리허설 반복 전에 강남 프리셋 캐시를 워밍해야 한다.
- **rollback**: 라우트 추가는 되돌리기 쉽다. `/place`를 제거해도 결과 화면은 독립적으로 동작한다.

## 검증과 재검토

- 증거: 3관점 독립 판정 기록(작업 로그), AX-005 브라우저 검증(코엑스몰 상세 실데이터),
  `test/place-api.test.js` 10건.
- 재검토 조건:
  - 위치정보 사전검토가 통과되어 지도·경로 실연동(AX-103)이 들어오면 SCR008은 지도를
    담는 독립 화면이 되어야 하므로 `/return` 라우트를 다시 검토한다.
  - 제출 서식이 "화면 단위 URL 목록"을 정형으로 요구하면 앵커 대응표로 먼저 대응하고,
    그래도 부족하면 `/plan` 분할을 재검토한다.
  - 2026-09-18 기능 동결 이후에는 이 ADR을 변경하지 않는다.
