# ADR-0003: 다국어 전략과 언어 결정 경로

- 상태: Accepted
- 날짜: 2026-08-13
- 작업 ID: AX-209
- 연결 문서: D01 대상 사용자, D03 화면 계약, D07-POL004(원문 보존), D09-AC019
- 결정자: 구현 결정 (사용자 대면 문구의 **번역 품질 검수**는 여전히 사람 승인 사항 — AX-106 5절)

## 맥락

SafeHour 의 대상 사용자는 **성형외과·피부과 시술을 받은 외국인 환자와 동반 보호자**다.
그런데 이 결정 전까지 화면은 한국어 전용이었고, 영문은 상태 배너 한 줄에만 병기돼 있었다.

즉 **대상 사용자가 제품을 읽을 수 없는 상태**였다. 안전 조건 입력 화면조차 한국어라,
"금식 중", "외출이 허용되지 않았습니다" 같은 **안전에 직결되는 선택지**를 이해하지 못한 채
체크할 수 있었다. 이것은 UI 개선 항목이 아니라 제품 목적의 실패다.

동시에 지켜야 할 제약이 있었다.

- **원문은 번역 대상이 아니다.** TourAPI `overview`·운영시간·기상 실황은 원문 그대로 두어야
  한다 (D07-POL004). 번역은 라벨과 SafeHour 자체 문구에만 적용된다.
- **판정은 언어와 무관하다.** 서버는 언어를 몰라야 하며, 언어가 판정 결과를 바꿔선 안 된다.
- **stateless 원칙**을 깨지 않아야 한다. 서버에 사용자 상태를 만들 수 없다.
- ADR-0001 의 라우트 계약(`/`, `/plan`, `/result`, `/place/{id}`)을 바꾸지 않아야 한다.

## 선택지

### A. 라우트 기반 i18n (`/en/plan`)

- 장점: URL 로 언어가 드러나고 공유·SEO 에 유리하다. Next.js 관례에 가깝다.
- 단점: **ADR-0001 라우트 계약을 다시 연다.** 화면 수가 2배가 되고, 모달 뒤로가기(AX-011)와
  차단 가드 경로를 언어별로 다시 검증해야 한다. 제출 마감까지 감당할 위험이 아니다.

### B. 서버에서 `Accept-Language` 로 렌더

- 장점: 첫 페인트부터 올바른 언어다.
- 단점: 같은 URL 이 요청자에 따라 다른 HTML 을 반환해 캐시가 갈라진다. 무엇보다
  **서버가 사용자 속성을 읽기 시작한다** — stateless·무수집 원칙과 방향이 반대다.

### C. 클라이언트 언어 컨텍스트 + 사전 (채택)

- 서버 렌더는 항상 `ko` 로 나가고, 마운트 후 `sessionStorage` → `navigator.language` 순으로
  언어를 정한다. 화면 문구는 `src/i18n/dictionary.js` 에서 온다.
- 장점: 라우트·서버 계약을 건드리지 않는다. 언어가 서버로 나가지 않는다.
  판정 로직과 완전히 분리된다.
- 단점: 영어 사용자에게 **첫 프레임이 한국어로 잠깐 보인다**(FOUC).

## 결정

**C 를 채택한다.**

FOUC 는 이 저장소가 이미 시간 기본값·세션 복원에 쓰고 있는 패턴(마운트 후 갱신)과 같은
성질의 비용이며, 하이드레이션 불일치를 만들지 않는 것이 더 중요하다. 라우트 계약을 다시
여는 비용(A)과 서버가 사용자 속성을 읽기 시작하는 비용(B)이 훨씬 크다.

### 세부 규칙

1. **언어 결정 순서**: `sessionStorage['safehour.lang']` → `navigator.language` → `ko`.
   한국어 태그(`ko*`)만 `ko` 로 좁히고 **나머지는 전부 `en`** 으로 본다 — 대상 사용자가
   외국인이므로 모르는 언어를 한국어로 떨어뜨리면 안 된다.
2. **저장소는 sessionStorage 만 쓴다.** localStorage 를 새로 만들지 않는다.
   개인정보 검토 대상(`SIGNOFF_CHECKLIST.md` 2.4)을 늘리지 않기 위해서다.
   대신 매 세션 `navigator.language` 로 자동 감지되므로 실사용에 불편이 없다.
3. **언어는 서버로 전송하지 않는다.** 요청 본문·헤더·쿼리 어디에도 넣지 않는다.
4. **안전 문구의 정본은 도메인 계층이다.** `STATE_MESSAGE`·`REASON_TEXT` 가 ko/en 을
   모두 갖고, 화면은 그것을 조회만 한다. 화면 사전이 안전 문구를 다시 정의하지 않는다.
5. **상태 배너와 즉시 복귀 시트는 두 언어를 함께 보여준다.** 언어를 바꾸지 못한 사용자,
   그리고 환자와 보호자의 언어가 다른 경우를 위한 안전장치다.
6. **원문에는 원문 언어를 `lang` 으로 붙인다.** 장소명·개요가 국문 폴백이면 `lang="ko"`,
   영문 원문이면 `lang="en"` — 스크린리더가 잘못된 음성으로 읽지 않게 한다.
7. **`document.documentElement.lang` 을 실제로 갱신한다** (WCAG 3.1.1).
8. **문구가 아니라 키를 저장한다.** 오류·안내·변화 요약은 사전 키와 값으로 보관해
   언어를 바꾸면 이미 화면에 뜬 문구도 함께 바뀐다.

## 결과

- 새 파일: `src/i18n/dictionary.js`(화면 문구), `src/i18n/index.js`(런타임),
  `components/LanguageProvider.js`, `components/LanguageToggle.js`
- 변경: 4개 화면 + 5개 컴포넌트가 사전을 통해 렌더된다. `lib/format.js` 는 로케일을 받는다.
- 검증: `test/i18n.test.js` 24건 — 번역 누락·자리표시자 불일치·미사용 키·한국어 복사본을
  전부 실패로 고정한다. `e2e/i18n.spec.js` 10건 — 영어권 브라우저 자동 진입, 전환,
  안전 문구 병기, 44px 터치 대상.
- Playwright 기본 로케일은 `ko-KR` 이므로 기존 28건은 그대로 한국어 경로를 검증한다.
