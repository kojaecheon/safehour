# ADR-0005: 본인 체크 재도입과 조건 기간 합성

- 상태: Accepted
- 날짜: 2026-09-18
- 작업 ID: AX-301
- 연결 문서: `docs/platform/PRODUCT_DEFINITION_V3.md` 7.2절, `docs/platform/ITINERARY_RULES.md` 3.4절·4–6장,
  `docs/PRODUCT_DEFINITION.md`(v2) 9-3절, ADR-0009(민감정보 동의), ADR-0011(병원 기간·최신성)
- 결정자: 운영자 (대화 결정)

## 맥락

v2는 병원이 발행한 조건만 받았다. 수기 입력은 "환자가 한국어 안내문을 해석한다"는 결함 때문에 철회했다
(`docs/PRODUCT_DEFINITION.md` 9-3절). 이 구조에서는 유효한 병원 조건이 없으면 추천하지 않는다.

그런데 연동 병원은 0곳이다. 병원 발행만으로는 실제로 쓸 수 있는 사람이 없고, 대중형 제품이 될 수 없다.

동시에 지켜야 할 제약이 있다.

- 앱은 의료 판단을 하지 않는다. 증상·시술 종류·회복 단계를 묻거나 해석하지 않는다.
- 수기 입력을 없앤 이유는 지금도 위험이다. 환자가 안내문을 자유롭게 옮겨 적으면 앱이 그 문장을 해석해야 한다.
- 체류는 최대 45박이고, 날짜마다 적용되는 주의사항이 다르다. 조건 하나로 체류 전체를 덮을 수 없다.

## 선택지

1. **병원 발행만 유지한다** — 안전 원칙은 가장 단순하지만, 연동 병원이 없으니 제품을 쓸 수 없다.
2. **안내문 사진을 AI가 정리한다** — 입력은 편하지만, 오역 책임과 의료 경계 문제가 생긴다.
3. **자유 서술 수기 입력을 되살린다** — 입력 폭은 넓지만, 앱이 문장을 해석해야 한다.
4. **정해진 항목만 고르는 본인 체크(채택)** — 환자가 병원 안내를 보고 정해진 항목의 답을 고른다.
   앱은 답을 해석하지 않고 그대로 적용한다.

## 결정

**정해진 항목만 받는 본인 체크를 다시 들이고, 조건을 '기간' 단위로 받아 날짜마다 합성한다.**

### 조건 기간

- 조건 기간은 날짜 범위 하나(시작일·종료일 포함)에 적용되는 제한조건 묶음이다.
- 출처는 `SELF`(본인 체크) 또는 `HOSPITAL`(병원 발행)이다. 같은 날짜에 여러 기간이 겹쳐도 된다.
- 자유 서술 입력칸은 없다. 앱은 입력값을 해석하지 않는다.
- 본인 체크는 민감정보 동의 후에만 입력할 수 있다(ADR-0009).
- `SELF` 기간은 '제한 없음 기간'으로도 저장할 수 있다.
  모든 항목이 '아니오'이고 복귀 시각이 '병원이 정하지 않음'인 것과 같다.

### '아니오'와 '모르겠음'을 구분한다

| 답 | 적용 |
| --- | --- |
| 값 있음 | 그 값을 적용한다 |
| 아니오(병원이 그런 안내를 하지 않음) | 제한 없음 |
| 모르겠음 | 가장 엄격한 기본값을 적용하고 '기본값 적용'으로 표시한다 |

- 필수 항목인 외출 허용 여부(`outing`)와 복귀 시각(`returnTime`)에는 '모르겠음'이 없다.
  외출이 `FORBIDDEN`이면 복귀 시각은 묻지 않는다.
- 병원 발행 기간에는 '모르겠음'이 없다. 값 있음 또는 아니오만 있다.
- '모르겠음' 기본값은 의료진 검토 전 임시값이다(`ITINERARY_RULES.md` 11장).

### 보호자 분리 항목을 뒤집는다

- 기존 `splitAllowed`(보호자 분리 허용)를 `guardianMustStay`(환자가 쉬는 동안 보호자가 곁을 지켜야 하나요?)로 바꾼다.
- 이렇게 하면 모든 예/아니오 항목이 '예 = 제한, 아니오 = 제한 없음'으로 맞춰진다.
- 동행 필수(`escortRequired`)가 '예'면 `guardianMustStay`는 묻지 않고 '예'로 고정한다.

### 겹치면 항목별로 가장 엄격한 값을 쓴다

1. 각 기간의 '모르겠음'을 기본값으로 바꾸고 '기본값 적용' 표시를 붙인다.
2. 항목마다 가장 엄격한 값을 고른다(외출은 `FORBIDDEN`이 이기고, 복귀 시각은 이른 값, 한도는 작은 값,
   예/아니오는 '예', 식사 제한은 `ALL_DAY`가 가장 엄격, 복약 시각은 합집합).
3. 적용한 값마다 출처(기간 id, `SELF`/`HOSPITAL`, 기본값 여부)를 남기고 화면에 보여준다.

한 병원 기간 **안에서** 동행 필수와 보호자 분리 허용이 함께 오면 그 기간의 날짜를 `CONFLICTING_CONDITION`으로 막는다.
본인 체크 화면은 이런 모순이 애초에 만들어지지 않게 한다.

### 조건이 없는 날짜는 수술 후 경계일로 나눈다

- 수술 후 경계일 = 가장 이른 `수술·시술` 일정의 날짜. 이 일정이 없으면 체류 설정을 저장할 수 없다.
- 경계일 전 날짜에 적용 기간이 없으면 **자유일**(`FREE`)이다. 병원 조건 게이트를 거치지 않고 일정을 만든다.
  **이것은 "병원 조건이 없으면 추천하지 않는다" 원칙을 의도적으로 바꾼 것이다.**
  휴무·관광 활동 아님·기상·데이터 신뢰 게이트는 그대로 적용한다.
- 경계일부터는 적용 기간이 없으면 **입력 필요**(`NEEDS_INPUT`)이고 일정을 만들지 않는다.
- 날짜 분류 전체와 사유 코드는 `ITINERARY_RULES.md` 5장에 있다.

## 대안과 버린 이유

| 대안 | 버린 이유 |
| --- | --- |
| 병원 발행 조건만 받는다(v2 유지) | 연동 병원이 0곳이라 대중형 제품이 될 수 없다 |
| 병원 안내문 사진을 AI가 읽어 조건으로 정리 | 오역 책임과 의료 경계 문제가 생긴다. 안내문을 재해석하지 않는다는 기존 금지와도 맞지 않는다 |
| 자유 서술 수기 입력 | v2에서 수기 입력을 없앤 이유("환자가 한국어 안내문을 해석한다")가 여전히 위험이다. 정해진 항목만 받고 앱은 해석하지 않는다 |
| '아니오'와 '모르겠음'을 하나로 합침(모르면 곧 제한) | 혼자 온 환자는 '동행 필수' 기본값 때문에 외출이 막히고, 식이 기본값 때문에 맛집이 대부분 빠진다 |
| 기존 `splitAllowed`를 그대로 씀 | '아니오(안내 없음)'가 '분리 불가'라는 제한으로 뒤집힌다. 다른 항목과 '예 = 제한' 규칙이 어긋난다 |
| 조건이 상충하면 추천하지 않음(기존 규칙 유지) | 본인 체크와 병원 발행, 여러 기간이 겹치는 대중형에서는 너무 자주 막힌다. 대신 항목별로 엄격한 값을 고르고, 한 병원 기간 안의 모순만 계속 막는다 |

## 영향

- **도메인**: 체류·조건 기간·답(`Answer`) 모델과 합성·날짜 분류 순수 함수가 새로 생긴다.
  사유 코드 `LODGING_REQUIRED`, `CONDITION_INPUT_REQUIRED`, `SENSITIVE_CONSENT_REQUIRED`,
  `HOSPITAL_PLAN_EXPIRED_INPUT_REQUIRED`를 더한다.
- **화면**: `/conditions`에 동의 단계, 기간 목록, 항목별 예/아니오/모르겠음 입력, 날짜별 합성 결과와 출처 표시가 생긴다.
- **병원 연동**: 병원 지침 v2의 각 기간은 `HOSPITAL` 기간으로 같은 합성에 참여한다(ADR-0011).
- **개인정보**: 본인 체크 값은 민감정보다. 동의 후에만 입력하고, 기기에만 저장하며, 동의를 철회하면 지운다(ADR-0009).
  서버는 판정 요청의 조건 값을 계산 뒤 버리고 로그에 남기지 않는다.
- **최신성**: 본인 체크의 최신성은 매일 확인이 대신한다(ADR-0011).
- **rollback**: 본인 체크를 되돌리면 경계일 이후 날짜는 병원 기간이 없는 한 모두 입력 필요가 된다.
  경계일 전 자유일 규칙은 별개의 변경이므로 되돌릴지 따로 판단해야 한다.

## 검증과 재검토

- 증거: 필수 항목 누락 거부, '모르겠음' 기본값 적용과 '기본값 적용' 표시, 겹친 기간의 항목별 합성과 출처 기록,
  한 병원 기간 안의 모순 차단, 경계일 전후 날짜 분류를 단위 테스트로 고정한다.
- 재검토 조건
  - 의료진이 '모르겠음' 기본값이나 항목 목록을 확정하면 값을 반영한다(`HUMAN_ACTIONS.md` 4번).
  - 실제 연동 병원이 생겨 병원 발행 비율이 높아지면 본인 체크의 기본 위치를 다시 본다.
