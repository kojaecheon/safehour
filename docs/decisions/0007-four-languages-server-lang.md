# ADR-0007: 4개 언어와 서버 언어 전송, 안전 문구 병기 규칙

- 상태: Accepted
- 날짜: 2026-09-18
- 작업 ID: AX-301
- 연결 문서: **ADR-0003을 개정한다.** `docs/platform/ITINERARY_RULES.md` 8.1절·9.2절,
  `docs/platform/IA_AND_FLOWS.md` 3.3절, ADR-0009(기기 저장)
- 결정자: 운영자 (대화 결정)

## 맥락

ADR-0003은 한국어·영어 두 언어를 정했고, 판정과 언어를 떼어 놓기 위해 **언어를 서버로 보내지 않는다**고 정했다.
3번째 언어(중국어·일본어)는 미결정으로 남겼다.

대중형 제품의 대상에는 일본어·중국어 사용자가 들어간다. 그런데 일본어·중국어 관광 데이터는
관광공사의 언어별 서비스에서 따로 받아야 한다. 서버가 사용자 언어를 모르면 어느 언어 서비스를 조회할지 정할 수 없다.

동시에 지켜야 할 것이 있다.

- 판정은 언어와 무관해야 한다. 입력이 같으면 언어가 달라도 정거장과 상태가 같아야 한다.
- 안전 문구는 의미가 정확해야 한다. 일본어·중국어 안전 문구는 아직 사람 검수를 받지 않았다.
- 병원 안내문(채널 B)은 번역하지 않는다.

## 선택지

1. **언어를 서버로 보내지 않고 4개 언어 관광 데이터를 모두 조회한다** — ADR-0003 규칙은 지키지만 호출량이 늘어난다.
2. **ADR-0003을 유지하고 한국어·영어만 지원한다** — 일본어·중국어 사용자가 제품을 읽을 수 없다.
3. **관광 데이터 언어를 고르는 용도로만 서버에 `lang`을 보낸다(채택)** — 판정 입력에는 쓰지 않는다.

## 결정

**선택지 3을 채택하고, 이 부분에서 ADR-0003을 개정한다.**

### 지원 언어와 결정 순서

- 지원 언어는 `ko`, `en`, `ja`, `zh`(간체)다.
- 언어 결정 순서
  1. 사용자가 고른 언어(기기에 저장)
  2. 브라우저 언어: `ko*`→`ko`, `ja*`→`ja`, `zh*`→`zh`, 그 밖→`en`
- 예: `ja-JP`→`ja`, `zh-CN`·`zh-TW`→`zh`, `fr`→`en`, `ko-KR`→`ko`.

### 서버 언어 전송

- 서버에 `lang`을 보낸다. 쓰임은 **관광 데이터 언어 선택** 하나뿐이다.
  - 항상 국문과 무장애 정보를 조회하고, `lang`이 `en`·`ja`·`zh`이면 그 언어 서비스를 더한다. `ko`이면 더하지 않는다.
  - 선택 언어 서비스가 없거나 실패하면 영문으로, 영문도 없으면 국문과 '번역 필요'로 보여준다.
- **판정 결과는 언어와 무관하다.** 같은 입력이면 언어가 달라도 날짜별 상태와 정거장 목록이 같다.
- 언어를 바꾸면 오늘 이후 날짜의 표시만 새 언어로 다시 쓴다. 재판정하지 않고 전후 비교도 만들지 않는다.

### 안전 문구 병기

- 안전 문구(상태 메시지, 사유, 고지, 복귀 안내)는 **선택 언어와 한국어를 함께** 보여준다.
  선택 언어가 `ko`이면 한국어+영어다.
- `ja`·`zh` 안전 문구는 검수 스위치가 켜지기 전까지 **영어+한국어**로 보여준다.
  - 스위치: `NEXT_PUBLIC_SAFEHOUR_SAFETY_COPY_REVIEWED_JA`, `NEXT_PUBLIC_SAFEHOUR_SAFETY_COPY_REVIEWED_ZH`
  - 빌드 시점에 읽는 공개 환경변수이고 기본은 꺼짐이다. 값이 `1`일 때만 켜지며, 바꾸려면 다시 빌드해야 한다.
- 일반 화면 문구는 `ja`·`zh` 번역을 그대로 쓴다.
- 병원 안내문(채널 B)은 번역하지 않는다(기존).

### ADR-0003에서 바뀌는 규칙

| ADR-0003 규칙 | 이 ADR 이후 |
| --- | --- |
| 1. 언어 결정: `sessionStorage` → `navigator.language` → `ko`. `ko*`만 `ko`, 나머지는 `en` | 기기에 저장한 선택 언어 → 브라우저 언어. `ko*`·`ja*`·`zh*`를 각각 인식하고 나머지는 `en` |
| 2. 저장소는 `sessionStorage`만 쓴다 | 탭 단위 저장소 사용을 중단하고 기기에 저장한다(ADR-0009). '이 기기에서 내 정보 지우기'를 해도 언어 설정은 남는다 |
| 3. 언어는 서버로 전송하지 않는다 | 관광 데이터 언어를 고르려고 `lang`을 보낸다. 판정에는 쓰지 않는다 |
| 5. 상태 배너와 즉시 복귀 시트는 두 언어를 함께 보여준다 | 병기 범위를 안전 문구 전체(상태 메시지, 사유, 고지, 복귀 안내)로 넓히고, 위 병기 규칙을 따른다 |
| 남은 것: 3번째 언어 미결정 | 일본어·중국어(간체)로 결정. 안전 문구 검수는 사람 확인 항목으로 남는다 |

이 표에 없는 ADR-0003 규칙은 바꾸지 않는다.

## 대안과 버린 이유

| 대안 | 버린 이유 |
| --- | --- |
| 언어를 보내지 않고 4개 언어를 모두 조회 | 호출량이 늘어난다. 관광공사 호출 한도(경고 800, 차단 1,000)에 부담이 된다 |
| ADR-0003 유지(한국어·영어만) | 일본어·중국어 사용자가 제품을 읽을 수 없고, 해당 언어 관광 데이터도 고를 수 없다 |
| 검수 전 `ja`·`zh` 안전 문구를 그대로 표시 | 안전 문구의 의미가 사람 검수로 확인되지 않았다. 검수 전까지는 영어+한국어로 보여준다 |
| 언어 변경 때 일정을 다시 판정 | 판정은 언어와 무관해야 한다. 표시만 다시 쓰면 결과가 흔들리지 않는다 |

## 영향

- **i18n**: 지원 언어가 4개가 되고, 모든 화면 문구·상태 메시지·사유 문구에 `ja`·`zh` 번역이 필요하다.
  기존 `test/i18n.test.js`의 `ja`·`zh`→`en` 단언은 의도적으로 고친다.
- **관광 데이터**: 일본어·중국어 서비스는 관광공사 활용 신청이 끝나야 쓸 수 있다. 그 전에는 영문 대체가 동작한다
  (`HUMAN_ACTIONS.md` 2번).
- **개인정보**: 서버로 가는 값이 하나 늘어난다(`lang`). 판정 운영 로그에는 언어가 남는다(ADR-0006).
  `/privacy`에 언어 전송을 적는다.
- **rollback**: `lang` 전송을 멈추면 일본어·중국어 관광 데이터를 고를 수 없어 영문 대체로 떨어진다. 판정 결과에는 영향이 없다.

## 검증과 재검토

- 증거: 브라우저 언어 정규화, `ja` 사용자의 안전 문구(스위치 꺼짐: 영어+한국어, 켜짐: 일본어+한국어),
  `ko` 사용자의 한국어+영어, 언어 무관성(4개 언어에서 같은 상태·정거장), 표시만 다시 쓰기를 테스트로 고정한다.
- 재검토 조건
  - 일본어·중국어 안전 문구 검수가 끝나면 검수 스위치를 켠다(`HUMAN_ACTIONS.md` 6번).
  - 언어를 더 늘릴 때는 검수 비용과 관광공사 언어 서비스 유무를 함께 본다.
