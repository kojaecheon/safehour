# ADR-0008: 런타임 AI 일정 소개 문장 (Gemini, 기본 꺼짐)

- 상태: Accepted
- 날짜: 2026-09-18
- 작업 ID: AX-301
- 연결 문서: `docs/platform/AI_USE_CASE_INTRO.md`(AI 사용 문서), `docs/platform/PRODUCT_DEFINITION_V3.md` 7.2절,
  ADR-0006(엔진은 결정적 함수)
- 결정자: 운영자 (대화 결정)

## 맥락

지금까지 SafeHour에는 런타임 AI가 없었다. 판정과 일정 배치는 규칙 엔진이 결정적으로 한다(ADR-0006).

하루 일정을 받은 사용자에게 그날 일정을 짧게 소개하는 문장이 있으면 읽기 쉽다.
다만 AI 문장은 의료·안전·영업 여부를 단정하는 표현을 만들어 낼 수 있고, 입력으로 민감정보가 새어 나갈 수 있다.
기존 정책은 AI를 쓰려면 AI 사용 문서, 위험 평가, 자동 평가, 사람 승인을 거치도록 요구한다.

## 선택지

1. **규칙 엔진만 쓰고 AI는 쓰지 않는다** — 위험은 가장 낮지만 소개 문장이 템플릿뿐이다.
2. **AI가 일정 배치나 추천에 관여한다** — 판정의 결정성과 설명 가능성을 잃는다.
3. **소개 문장에 한해 AI를 쓰고, 기본은 꺼 둔다(채택)** — 판정·배치는 규칙 엔진이 하고, AI는 이미 정해진 일정을 소개만 한다.

## 결정

**선택지 3을 채택한다.** AI는 하루 일정 소개 문장에만 쓰고, 승인 전에는 꺼 둔다.

### 동작 조건과 대체

- 스위치 `SAFEHOUR_AI_INTRO=1`과 키 `GEMINI_API_KEY`가 **모두** 있어야 동작한다. 기본은 꺼짐이다.
- 꺼져 있거나, 실패하거나, 시간이 초과되거나, 검사에서 떨어지면 정해진 템플릿 문장을 쓴다.
  예: "오늘은 {장소1}, {장소2}를 들르는 가벼운 일정이에요".

### 입력 최소화

| 넣는 것 | 넣지 않는 것 |
| --- | --- |
| 언어, 그날 정거장의 공개 장소 이름·유형·시각, 관심사 태그, 이동 강도 | 조건 항목, 병원·시술 정보, 숙소 이름·주소, 날짜, 계정 정보 |

요청 본문에 허용 목록 밖 필드가 있어도 무시하고 외부로 보내지 않는다.

### 호출

- 서버에서만 호출하며, 추가 라이브러리 없이 HTTP로 호출한다.
- Gemini의 빠르고 저렴한 등급(Flash 계열)을 쓴다. 모델 이름은 구현 시점의 공식 문서로 확인하고,
  환경변수 `GEMINI_MODEL`로 바꿀 수 있게 한다.
- 제한시간은 3초다(조정 가능).

### 출력 자동 검사

하나라도 걸리면 템플릿으로 바꾼다.

- 200자 초과(조정 가능)
- 선택 언어의 문자 체계가 아님
- 금지 표현: 안전·안심 단정, 의료·회복·치료·약·수술 언급, 영업 중·열려 있음 단정, 보장·순위·1위 표현, 가격

### 표시와 캐시

- 'AI가 쓴 소개'라고 표시하고, 판정·사유 영역과 시각적으로 분리한다.
- 같은 입력이면 기기에 저장된 문장을 다시 쓴다. AI 문장 캐시는 '이 기기에서 내 정보 지우기'와 출국 후 자동 삭제 대상이다.

### 함께 만드는 것

- AI 사용 문서(`docs/platform/AI_USE_CASE_INTRO.md`): 목적, 위험 등급, 입력 최소화, 검사 규칙, 승인 절차, 켜는 방법
- 평가 세트: 고정 일정 샘플 × 4개 언어
- 평가 스크립트: 키가 있을 때만 수동으로 실행한다. CI와 자동 테스트에서는 실행하지 않는다.

## 대안과 버린 이유

| 대안 | 버린 이유 |
| --- | --- |
| 규칙 엔진만(AI 없음)(추천안) | 운영자가 소개 문장에 한해 AI를 쓰기로 골랐다. 대신 기본 꺼짐과 템플릿 대체로 위험을 묶는다 |
| AI가 배치·추천에 관여 | 같은 입력이면 같은 결과가 나와야 한다는 엔진 원칙(ADR-0006)과 맞지 않는다. AI는 배치에 관여하지 않는다 |
| Claude 사용 | 운영자가 Gemini를 골랐다 |
| 처음부터 켜 두기 | 기존 정책(AI 사용 문서, 위험 평가, 자동 평가, 사람 승인)을 지키려면 승인 전에는 꺼 두어야 한다 |
| 조건·숙소 정보까지 넣어 더 맞춤한 문장 생성 | 민감정보가 외부 AI로 나간다. 공개 장소 정보만 넣는다 |
| 한국어 안내 카드 문구도 AI로 생성 | 카드 문구는 사람이 검수하는 고정 문구다. AI를 쓰지 않는다 |

## 영향

- **서버**: `POST /api/itinerary/intro`가 생긴다. 로그인 세션이 필요하고, 요청 본문 외의 정보를 받지 않는다.
- **의존성**: 새 패키지를 설치하지 않는다. HTTP 호출로 구현한다.
- **개인정보**: 외부로 나가는 값은 공개 장소 정보, 관심사, 강도, 언어뿐이다. `/privacy`에 AI 소개(기본 꺼짐)를 적는다.
- **운영**: 키와 스위치가 없는 지금은 모든 사용자가 템플릿 문장을 본다.
- **rollback**: 스위치를 끄면 템플릿 문장으로 돌아간다. 스위치는 서버 환경변수라 코드를 고치지 않고 바꿀 수 있다.

## 검증과 재검토

- 증거: 스위치 꺼짐·키 없음이면 `source=TEMPLATE`, 금지 표현이 든 출력은 `TEMPLATE`으로 바뀜, 시간 초과 대체,
  허용 목록 밖 필드(조건·병원·숙소·날짜)가 외부로 전달되지 않음을 가짜 응답으로 테스트한다.
- 운영 승인 절차와 켜는 방법은 `AI_USE_CASE_INTRO.md`를 따른다(`HUMAN_ACTIONS.md` 3번).
- 재검토 조건
  - 평가 스크립트 결과는 사용 승인 판단의 근거로 쓴다.
  - 모델이나 등급을 바꾸면 평가 세트로 다시 평가한다.
