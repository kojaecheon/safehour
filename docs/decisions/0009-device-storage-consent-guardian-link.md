# ADR-0009: 기기 영구 저장, 계정 이름공간, 민감정보 동의, 출국 후 삭제, 보호자 PIN 링크

- 상태: Accepted
- 날짜: 2026-09-18
- 작업 ID: AX-301
- 연결 문서: ADR-0004(소셜 로그인과 서버 상태 경계), ADR-0003(개정은 ADR-0007), ADR-0005(본인 체크),
  `docs/platform/IA_AND_FLOWS.md` 2.5절·2.7절·5.3절, `docs/platform/ITINERARY_RULES.md` 1장
- 결정자: 운영자 (대화 결정)

## 맥락

v2는 탭 단위 저장소(`sessionStorage`)만 썼고, 서버는 계정·세션·조건·판정 결과를 저장하지 않았다(ADR-0004).

체류 전체 일정(ADR-0006)은 이 구조와 맞지 않는다.

- 확정 일정, 체류, 조건 기간, 편집 기록을 입국부터 출국까지 들고 있어야 한다. 탭을 닫으면 사라지는 저장소로는 안 된다.
- 본인 체크 값은 민감정보다(ADR-0005). 입력 전 동의와 철회 방법이 필요하다.
- 보호자는 1명이지만 자기 기기를 쓸 수 있다. 서버 없이 보호자에게 일정을 넘겨야 한다.
- 로그인은 "같은 계정이 다시 왔다"만 보장한다(ADR-0004). 저장 공간을 계정별로 나누는 기준이 필요하다.

## 선택지

1. **서버 계정별 저장** — 기기 간 동기화와 보호자 실시간 공유가 가능하지만, 계정 DB가 생기고 서버 무저장 원칙이 깨진다.
2. **기기 영구 저장(계정 이름공간) + PIN 잠금 링크 사본(채택)** — 서버는 여전히 아무것도 저장하지 않는다.
   대신 보호자 공유는 자동 갱신되지 않는 사본이고, 알림은 앱이 열려 있을 때만 확실하다.

## 결정

**선택지 2를 채택한다.** 운영자가 추천안(서버 계정별 저장) 대신 골랐다. 이 선택의 한계는 화면에 숨기지 않는다.

### 로그인

- **모든 기능은 로그인 후에 쓴다.** 구글·카카오 로그인, 세션 12시간, 데모 로그인 스위치는 기존대로 유지한다.
- 예외로, 로그인 만료나 오프라인에서도 다음은 **보기 전용**으로 보여준다:
  긴급 연락, 한국어 카드, 오늘·내일 일정과 복귀 마감(이 기기에 마지막으로 로그인한 계정의 사본),
  보호자 사본의 안전 정보, 개인정보 고지.
  - 이때는 '보기 전용 — 로그인이 필요합니다'를 표시하고 생성·편집·연동·공유를 막는다.
- 홈 화면에 설치할 수 있게 하고(매니페스트, 서비스 워커), 앱 셸과 보기 전용 화면을 오프라인에서 연다.
  **API 응답은 서비스 워커 캐시에 넣지 않는다.**

### 기기 저장과 계정 이름공간

- 브라우저 영구 저장소에 계정별 이름공간으로 저장한다.
- 이름공간 키는 서버가 세션에서 주는 **불투명 계정 키**다. 원래 계정 식별자에서 되돌릴 수 없는 값이며,
  원래 계정 식별자는 저장하지 않는다.
- 탭 단위 저장소(`sessionStorage`) 사용을 중단한다. 기존 키는 옮기지 않고 삭제 대상에 넣는다.
  - 유일한 예외: 보호자 링크를 로그인 전에 열었을 때, 로그인 왕복 동안 링크의 암호문만 탭 저장소에 잠시 둔다.
    가져오기가 끝나거나 1시간이 지나면 지운다.
- 서버는 계정·체류·조건·일정을 저장하지 않는다(기존). 판정 요청에 실린 조건 값은 계산 뒤 버리고 로그에도 남기지 않는다.

### 민감정보 동의

- **첫 본인 체크 입력 전, 또는 병원 연동 전에 반드시 받는다.**
- 동의 문구 버전과 동의 시각을 기기에 저장한다. 화면에는 '동의 문구 법무 검토 전' 배지를 표시한다.
- 거부하면 수술 후 경계일 전 자유일 일정만 쓸 수 있다.
- 설정에서 철회하면 본인 체크 기간과 연동 지침 사본을 지우고, 해당 날짜를 `NEEDS_INPUT`(`SENSITIVE_CONSENT_REQUIRED`)으로 바꾼 뒤 재계획한다.

### 삭제

- **출국 후 삭제**: 출국일로부터 7일이 지난 뒤 앱을 처음 여는 시점에 그 계정의 체류 데이터를 전부 지운다
  (체류, 숙소, 병원, 조건, 일정, 동의 기록, 카드, 알림 예약, AI 문장 캐시).
  - 화면 문구는 "출국 7일이 지난 뒤 앱을 처음 열 때 삭제됩니다"로 쓴다.
- **이 기기에서 내 정보 지우기**: 모든 계정 이름공간, 보호자 사본, 알림 예약, AI 문장 캐시, 언어 외 설정을 지우고 로그아웃한다(기존 규칙).

### 보호자 PIN 링크

- 같은 기기에서는 하루 일정 화면의 환자/보호자 탭으로 본다.
- 링크를 만들 때마다 **공유 동의**를 받고, 담기는 항목을 동의 화면에 보여준다.

| 담는 것 | 담지 않는 것 |
| --- | --- |
| 만든 시각, 만료 시각(출국일 23:59), 언어 | 조건 항목 세부(식이·복약·보행·자외선·열·물) |
| 날짜별 보호자 일정 | 병원 이름·주소·전화, 병원 안내문, 병원 일정 |
| 날짜별 환자 복귀 마감과 복귀 장소의 이름·주소 | 환자 복귀 장소가 병원이면 이름·주소 대신 일반 라벨 '병원'만 |
| 날짜별 동행 필요 여부, 보호자 단독 외출 가능 여부 | 보호자 외출의 마감 이유(마감 시각만 담는다) |
| 긴급 번호(119, 1330) | |

- 환자가 정한 **6자리 PIN**으로 내용을 암호화한다.
  - 암호문은 링크의 `#` 뒤에만 담아 서버로 전송되지 않게 한다. 서버는 아무것도 저장하지 않는다.
  - 표준 브라우저 암호 기능으로 구현하고, 새 라이브러리는 쓰지 않는다.
  - PIN은 링크와 따로 알려주라고 안내한다.
  - 완벽한 보호가 아니라 **우연한 열람을 막는 수준**이라는 점을 화면에 밝힌다.
- 보호자 기기에서는 로그인 → PIN 입력 → 복호화 → 기기 저장 순으로 연다.
  - PIN이 5회 연속 틀리면 그 기기에서 그 링크를 1시간 잠근다.
  - 이미 가져온 사본의 안전 정보는 로그인 만료나 오프라인에서도 보여준다.
  - 만료 시각이 지나면 표시하지 않고 삭제한다.
- 사본은 자동으로 갱신되지 않는다. 보호자 화면 상단에 '○월 ○일 ○시 기준'을 표시하고,
  환자 일정이 바뀌면 환자 화면에 '보호자 링크 다시 보내기'를 안내한다.

## 대안과 버린 이유

| 대안 | 버린 이유 |
| --- | --- |
| 서버 계정별 저장(추천안) | 운영자가 기기 저장만 하기로 골랐다. 서버에 계정·체류·조건·일정 저장소를 만들지 않는다는 원칙을 지킨다 |
| 병원 연동 때만 로그인(추천안) | 운영자가 모든 사용에 로그인을 골랐다. 대신 안전 정보(긴급, 카드, 오늘 일정, 복귀 마감)는 로그인 만료·오프라인에서도 보기 전용으로 보여준다 |
| 탭 단위 저장 유지 | 탭을 닫으면 체류 전체 확정 일정과 조건이 사라진다 |
| 보호자 실시간 동기화·환자→보호자 호출 메시지 | 서버가 없어 동기화할 수 없다. 사본 방식을 쓰고 '○시 기준'과 '다시 보내기'로 한계를 드러낸다 |
| 보호자 사본에 병원 정보를 담음 | 운영자가 고른 'PIN 잠금 + 동의' 위에서 최소화를 더했다. 보호자 외출은 환자 숙소로 돌아오므로 병원 주소가 없어도 보호자의 복귀 기능은 유지된다 |
| 문구를 "자동으로 삭제됩니다"로 씀 | 앱을 열지 않으면 지워지지 않으므로 사실과 달라진다. 실제 동작대로 쓴다 |
| 동의를 입력 뒤에 받음 | 본인 체크 값은 민감정보다. 첫 입력 전, 병원 연동 전에 받는다 |
| 애플·라인·위챗 로그인 추가 | 이번 차례에는 구글·카카오를 유지한다. 중국 본토에서 출국 전에는 구글을 쓰기 어렵다는 한계를 알고 받아들였다 |

## 영향

- **ADR-0004 확장**: 세션 응답에 불투명 계정 키(`accountKey`)를 더한다. 서버 비밀값으로 계정 식별자에서 유도하며,
  원래 식별자는 응답에 싣지 않는다. 계정·세션 테이블이 없다는 ADR-0004 원칙은 그대로다.
- **ADR-0003·ADR-0007**: 언어 설정도 기기에 저장한다. '내 정보 지우기' 뒤에도 언어는 남는다.
- **개인정보**: 기기에 민감정보(본인 체크 값)가 남는다. 동의, 철회, 내 정보 지우기, 출국 후 삭제로 관리한다.
  `/privacy`에 기기 저장, 출국 7일 후 첫 실행 삭제, 보호자 링크를 적는다. 법무 검토가 필요하다(`HUMAN_ACTIONS.md` 5번).
- **알림**: 서버 푸시가 없으므로 알림은 앱이 열려 있거나 실행 중일 때만 확실하다(ADR-0010).
- **호환**: 저장 모델에 `schemaVersion`을 둔다. 서버 라우트는 무상태 계산기로 두어, 나중에 저장 계층을 앞에 붙일 수 있게 한다.
- **rollback**: 탭 저장소로 되돌리면 탭을 닫을 때마다 확정 일정이 사라져 체류 전체 일정(ADR-0006)이 동작하지 않는다.

## 검증과 재검토

- 증거: 계정 키에서 원래 식별자를 복원할 수 없음, '내 정보 지우기'가 모든 이름공간과 보호자 사본을 비우고 로그아웃함,
  출국일+7일 뒤 첫 실행 때 체류 데이터 삭제, 보호자 스냅샷에 금지 필드 없음, 올바른 PIN으로만 복원,
  5회 오류 후 1시간 잠금, 만료 후 삭제, 암호문이 `#` 뒤에만 있고 서버 요청에 실리지 않음을 테스트로 고정한다.
- 재검토 조건
  - 서버 계정 저장과 기기 간 동기화, 보호자 실시간 동기화를 도입하면 이 결정을 다시 연다.
  - 법무 검토에서 동의 문구나 보호자 공유 방식이 바뀌면 반영한다.
