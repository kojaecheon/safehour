# ADR-0010: 지도 목적지 전용 링크, 긴급 연락, 기기 알림

- 상태: Accepted
- 날짜: 2026-09-18
- 작업 ID: AX-301
- 연결 문서: `docs/platform/IA_AND_FLOWS.md` 1.2절·5.3절, ADR-0009(서버 무저장·보기 전용), ADR-0001(위치정보 검토 조건)
- 결정자: 운영자 (대화 결정)

## 맥락

환자와 보호자는 일정을 실제로 따라가야 한다. 장소까지 가는 방법, 급할 때 연락할 곳, 복귀 마감을 놓치지 않게 하는 알림이 필요하다.

지켜야 할 제약이 있다.

- 현재 위치(GPS)를 수집하지 않는다. 기준점은 사용자가 고른 숙소·병원의 고정 좌표뿐이다.
- 지도·경로 실연동은 위치정보 사전검토가 끝나야 들일 수 있다(ADR-0001 재검토 조건). 그 검토는 아직 대기 중이다.
- 서버는 아무것도 저장하지 않는다(ADR-0009). 서버 푸시 알림을 보낼 구독 정보를 둘 곳이 없다.
- 알림은 잠금 화면에 보일 수 있다.

## 선택지

1. **지도 내장 화면·경로 API** — 앱 안에서 길을 안내하지만, 출발지(숙소) 좌표가 지도 사업자로 가고 위치정보 검토가 먼저 필요하다.
2. **출발지와 목적지를 모두 담은 외부 지도 링크** — 구현은 쉽지만, 숙소 좌표가 지도 사업자로 간다.
3. **목적지만 담은 외부 지도 링크(채택)** — 길찾기의 출발지는 지도 앱이 스스로 정한다. SafeHour는 숙소·병원 좌표를 넘기지 않는다.

## 결정

**선택지 3을 채택한다.** 함께, 긴급 연락은 어떤 상태에서도 열리게 하고, 알림은 서버 없이 기기에서만 보낸다.

### 지도 길찾기

- 장소 카드와 장소 상세에 '구글 지도로 열기', '카카오맵으로 열기'를 둔다.
- 링크에는 **목적지 장소의 이름과 좌표만** 넣고, 출발지 매개변수는 넣지 않는다.
- 숙소·병원 좌표는 어떤 지도 링크에도 넣지 않는다. 복귀 카드는 주소 텍스트만 보여준다.
- 매일 확인 전에는 길찾기 동작을 비활성화한다(`IA_AND_FLOWS.md` 4장).

### 긴급 연락

- `/emergency`에 전화 걸기 링크를 둔다: 119, 1330(관광통역안내), 등록된 병원 전화(병원 이름과 함께).
- **긴급 연락 버튼은 모든 화면에 고정한다.** 로그인 전, 로그인 만료, 오프라인 상태도 포함한다.
- 추천 중단 스위치가 켜져도 긴급 연락은 계속 동작한다.
- 1330의 휴대전화 발신 형식은 공식 안내로 확인한 값을 쓴다(사람 확인 항목).
  확인 전에는 공식 안내 페이지를 근거로 구현하고, 근거를 코드 주석과 문서에 남긴다.

### 기기 알림

- 알림 권한은 사용자가 설정에서 켤 때만 요청한다.
- 알림 대상과 시점(조정 가능)

| 대상 | 시점 |
| --- | --- |
| 외출 복귀 마감 | 60분 전, 30분 전 |
| '숙소에서 복용' 복약 | 10분 전 |
| '숙소 밖 복용' 복약 | 그 시각 |
| 병원 일정 | 숙소에서 출발해야 하는 시각(일정 시작 − 이동 − 10분)의 15분 전. 직전 외출이 병원에서 끝나면 복귀 마감 알림이 대신한다 |

- 서버 없이 동작한다. 앱이 열려 있거나 설치·실행 중일 때 기기 알림과 앱 안 배너로 알린다.
- 설정 화면에 "앱이 완전히 닫혀 있으면 알림을 받지 못할 수 있습니다"를 표시한다.
- 알림 문구에는 조건 항목, 병원 이름, 복약 정보를 넣지 않는다(잠금 화면 노출 대비).
  예: "18:00까지 숙소로 돌아갈 시간이에요".

### 관련 결정: 위치 입력

- 숙소·병원 위치는 **도로명주소 검색**으로 입력한다. 검색은 사용자가 입력한 검색어로만 하고, 병원 목록·검색 추천·순위를 보여주지 않는다.
- 행정안전부 좌표 API가 주는 UTM-K(GRS80) 좌표를 서버에서 WGS84 위경도로 바꿔 돌려준다. 키가 없으면 주소 검색은 동작하지 않는다(`HUMAN_ACTIONS.md` 1번).

## 대안과 버린 이유

| 대안 | 버린 이유 |
| --- | --- |
| 지도 내장 화면·경로 API | 이번 범위에서 제외했다. 숙소·병원 기준점만 쓰며, 위치정보 검토가 끝나야 검토할 수 있다 |
| 출발지(숙소)를 포함한 지도 링크 | 숙소 좌표가 지도 사업자로 간다. 위치정보 검토가 대기 중이므로 목적지만 넘긴다 |
| 현재 위치로 출발지 설정 | 현재 위치를 수집하지 않는다는 불변조건에 어긋난다 |
| 서버 푸시 알림 | 서버에 아무것도 저장하지 않기로 했다(ADR-0009). 대신 앱이 닫혀 있으면 알림을 못 받을 수 있다는 한계를 화면에 밝힌다 |
| 알림 문구에 병원·복약 정보를 넣어 구체적으로 안내 | 잠금 화면에 건강 정황이 드러난다. 조건 항목, 병원 이름, 복약 정보는 넣지 않는다 |
| 긴급 연락도 로그인 뒤에만 제공 | 모든 사용에 로그인을 요구하는 대신, 긴급 연락 같은 안전 정보는 로그인 만료·오프라인에서도 보여주기로 했다(ADR-0009) |
| 병원 목록에서 골라 위치 입력 | 병원 알선 금지 원칙에 어긋난다. 병원 목록을 보여주지 않으려고 주소 검색을 쓴다 |

## 영향

- **화면**: 장소 카드·상세에 지도 링크 2개, 모든 화면에 긴급 버튼, 설정에 알림 켜기와 한계 안내가 생긴다.
- **개인정보**: 지도 사업자에게는 관광공사 공개 장소의 이름·좌표만 간다. `/privacy`에 '지도 링크는 목적지만'을 적는다.
  위치정보 관점 검토가 필요하다(`HUMAN_ACTIONS.md` 8번).
- **오프라인**: 긴급 연락과 한국어 카드는 서비스 워커로 오프라인에서도 연다(ADR-0009).
- **rollback**: 지도 링크를 없애도 일정 기능에는 영향이 없다. 이동 카드(정거장의 한국어 이름·주소)로 계속 안내할 수 있다.

## 검증과 재검토

- 증거: 지도 링크에 목적지 좌표·이름만 있고 숙소·병원 좌표와 출발지 매개변수가 없음, 알림 문구에 조건·병원·복약 정보가 없음,
  로그인 만료 상태에서 `/emergency`·`/cards`가 열림, 모든 화면에서 현재 위치 권한 요청이 0건임을 테스트로 고정한다.
- 재검토 조건
  - 위치정보 검토가 끝나면 경로 API·지도 화면·숙소 출발 경로를 다시 검토한다.
  - 1330 발신 형식을 확인하면 구현과 문서를 갱신한다(`HUMAN_ACTIONS.md` 7번).
  - 서버 푸시를 도입하면 알림 방식과 한계 안내를 다시 정한다.
