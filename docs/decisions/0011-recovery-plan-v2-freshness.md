# ADR-0011: 병원 지침 계약 v2와 최신성 규칙 변경 (24시간 → 유효기간·매일 확인)

- 상태: Accepted
- 날짜: 2026-09-18
- 작업 ID: AX-301
- 연결 문서: `docs/PRODUCT_DEFINITION.md`(v2) 2절·4절, `docs/PRD.md` ⑤절(유효기간과 24시간 한도의 충돌),
  `docs/platform/ITINERARY_RULES.md` 4.3절·5–6장, ADR-0005(조건 기간), ADR-0006(전체 확정), ADR-0009(동의·삭제)
- 결정자: 운영자 (대화 결정)

## 맥락

v1 지침 계약은 조건 묶음 하나를 담았고, 판정 게이트는 조건 발행 시각에서 **24시간**이 지나면
`STALE_HOSPITAL_CONDITION`으로 막았다.

이 구조는 두 가지 이유로 새 제품과 맞지 않는다.

- **조건이 날짜마다 다르다.** 수술 전 금주·금식과 수술 후 제한처럼 기간에 따라 조건이 바뀐다.
  조건 묶음 하나로는 체류 전체를 표현할 수 없다. 본인 체크와 같은 '조건 기간' 모델(ADR-0005)이 필요하다.
- **24시간 한도는 전체 확정과 함께 쓸 수 없다.** 체류 전체 일정을 미리 확정하는데(ADR-0006),
  24시간 한도를 그대로 두면 받은 지 하루가 지난 지침은 모두 최신성 미달이 된다.
  이미 `docs/PRD.md` ⑤절이 "유효기간 안인데 24시간 한도 때문에 이유 없이 막힌다"는 결함을 기록해 두었다.

그리고 실제 연동 병원은 0곳이다. 지금 오가는 지침은 데모 지침뿐이다.

## 선택지

1. **v1을 유지하고 24시간 한도도 유지한다** — 체류 전체 일정과 맞지 않는다.
2. **v1·v2를 함께 받는다** — 호환은 되지만, 받을 실제 v1 발행처가 없는데 검증 경로만 두 벌이 된다.
3. **v2로 바꾸고 v1은 받지 않으며, 최신성은 유효기간·철회 여부와 매일 확인으로 판정한다(채택)**

## 결정

**선택지 3을 채택한다.**

### 지침 계약 v2

- 지침은 **기간 목록**을 담는다. 각 기간은 시작일·종료일과 조건 항목(값 있음 또는 아니오만)을 가진다.
  그 밖에 계획 id, 버전(1 이상), 발행·수정 시각, 만료 시각, 철회 여부, 발행자, 병원(이름·주소·좌표·전화),
  병원 일정(선택), 안내문(채널 B)을 담는다.
- **v1은 더 이상 받지 않는다.** 실제 연동 병원이 없고 데모 지침만 있기 때문이다.
- 형식이 어긋나면 지침 전체를 거부한다(기존). 기간의 날짜가 역순이어도 지침 전체를 거부한다.
- 게이트웨이 허용 목록 규칙(목록 밖 필드 차단)을 v2 필드에 맞춰 유지한다.
- 안내문(채널 B)의 표시 규칙과 중요 안내 확인 게이트는 그대로 둔다. 안내문은 번역·요약·편집하지 않고 판정에 쓰지 않는다.
- 데모 지침 세 개를 v2로 옮긴다.

| 코드 | 내용 |
| --- | --- |
| `DEMO-A` | 외출 허용 기간을 포함한 정상 지침 |
| `DEMO-B` | 외출 제한 기간을 포함 |
| `DEMO-C` | 이미 만료된 지침 |

### 연결과 변환

- 코드 연결은 기존 흐름(로그인 + 코드)을 유지한다. '병원 연동 데모' 배지를 늘 표시한다.
- 연결한 병원 하나는 체류의 병원 목록과 이어진다. 사용자가 기존 병원 중 하나를 고르거나 새 병원으로 추가한다.
- 지침의 각 기간은 `HOSPITAL` 조건 기간이 되어 날짜별 합성에 참여한다(ADR-0005).
  - **기간을 잘라내지 않는다.** 각 기간에 지침의 만료 시각·철회 여부를 함께 저장하고, 적용 여부는 날짜마다 판정한다.
    기간이 만료 시각을 넘어도 저장하되, 넘는 날짜에는 적용하지 않는다.
  - v2 원문의 복귀 장소가 병원이면 병원 id가 없고 발행 병원을 뜻한다. 변환할 때 연결한 병원 id로 채운다.
    연결 병원이 정해지기 전에는 변환하지 않는다.
- 지침의 병원 일정은 연결한 병원의 일정으로 더한다. 같은 날짜·시각·유형의 일정이 이미 있으면 더하지 않는다.
- 연결하면 지침 사본(연결 코드, 받은 지침 전체, 받은 시각, 안내문별 확인 여부)을 기기에 저장한다.
  - 안내문 확인 기록은 `안내문 id@수정 시각` 키로 남긴다. 안내문 내용이 바뀌어 수정 시각이 달라지면 확인이 풀린다.
  - 동의 철회와 '이 기기에서 내 정보 지우기' 때 사본과 코드를 지운다(ADR-0009).
- `/api/plan/link`도 로그인이 없으면 401 `{ ok: false, errorCode: "SAFEHOUR_AUTH_REQUIRED", message }`를 돌려준다.
  기존 `code: 'UNAUTHENTICATED'` 형태는 이 형태로 바꾼다.

### 최신성 규칙

| 출처 | 이전 | 이후 |
| --- | --- | --- |
| 병원 발행 | 발행 후 24시간 | **유효기간 안이고 철회되지 않음.** 24시간 한도는 병원 기간에 적용하지 않는다 |
| 본인 체크 | (없었음) | **매일 확인**이 최신성을 대신한다(`ITINERARY_RULES.md` 6장) |

- 병원 기간은 철회되지 않았고 만료 시각이 그날 **활동 종료 시각보다 늦을 때만** 그날을 덮는다.
  하루 도중에 만료되는 지침은 그날을 덮지 않는 것으로 본다(보수적 처리).
- 앱을 열 때 저장된 연결 코드로 지침을 다시 받아 버전 변경, 철회, 만료를 확인한다.
  - 버전이 바뀌면 사본을 갱신하고 해당 날짜를 재계획한다.
  - 확인하지 않은 중요 안내가 있으면 오늘을 `STANDBY`(`PLAN_UNCONFIRMED_UPDATE`)로 덧씌운다.
  - 외출 중 철회·만료면 오늘 남은 일정을 비우고 즉시 복귀 시트를 띄운다.
- 병원 기간만 덮는 날은 매일 확인을 하지 않는다.
- `STALE_HOSPITAL_CONDITION`은 일정 엔진에서 쓰지 않는다.

### 만료 후 날짜

- 경계일 이후 날짜 중 만료된 병원 기간만 덮고 다른 유효 기간이 없는 날짜는
  `NEEDS_INPUT`(`HOSPITAL_PLAN_EXPIRED_INPUT_REQUIRED`)이다.
  "병원에서 새 지침을 받거나 본인 체크로 입력하세요"를 안내한다.
- 병원 값을 본인 체크로 자동으로 옮기지 않는다.
- 경계일 전 날짜라면 다른 기간이 없을 때 `FREE`다.
- 이미 만료된 `DEMO-C`를 연결해도 기간은 저장되고 위 규칙이 그대로 적용된다.

### 환자 호출

- 지침 계약에는 환자 호출 필드가 없다. 이번 차례에는 데모 사건(`PATIENT_RECALL`)으로만 다룬다(ADR-0006).

## 대안과 버린 이유

| 대안 | 버린 이유 |
| --- | --- |
| v1 계속 수용(v1·v2 병행) | 실제 연동 병원이 없고 데모 지침만 있다. 받을 v1 발행처가 없는데 검증 경로만 늘어난다 |
| 병원 기간에도 24시간 최신성 한도 유지 | 체류 전체를 미리 확정하는 방식(ADR-0006)과 함께 쓸 수 없다. 유효기간 안의 지침이 이유 없이 막히는 기존 결함(`docs/PRD.md` ⑤절)도 그대로 남는다 |
| 만료 시각에 맞춰 기간을 잘라 저장 | 적용 여부를 날짜마다 한곳(날짜별 합성 규칙)에서 판정하기로 했다. 기간은 받은 그대로 저장한다 |
| 하루 도중 만료되는 지침이 만료 전 시간은 덮게 함 | 보수적으로 처리한다. 그날을 덮지 않는 것으로 본다 |
| 지침에 환자 호출 필드 추가 | 기존 지침 계약에 호출 필드가 없었고, 서버가 없어 실시간으로 전달할 수도 없다. 데모 사건으로만 다룬다 |
| 안내문 확인 기록을 안내문 id만으로 관리 | 같은 id의 안내문 내용이 바뀌어도 확인이 풀리지 않는다. 수정 시각을 키에 넣는다 |

## 영향

- **지침·게이트웨이**: 검증을 v2로 바꾸고 v1을 거부한다. 허용 목록을 v2 필드로 갱신한다. 데모 지침 A/B/C를 v2로 옮긴다.
  기존 `test/recovery.test.js`를 v2 기준으로 고친다.
- **엔진**: 병원 기간이 날짜별 합성에 참여한다. 게이트의 24시간 최신성 검사는 일정 엔진 경로에서 쓰지 않는다.
- **화면**: `/link`가 병원 선택(기존 병원 또는 새 병원)과 일정 합치기를 거친다. `/guide`는 채널 B 규칙을 유지한다.
- **API**: `/api/plan/link`가 v2 지침을 돌려주고, 미로그인 오류 형태가 `errorCode` 키로 바뀐다.
- **호환**: 지침은 어댑터를 거쳐 들어오게 해, 나중에 병원 전용 어댑터나 FHIR 매핑을 붙일 수 있게 한다.
- **rollback**: v1 수용을 되살리려면 v1 검증과 데모 지침을 복원해야 한다. 24시간 한도를 되살리면 체류 전체 확정과 충돌한다.

## 검증과 재검토

- 증거: v1 지침 거부, v2 허용 목록 밖 필드 제거, 역순 기간 거부, 기간 보존(잘라내지 않음),
  만료 시각과 활동 종료 비교에 따른 날짜 적용, 경계일 전후 만료 사유, 병원 복귀 기간의 병원 id 채움,
  안내문 수정 시각 변경 시 확인 해제와 `PLAN_UNCONFIRMED_UPDATE` 덧씌움, 재확인 시 버전 변경·철회·만료 감지를 테스트로 고정한다.
- 재검토 조건
  - 실제 연동 병원이 생기면 병원 전용 어댑터, 지침 서명·위조 검증, 병원 측 감사 기록을 다시 검토한다.
