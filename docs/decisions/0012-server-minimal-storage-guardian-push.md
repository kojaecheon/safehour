# ADR-0012: 서버 최소 저장과 보호자 푸시, '돌아왔어요' 확인

- 상태: Accepted
- 날짜: 2026-11-14
- 작업 ID: 갈래 2 (복귀 마감 작업의 뒤 갈래, `docs/tracking/status.md` 남은 것 2번)
- 연결 문서: `docs/superpowers/specs/2026-11-09-server-push-design.md`(설계서, 8절 질문 25개와 답),
  `docs/superpowers/specs/2026-11-06-overdue-return-design.md`(갈래 1), ADR-0004(서버 상태 경계), ADR-0009(기기 저장·보호자 링크),
  ADR-0010(기기 알림), `CLAUDE.md` 절대 넘지 않는 선 4
- 결정자: 운영자 (대화 결정, 2026-11-13~14. 질문 1~22는 하나씩 답했고, 23~25는 "추천 방향대로 진행" 지시로 정했다)

## 맥락

서버 없이 할 수 있는 만큼은 갈래 1에서 했다. 남은 빈틈 둘은 서버에 무언가를 두지 않으면 닫히지 않는다.

- **보호자 알림은 앱이 열려 있을 때만 확실하다.** 웹은 앱이 닫힌 동안 정해진 시각에 기기 알림을 스스로 낼 수 없다.
- **앱은 환자가 돌아왔는지 모른다.** 환자 기기에서 누른 확인을 보호자 기기로 옮길 통로가 없다. 위치를 쓰지 않으므로(선 2)
  자동으로 알 방법도 없다.

지금까지 서버에는 계정·체류·조건·일정 저장소가 없었고, `CLAUDE.md` 선 4는 "저장소를 두기 전에 반드시 운영자에게 보고한다"고
정한다. 설계서가 그 보고였고, 운영자가 8절의 질문에 답했다.

## 선택지

1. **서버 저장을 하지 않는다**: 갈래 1 + '돌아왔어요' 메신저 공유 + 보호자 달력 파일. 서버 저장 0이지만 "확인이 없으면 알린다"는
   핵심 동작을 만들 수 없다.
2. **상태 없는 서버 + 외부 지연 메시지만**: 자체 저장소 없이 예약 업체에 구독 주소와 시각을 맡긴다. 저장소를 업체로 옮긴 것일 뿐이고
   확인 취소를 할 수 없다. 선 4를 피하는 방법이 아니다.
3. **옵트인 최소 저장(채택)**: 환자가 '서버 알림'을 켠 경우에만 복귀 마감 시각, '돌아왔어요' 확인 여부, 알림 주소, 횟수 제한 카운터를
   서버에 두고, 마감 + 유예에 확인이 없으면 보호자에게 푸시를 보낸다.

## 결정

선택지 3으로 간다. 세부는 아래와 같다(번호는 설계서 8절의 질문 번호).

**저장 범위와 기한**

- 서버가 갖는 것은 네 레코드뿐이다: 지켜보기(해시된 키, 계정 표시 해시, 쓰기 토큰 해시, 만료 시각), 알림 주소(암호화 저장),
  날짜 기록(그날 마감 `HH:MM` 목록과 확인·예약·발송 표시), 횟수 제한 카운터. (1)
- 조건 값, 조건 기간, 판정 결과, 병원·숙소 정보, 좌표, 장소 이름, 외출 출발 시각, 계정 식별자, 토큰 원문, PIN, IP, 기기 정보는
  저장하지 않는다.
- 마감은 남은 체류 기간 전체를 올리고, 예약은 오늘과 내일 것만 건다. (5)
- 보관은 출국일 + 7일까지이고, 서버는 받은 만료 시각을 오늘 + 53일로 깎는다. 날짜 기록은 그 날짜 + 1일까지다. (10)
- 계정 표시 해시(`ownerHash`)를 둔다. 기기를 잃은 환자가 새 기기에서 '서버에 남은 내 정보 지우기'를 할 수 있다. 한 계정의 체류끼리
  서버 안에서 이어지는 것은 감수한다. (17)
- 민감정보 동의를 철회하면 지켜보기도 지운다. (25)
- 기기 백업·복원(단계 B)은 이번에 하지 않는다. 조건 값의 암호문 보관은 선 4에 대한 별도 판단이다. (12)

**기술**

- 저장소는 Upstash Redis를 REST로 부른다(새 패키지 없음). 보관 기한은 키의 TTL로 저장소가 지킨다. (2)
- 예약은 혼합이다: 하루 1회 Vercel Cron이 다음 날 마감을 걸고, 같은 날 마감은 올릴 때 QStash에 건다. `armed` 표시, 중복 제거 id,
  `SADD` 권리로 마감마다 한 번만 보낸다. (3)
- 웹 푸시 서명과 암호화는 `node:crypto`로 직접 구현한다(`web-push` 패키지를 들이지 않는다). RFC 8291 부록 A 시험 벡터로 고정한다.
  두 번 시도해도 벡터가 맞지 않으면 멈추고 다시 묻는다. (4)
- 리전은 서울이 있으면 서울, 없으면 국외 이전 고지를 처리방침·동의 문구에 넣는 조건으로 도쿄를 허용한다. (18)
- 비밀값은 Vercel 환경변수에 두고(운영·미리보기 다른 값) 사본은 운영자 비밀번호 관리자 한 곳에 둔다. 정기 교체는 하지 않고 유출이
  의심될 때만 바꾼다. 입력은 운영자가 직접 한다. (19)
- 업체 비용에 월 상한을 둔다. 금액은 요금표 확인 뒤 운영자가 정한다. (20)

**동작**

- 서버 푸시 유예는 마감 + 10분이고 `src/stay/defaults.js`에 사람 검토 전 임시값으로 둔다. (6)
- '돌아왔어요'는 시트 두 곳과 오늘 화면 외출 카드에 둔다. 외출이 시작된 뒤에만 누를 수 있고 되돌릴 수 있다. (7)
- 보기 전용(세션 만료)에서도 '돌아왔어요'는 누를 수 있다. 세션이 아니라 환자 기기에만 있는 쓰기 토큰으로 권한을 확인한다.
  보기 전용 규칙의 예외 하나로 문서에 적는다. (8)
- '복귀 확인' 푸시는 마감 지남 푸시를 이미 보낸 마감에만 보낸다. (9)
- 보호자 구독은 지켜보기당 1개이고 새 구독이 덮어쓴다. 바뀔 때 이전 기기에 알린다. (14)
- 갈래 1의 보호자 기기 알림은 그대로 둔다. 서버가 꺼지거나 실패할 때의 바탕이다. (15)
- 보호자 스냅샷에 `watchId` 필드를 더한다(링크 약 30자 증가). (11)
- 환자 기기도 푸시를 구독해 마감 시각에 "돌아왔으면 눌러 주세요"를 받는다. 단계 A의 끝에 붙인다. (21)
- 보호자가 '오늘 함께 있음'을 켜면 그날 서버 푸시를 보내지 않는다. 날짜가 바뀌면 풀린다. (24)
- 아이폰 보호자 구독에 로그인을 요구할지는 실기기 확인 뒤 정한다. 로그인 왕복이 홈 화면 앱으로 돌아오지 않으면 `watchId`만으로
  허용하고 횟수 제한을 더 엄격히 한다. (22)

**운영과 고지**

- 법무 검토 전에는 미리보기 배포에서만 켜고 운영 스위치는 끈다. (13)
- 화면의 "서버에 저장하지 않습니다" 약속 문구는 운영 스위치를 켜는 **같은 배포에서** 모든 사용자에게 "기본은 이 기기에만 저장합니다.
  '서버 알림'을 켜면 복귀 마감 시각과 확인 여부만 서버에 보관합니다"로 바꾼다. 켜기 전에는 지금 문구가 사실이므로 바꾸지 않는다. (16)
- 사고 대응 담당은 운영자 1인이다. 유출이 의심되면 차단 스위치 켜기, 비밀 교체, 저장소 비우기, 영향 범위 확인, 법이 정한 기한 안의
  이용자 고지 순으로 한다. 고지 기한은 법무 확인 항목이다. (23)

## 영향

- **선 4의 범위가 바뀐다.** "서버에는 계정·체류·조건·일정 저장소가 없다"는 문장은 운영 스위치를 켜는 배포에서 "옵트인한 사용자의
  복귀 마감 시각과 확인 여부, 알림 주소만 서버에 둔다. 조건 값과 일정 내용은 여전히 두지 않는다"로 바뀐다. 그 전까지 `CLAUDE.md`와
  화면 문구는 그대로다.
- **새 저장 범주는 다시 보고 대상이다.** 이 결정은 위 네 레코드에 한정된다. 다른 값을 서버에 두려면 다시 운영자에게 보고한다
  (단계 B 포함).
- **판정 경로는 그대로 하나다.** 서버는 엔진이 이미 정해 기기가 올린 마감 시각을 지금 시각과 비교만 한다. 조건을 보지 않으므로
  두 번째 판정 경로가 아니다. 위치 권한 요청은 여전히 0건이다.
- **보기 전용 규칙에 예외가 하나 생긴다**('돌아왔어요'). **'내 정보 지우기' 규칙에도 예외가 하나 생긴다**: 오프라인에서 지웠을 때
  서버 삭제를 다시 보내기 위한 대기 표시가 계정 이름공간 밖에 남는다. 둘 다 `docs/security.md`에 적는다.
- 새 환경변수와 외부 업체(Upstash Redis·QStash)가 생긴다. 처리방침의 처리 위탁·국외 이전 고지가 필요하다(법무).
- 푸시 도착은 보장되지 않는다. 화면과 동의 문구에 "알림은 늦거나 오지 않을 수 있습니다. 알림만 믿지 말고 직접 연락해 주세요"를
  늘 보인다. 푸시 문구는 "복귀 확인이 없어요"라고 쓰고 "돌아오지 않았어요"라고 쓰지 않는다(선 5).
- 되돌리기: 운영 스위치를 끄면 화면에서 항목이 사라지고 쓰기 경로가 503이 된다. 삭제 경로는 계속 동작한다. 저장소는 TTL로 비워진다.

## 검증과 재검토

- 단위 테스트(외부 호출 0): VAPID 서명, RFC 8291 시험 벡터, 저장소 어댑터의 TTL·멱등·만료 상한, 재등록 규칙, 예약 처리 판정표.
- 계약 테스트: 클라이언트의 실제 요청 조립 함수가 만든 본문을 실제 라우트 처리기에 넣는다.
- 화면 테스트: 메모리 저장소와 로컬 가짜 푸시 엔드포인트(데모 모드에서만), 받은 암호문을 복호화해 문구 확인.
- 실기기: 안드로이드 Chrome, 아이폰 홈 화면 앱, 데스크톱 브라우저. 운영자 기기가 필요하다.
- 재검토 시점: 법무 검토 결과가 나왔을 때(운영 스위치), 아이폰 실기기 확인 뒤(질문 22), 단계 B를 다시 논의할 때, 업체 한도나
  요금이 바뀌었을 때.
