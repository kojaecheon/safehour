## 1. UX 원칙

1. **안전한 미추천 우선:** 추천이 없는 상태도 실패 화면이 아니라 명확한 다음 행동을 가진
   정상 결과로 설계한다.
2. **병원 조건 우선:** 인기·취향·평점은 금지조건을 상쇄하지 않는다.
3. **한 화면 한 결정:** 사용자는 현재 가능한 상태, 복귀 마감, 추천 3개, 변화 이유를
   빠르게 이해해야 한다.
4. **환자와 보호자 구분:** 같은 장소라도 역할과 분리 가능 여부에 따라 문구·버퍼·CTA가 달라진다.
5. **의료 판단 금지:** 회복일차나 증상으로 관광 가능 여부를 앱이 진단하지 않는다.
6. **출처와 불확실성 표시:** 폴백·추정·운영시간 불명·이동시간 폴백을 숨기지 않는다.
7. **현재 GPS 미사용:** 병원 지침에 담겨 온 고정 기준점만 사용한다.

### 개정으로 추가된 원칙

8. **사용자는 병원 조건을 타이핑하지 않는다.** 조건은 병원 발행값이고 화면에서 **고칠 수 없다**.
   고칠 수 있으면 "병원이 정한 조건" 이라는 말이 거짓이 된다.
   `/plan` 상시 문구 — "아래 조건은 병원이 발행한 것입니다. SafeHour가 해석하거나
   완화하지 않으며, 직접 고칠 수 없습니다."
9. **채널 A 와 채널 B 를 화면에서 섞지 않는다.**
   - 채널 A(제한조건 코드값) → 판정에 쓰이고 서버로 나간다. `/plan` 에 배지로 표시.
   - 채널 B(병원 안내문 원문) → **판정에 절대 쓰지 않고 서버로 보내지 않는다.**
     `/guide` 에서 원문 그대로 출력한다. 요약·편집·재배열·번역 금지.
10. **연결되지 않으면 관광지를 표시하지 않는다.** 지침 없음·만료·철회는 화면에서
    "조건 완화" 로 흡수되지 않는다. 미확인 중요 변경은 차단이 아니라 STANDBY 강등이며
    **읽으면 풀린다.**
11. **액션은 사라지지 않고 성격이 바뀐다** (단일 액션 원칙, 정의 §5.2).

    | 상태 | 단일 액션 | 사전 키 |
    | --- | --- | --- |
    | 가능 | **안전 외출 확인** | `today.ctaOuting` |
    | 대기(STANDBY) | **병원 안내 확인하기** | `today.reviewCta` |
    | 불가 | **병원에 연락하세요** | `today.ctaContact` |

    > 구현 주의 — "불가" 는 현재 버튼이 아니라 `medical-callout`(role=note) 안내문이다.
    > 누를 곳이 없다. 연락 수단 연결 여부는 §10 UNRESOLVED-006.

12. **출처는 세 갈래다.** 병원 원문 / SafeHour 판정·추정값 / 관광정보(TourAPI·기상청).
    v1.0 의 2영역 구분(원문·추정값)을 3영역으로 확장했다.
    병원 원문은 `.hospital-note`(좌측 3px 틸 보더)와 `badge-hospital` 로 묶는다.
13. **데모임을 숨기지 않는다.** 데모 지침으로 진입하면 `link.demoBadge` = "병원 연동 데모"
    를 `/link` `/today` `/plan` 상단에 상시 표시한다. 실제 연동으로 오인되면 공모전
    요강의 허위 제출 조항에 걸린다.

## 2. 정보구조

### D03-IA001 계획 생성 — **전면 개정**

v1.0 의 "시작 안내 → 기준점 선택 → 주의조건 입력 → 복귀시간 입력 → 역할 선택 → 확인" 은
폐기됐다. 실제 구조는 다음과 같다.

- 시작 안내 (의료 한계 3원칙)
- 로그인 (같은 계정이 다시 왔는가)
- 병원 지침 연결 (코드 또는 데모 예시)
- 오늘의 회복 상태 (연결 상태 · 복귀 마감 · 미확인 안내 · 단일 액션)
- 외출 계획 확인 (병원 조건 읽기 전용 · 기준점 · 복귀 마감 · **지금 상황만 선택**)
- 판정 실행

### D03-IA002 판정 결과

- 안전 상태 배너 (두 언어 병기)
- 복귀 마감 · 늦어도 출발 · 기준점 · 기상 실황
- 추천 3개 또는 미추천
- 제외 이유 (접기·펼치기)
- 환자·보호자 코스 전환
- 마지막 변화 요약 (시트를 닫아도 잔존)
- 장소 상세

### D03-IA003 변화 대응

- 변화 발생 → **처음부터 재판정**
- 변경 전후 비교 (제거·대체·축소·상태 전이)
- 즉시 복귀
- 외출 중 지침 만료·철회 시 추천 무효화 + 복귀 시트 자동 표시 (AX-220)

### D03-IA004 도움말·정책

- 의료진 판단 우선 안내
- 위치정보 처리 안내 (GPS 미수집, 좌표가 어디로 나가는지)
- 관광정보 출처·저작권
- 로그인이 무엇을 가져가는가 (ADR-0004 반영)
- 이 기기에서 내 정보 지우기
- 문의 및 오류 신고 — **책임자·창구 [지정필요]**

### D03-IA005 병원 회복 안내 열람 — **신설 (채널 B)**

- 카테고리 7종: 활동·외출 / 복약 / 음식·음료 / 생활 안내 / 동행 / 이상 상황 대응 / 다음 진료
- 카드마다: "병원에서 제공한 안내" 배지 · 원문 · 발행 시각 · 확인 상태
- 중요 4종(활동·동행·다음 진료·이상 상황)은 미확인 시 판정을 STANDBY 로 강등한다
- 원문 언어를 `lang` 속성으로 표기 — 번역하지 않는다

### D03-IA006 병원 연결 — **신설**

- 연결 코드 입력
- 데모 예시 3종 (외출 가능 / 외출 제한 / 지침 만료)
- 연결 후: 발행처 · 유효기간 · 연결 해제

### 내비게이션 구현 사실 (오해를 막기 위해 적는다)

- **하단 4탭 내비게이션(홈·회복 안내·안전 외출·보호자)은 미구현이다.**
  정의 §5 의 제안이며, 실제 내비게이션은 헤더 뒤로가기 버튼 + 본문 CTA + 하단 고지 링크다.
- **`/share`(보호자 연결·공유 범위) 화면은 없다.** 게이트웨이의 보호자 축약 발행 함수만
  구현돼 있고, 부르는 곳도 볼 화면도 없다.
- **`/login` 으로 가는 화면 링크가 없다.** 진입 경로는 `/link` 연결 시도의 401 리다이렉트와
  OAuth 오류 리다이렉트, 그리고 직접 URL 입력뿐이다 (§10 UNRESOLVED-007).
- 헤더 뒤로가기 목적지: `/link`·`/login` → `/`, `/plan` → `/today`, `/result` → `/plan`,
  `/place` → `/result`, `/guide`·`/privacy` → `history.back()`. `/today` 에는 뒤로가기가 없다.

## 4. 화면 계약

모든 화면 헤더에 언어 전환 버튼이 있다 (`common.langToggle`).
모든 판정 화면 하단에 `FooterLinks`(개인정보·면책 고지 링크 + 내 정보 지우기)가 붙는다.

### D03-SCR001 시작·안전 안내

- URL: `/`
- 목적: 서비스 역할과 의료 판단 한계를 이해하고 시작한다.
- 대상: 환자, 보호자
- 표시 문구 (정본 `home.*`)
  - 제목: "병원 조건 안에서만, / 안심 관광을 추천합니다"
  - 리드: "수술·시술 후 회복 중인 외국인 환자와 보호자를 위해, 병원이 정한 주의조건과
    복귀시간을 지키는 활동만 골라 보여드립니다."
  - 3원칙 (`home.p1`–`p3`): ① 의료 판단을 하지 않습니다. ② 현재 위치(GPS)를 서버로 보내지
    않습니다. ③ 조건을 지킬 수 없으면 추천하지 않습니다.
- 1순위 CTA: **"안심 코스 만들기"** (`home.cta`) → `/today`
- 부가 상태: "내 정보 지우기" 로 도착하면 삭제 완료를 1회 고지한다 (`home.clearedNotice`)
- 성공: 핵심 한계 3개를 읽지 않아도 CTA 주변에서 인지 가능
- **빈틈**: 이 화면은 "병원 연결이 필요하다" 는 사실을 말하지 않는다. 정의 §5 의
  "시작 → 연결 유도" 가 아직 문구로 반영되지 않았다 (§10 UNRESOLVED-005).

### D03-SCR009 로그인 — 신설

- URL: `/login`

- 표시 문구 (정본 `login.*`)
  - 제목: "회복 계획을 안전하게 불러오려면 / 로그인이 필요합니다"
  - 리드: "로그인은 다음에 열었을 때 같은 계획을 다시 불러오기 위한 것입니다.
    이름·이메일·프로필은 받지 않습니다."
  - **경계 고지 (필수, `medical-callout`)**: "로그인은 본인 확인이 아닙니다.
    어느 환자의 계획인지는 병원이 발급한 코드로 확인합니다."
  - 다음 단계 안내: "병원 회복 계획 연결은 로그인 다음 단계입니다.
    병원에서 받은 QR 또는 코드가 필요합니다."
- 순서: **Google 이 위, Kakao 가 아래.** 대상 사용자가 외국인 환자이므로 순서를 바꾸지 않는다.
- 자격증명이 없는 공급자: 숨기지 않고 "준비 중" 배지를 붙인 **버튼**으로 둔다.
  `href` 없는 `<a>` 는 link 롤을 잃어 보조기술에서 사라진다.
- 데모 경로: `SAFEHOUR_ALLOW_DEMO_LOGIN=1` 일 때만 "로그인 없이 둘러보기 (데모)" 가 뜬다.
- 오류: 공급자 실패 코드를 그대로 노출하지 않고 사용자 문구로 바꾼다
  (취소 / 시간 초과 / 재시도 / 미연결).
- 로그아웃: **POST 전용**.
- 금지: 이메일·이름·프로필 요청, 액세스·리프레시 토큰 저장.

  4. 미확인 안내 — "확인하지 않은 병원 안내가 {n}건 있습니다" → "병원 안내 확인하기"

  6. "병원 회복 안내 전체 보기"

  선택지를 계산할 수 있습니다." → CTA "병원 연결하기"
- 금지: 지침 없이 관광지 카드를 표시하는 것.

### D03-SCR007 변화 전후 비교 (모달)

### D03-UXS001 기본

### D03-UXS002 로딩

- Skeleton·spinner 와 현재 단계 표시 (`role="status"`)
- 중복 제출 방지 (버튼 disabled)
- 화면별 문구: "회복 상태를 확인하는 중입니다…" / "연결하는 중입니다…" /
  "조건에 맞는 활동을 찾고 있습니다…" / "결과를 불러오는 중입니다…" /
  "관광 원문을 불러오는 중입니다…" / "코스를 처음부터 다시 판정하고 있습니다…"
- 재판정 진행 표시는 **상주형 라이브 리전**이다. 조건부 마운트는 일부 스크린리더가 고지를 놓친다.
- 10초 지연 안내: [확인필요] — v1.0 계약에 있었으나 구현 확인 못 함

### D03-UXS003 빈 결과

- 추천 0건은 오류 화면이 아니다. "이것은 안전을 위한 정상 결과입니다."
- 조건을 임의 완화하지 않는다. 병원 확인 또는 인근 대기를 안내한다.
- `NO_CANDIDATE` 사유를 표시한다.

### D03-UXS004 오류

- 사용자 메시지와 기술 로그를 분리한다. 공급자 실패 코드를 그대로 노출하지 않는다.
- 재시도 가능 여부를 문구로 알린다.
- 인증키·URL query·원문 건강정보 미노출.
- 재계산 실패 시: "네트워크 오류로 재계산하지 못했습니다. **기존 추천을 계속 신뢰하지 마세요.**"

### D03-UXS005 Timeout·Offline

- 마지막 정상 결과는 오래된 결과임을 표시한 경우에만 열람한다.
- 새 추천·재계산은 네트워크 회복 후 실행한다.
- 안전 입력이 불충분하면 미추천.

### D03-UXS006 연결 게이트 차단 — **개정 (기존 "권한·정책 차단")**

기존 안전 게이트 **앞**에 연결 게이트가 있다. 차단·강등 사유를 반드시 설명한다.

| 사유 코드 | 화면 문구 | 결과 |
| --- | --- | --- |
| `NO_HOSPITAL_PLAN` | 연결된 병원 회복 지침이 없습니다 | 차단 (NO_TOURISM) |
| `PLAN_EXPIRED` | 병원 회복 지침의 유효기간이 지났습니다 | 차단 + 외출 중이면 추천 무효화·복귀 |
| `PLAN_REVOKED` | 병원이 회복 지침을 거둬들였습니다 | 차단 + 외출 중이면 추천 무효화·복귀 |
| `PLAN_UNCONFIRMED_UPDATE` | 확인하지 않은 병원 안내 변경이 있습니다 | **STANDBY 강등** — 읽으면 풀린다 |
| `MEDICATION_WINDOW` | 복약 시각까지 돌아와야 합니다 | 마감 단축 — **현재 어디서도 방출되지 않는다** (§10) |

기존 안전 게이트 사유(외출 제한·필수 동행·금식·실내 전용·자외선·보행/이동 한도·
조건 최신성·위험신호 등)는 그대로 유지된다.

- 우회 CTA 제공 금지.
- 차단 화면에는 병원 확인 또는 복귀 CTA를 둔다.
- **외출 중 만료 감시 (AX-220)**: 진입 시점 · 만료 타이머 · 탭 복귀 3시점에서 확인한다.
  이미 나가 있는 사람에게 "만료됐습니다" 만 띄우는 것은 위험하므로, 환자 호출과 **같은
  모양**으로 추천을 비우고 복귀 시트를 자동 표시한다.

### D03-UXS007 Stale 데이터

- 운영시간·상세·날씨가 최신이 아니면 배지와 재조회 행동을 제공한다.
- stale 정보는 안전 조건을 완화하는 근거로 쓰지 않는다.
- 기상 확인 불가는 "반영되지 않았습니다" 로 명시한다 — 침묵하지 않는다.

### D03-UXS008 데모 표시 — 신설

- 데모 지침으로 연결된 세션은 `/link` `/today` `/plan` 상단에 "병원 연동 데모" 배지를
  상시 표시한다.
- 이 표시를 숨기거나 조건부로 감추지 않는다.

### 용어

| 쓰는 말 | 안 쓰는 말 | 왜 |
| --- | --- | --- |
| 병원 조건 / 병원 회복 지침 | ~~회복 단계~~ | 앱이 회복 정도를 판단하는 것으로 오해된다 |
| 현재 입력 조건을 통과함 | ~~안전합니다~~ | 조건 통과와 안전은 다르다 |

### 번역 정책 (ADR-0003)

- 번역 대상: 화면 라벨과 SafeHour 자체 문구.
- **번역하지 않는 것**: TourAPI `overview`·운영시간 원문, 기상 실황, **병원 안내문(채널 B)**.
- 원문에는 원문 언어를 `lang` 으로 붙인다.
- 국문 폴백 시 "번역 필요" 배지로 표시만 한다.
- 문구가 아니라 **키를 저장**한다 — 언어를 바꾸면 이미 뜬 오류·변화 요약도 함께 바뀐다.
- 언어는 서버로 전송하지 않는다 (본문·헤더·쿼리 어디에도).

## 7. 반응형·접근성

- 앱 셸 최대 폭 480px. 검증 폭: **320 / 360 / 430 / 768 / 1280px 가로 스크롤 없음**
- 모바일 주요 CTA는 엄지 도달 영역에 고정 (`.sticky-return`, `env(safe-area-inset-bottom)` 반영)
- 본문 최소 16px, 터치 대상 최소 44×44px
- 상태를 색상만으로 구분하지 않고 배지 텍스트를 병행
- WCAG AA 대비 목표 — 병기 문구를 `opacity` 로 흐리게 하지 않는다
- 모든 입력에 label·description·error 연결
- 키보드 탭 순서와 focus-visible. 탭 목록은 좌우 화살표 이동
- 하단 고정 복귀 CTA는 시각 위치와 무관하게 **DOM 상 `main` 앞**에 둔다
- 변화 발생 시 `aria-live="polite"`. 재판정 진행 고지는 상주형 라이브 리전
- 이미지 alt는 장소명·장면 정보만 사용하고 홍보 문구 금지
- Reduce motion 환경에서 전환 애니메이션 제거
- `document.documentElement.lang` 을 실제로 갱신한다 (WCAG 3.1.1)
- `href` 없는 `<a>` 를 쓰지 않는다 — link 롤을 잃어 보조기술에서 사라진다

### D03-UNRESOLVED-003 경로 열기 — 존치·확대

### D03-UNRESOLVED-004 `/plan` 앵커 계약 불일치 — 신설

- 사실: ADR-0001 보완 조건 1 은 `#location` `#condition` `#role` 3개 앵커를 요구했으나,

- 영향: AX-101(Figma 매핑)·AX-202(화면·URL 대응표)가 3분할 앵커를 전제하면 어긋난다.
- 선택: 앵커 2개를 추가하거나, 화면 구조가 바뀌었으므로 ADR-0001 보완 조건 1을
  이 문서 §4 의 절 구성으로 대체하거나.
- Blocking Level: doc_blocker

### D03-UNRESOLVED-005 시작 화면이 연결을 유도하지 않는다 — 신설

- 사실: `/` 는 3원칙과 "안심 코스 만들기" 만 보여주고, **병원 연결이 필요하다는 사실을
  말하지 않는다.** 정의 §5 의 "시작 → 연결 유도" 가 문구로 반영되지 않았다.
- 또한 CTA 문구("안심 코스 만들기")와 목적지(`/today` 오늘의 회복 상태)가 어긋난다. [확인필요]
- 영향: 처음 온 사람이 `/today` 에서 "연결된 병원 지침이 없습니다" 를 만나 이유를 모른다.
- Blocking Level: ux_blocker

### D03-UNRESOLVED-006 "불가" 상태의 단일 액션에 행동이 없다 — 신설

- 사실: 불가 상태의 단일 액션 "병원에 연락하세요" 는 버튼이 아니라 안내문이다.
  누를 곳이 없고, 병원 연락처가 화면에 없다.
- 질문: 발행 병원의 연락 수단을 채널 A 에 포함시킬 것인가? 포함시키면 무엇을(대표번호만?)
  받을 것인가?
- 근거 필요: 의료진·개인정보 검토
- Blocking Level: ux_blocker · 담당 [지정필요]

### D03-UNRESOLVED-007 `/login` 진입 경로가 없다 — 신설

- 사실: 어느 화면에서도 로그인으로 가는 링크가 없다. 진입은 `/link` 의 401 리다이렉트,
  OAuth 오류 리다이렉트, 직접 URL 뿐이다.
- 영향: 이미 로그인한 사용자가 **로그아웃할 방법을 화면에서 찾을 수 없다**
  (「내 정보 지우기」가 로그아웃을 함께 수행하지만, 그것이 로그아웃 수단이라고
  화면이 말하지 않는다).
- Blocking Level: ux_blocker

### D03-UNRESOLVED-008 QR 문구와 구현의 불일치 — 신설

- 사실: `/link` 와 `/login` 문구가 "QR 또는 코드" 라고 안내하지만, **QR 카메라 스캔은 없다.**
  실제 입력 수단은 텍스트 코드뿐이다.
- 선택: 스캔을 구현하거나, 문구에서 QR 을 빼거나, "QR 에 적힌 코드" 로 바꾸거나.
- Blocking Level: doc_blocker (허위 표시 위험)

### D03-UNRESOLVED-009 표시되지만 판정에 쓰이지 않는 조건 — 신설

- 사실: `/plan` 의 "병원이 정한 조건" 에 **열 노출 회피**와 **수중 활동 금지** 배지가 뜨지만,
  조건 객체로 옮기는 단계에서 빠져 안전 게이트가 읽지 않는다.
  **병원이 "사우나·찜질 금지" 를 발행해도 찜질방이 후보에서 빠지지 않는다.**
  금식 종료 시각도 boolean 으로만 쓰이고 시각으로는 쓰이지 않는다.
- 판단: 적용되지 않는 조건을 적용되는 것처럼 보여주는 것은 **아예 안 보여주는 것보다 나쁘다.**
  사용자가 앱이 걸러줬다고 믿는다.
- 선택: 판정에 반영하거나, 화면에서 **표시 전용임을 구분**하거나.
- Blocking Level: safety_blocker

### D03-UNRESOLVED-010 채널 A 제한조건 목록 확정 — 신설

- 질문: 병원이 실제로 발행할 수 있는 제한조건 항목은 무엇인가?
- 근거 필요: **의료진 확인.** 연동 병원 파트너 **0곳**이라 미검증.
- 영향: SCR013 의 조건 배지 목록과 SCR011 의 마감 계산 입력이 여기서 정해진다.
- Blocking Level: development_blocker · 담당 [지정필요]

### D03-UNRESOLVED-011 유효기간 72시간 vs 조건 최신성 24시간 충돌 — 신설

- 사실: 병원 계획은 72시간 유효한 것으로 발행되고 화면에도 그렇게 표시되는데,
  안전 게이트의 조건 최신성 한도는 24시간이다. 30시간 전 발행된 계획으로 판정하면
  `state=NO_TOURISM · reasons=["STALE_HOSPITAL_CONDITION"]` 이 나온다.
- 화면 영향: **사용자에게는 "유효기간 내" 라고 보이는데 아무것도 추천되지 않는다.**
  안전 방향으로 보수적이라 위험하지는 않지만, 이유를 알 수 없는 차단은 신뢰를 깨뜨린다.
  데모 계획이 방금 발행된 것으로 동작해 평소 시연에서는 드러나지 않는다.
- 선택: 유효기간을 24시간에 맞추거나, 최신성 한도를 계획 유효기간에 위임하거나,
  두 기준을 분리해 화면에 각각 표시하거나.
- **어느 쪽이든 의료 자문이 정할 값이다** (조건이 며칠까지 유효한가는 의학적 판단이다).
- Blocking Level: safety_blocker · 담당 [지정필요]

### D03-UNRESOLVED-012 `MEDICATION_WINDOW` 사유가 화면에도 로그에도 없다 — 신설

- 사실: 복약 시각 때문에 마감이 앞당겨졌다는 사유 코드가 정의돼 있지만 **어디서도
  방출되지 않는다.** 화면은 "복약 시각이 더 이릅니다" 라는 별도 문구로 그 사실을
  보여주므로 사용자가 정보를 잃지는 않지만, 판정 기록에는 사유가 남지 않는다.
- Blocking Level: doc_blocker

### D03-UNRESOLVED-013 보호자 화면 미착수 — 신설

- 사실: 게이트웨이의 보호자 축약 발행 함수만 있고 **부르는 곳도 볼 화면도 없다.**
  `/share`(보호자 연결·공유 범위) 라우트가 없다.
- 미결: 환자가 보호자를 부르는 수단, 공유 기본값을 "공유 안 함" 으로 할지.
- 주의: 보호자 화면을 환자 앱의 탭으로 넣으면 정보 분리가 무의미해진다 (정의 §5.1).
- Blocking Level: development_blocker

### D03-UNRESOLVED-014 하단 4탭 내비게이션 채택 여부 — 신설

- 질문: 정의 §5 가 제안한 하단 4탭(홈·회복 안내·안전 외출·보호자)을 도입할 것인가?
- 현재: 미구현. 헤더 뒤로가기 + 본문 CTA + 하단 고지 링크로 동작한다.
- 종속: 4번째 탭은 보호자 화면(UNRESOLVED-013)에 달려 있다.
- Blocking Level: design_blocker

### D03-UNRESOLVED-015 지침 변경 → 재판정 배선 미연결 — 신설

- 사실: 만료·철회는 감시되지만(AX-220), **병원 업데이트 5종(안내 변경·진료시간 변경·
  동행 조건 변경·복귀시간 단축·환자 호출)의 변경 신호는 재판정 파이프라인에 연결되지
  않았다.** 기존 파이프라인 재사용이 계획이나 배선이 없다.
- 화면 영향: SCR007 이 병원발 변경을 표시할 경로가 아직 없다.
- Blocking Level: development_blocker

### D03-UNRESOLVED-016 계획 서명·위조 검증 없음 — 신설

- 사실: 계획이 판정 근거인데 서명·위조 검증이 없다. 게이트웨이는 **형식만** 검증한다.
- 화면 영향: "병원 지침 확인됨" 배지가 무엇을 근거로 확인이라고 말하는지가 이 결정에 달렸다.
- Blocking Level: release_blocker · 담당 [지정필요]

### D03-UNRESOLVED-017 연결 게이트가 판정 API에 없다 — 신설

- 사실: 화면과 `/api/today` 경로에는 연결 게이트가 있지만, **추천을 생성하는 판정 API에는 없다.**
  화면을 따라가는 사용자는 만료된 지침으로 추천을 받지 못하지만, API를 직접 부르면 받는다.
- 현재 위험도: 화면이 유일한 진입점이라 실사용 위험으로 이어지지 않는다.
- 판단: "지침이 없으면 관광지를 표시하지 않는다" 가 제품의 안전 주장인 이상,
  **그 강제는 서버에 있어야 한다.**
- Blocking Level: safety_blocker

### D03-UNRESOLVED-018 사용자 검증 0건 — 신설

- 사실: 실제 환자·보호자 인터뷰 **0건**. 실기기·스크린리더 확인 미실행.
  이동 버퍼 현장 측정 미실행. 영문 문구 검수 미실행.

- Blocking Level: release_blocker
