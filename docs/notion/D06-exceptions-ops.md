## 1. 예외 등급

- Critical: 의료 경계·복귀·개인정보·인증정보 위험. 즉시 추천 중단과 운영 알림
- High: 잘못된 후보·상태를 만들 수 있는 데이터·판정 실패. 안전한 미추천
- Medium: 일부 상세·번역·이미지 실패. 핵심 판정 유지 가능하면 제한적 폴백
- Low: 비핵심 표시·분석 이벤트 실패. 사용자 핵심 흐름 유지

**로그 공통 금지**: API key, serviceKey, 전체 URL query, 현재 GPS, **병원 안내문 원문(채널 B)**,
이름·연락처·증상 원문, 세션 식별자·OAuth 토큰·`provider+sub` 식별자, 기준점 좌표 원값.

> 판정 운영 로그의 허용 범위는 ADR-0002 가 정본이다 — 상태·사유 코드·후보 수·조건 신선도
> 구간만 남기고, 그 로그로 요청을 복원할 수 없어야 한다.

#### D06-E024 로그인 실패 — **공급자 미설정 포함**

- 등급: **Critical (배포 환경 결함일 때)** / High (개별 사용자 실패)
- 연결 기능: `/login`, `/api/auth/login`, `/api/auth/callback` (ADR-0004)
- 왜 Critical 인가: 로그인이 막히면 지침을 연결할 수 없고, 지침이 없으면 연결 게이트가
  관광지 표시 자체를 막는다. **"일부 기능 제한" 이 아니라 제품 전체가 도달 불가능**해진다
- 실패 사유 코드와 처리:

| 사유 코드 | 발생 조건 | 사용자 메시지 |
| --- | --- | --- |
| `cancelled` | 공급자 화면에서 사용자가 취소 | "로그인을 취소했습니다. 다시 시도해 주세요." |
| `expired` | OAuth 왕복 쿠키(10분) 만료 | "시간이 지나 다시 시작해야 합니다. 다시 시도해 주세요." |
| `state_mismatch` · `missing_code` · `exchange_failed` | CSRF 대조 실패 / 인가 코드 없음 / 토큰 교환 실패 | "문제가 생겨 로그인을 마치지 못했습니다. 다시 시도해 주세요." |
| `not_configured` | `SAFEHOUR_SESSION_SECRET` 또는 `SAFEHOUR_BASE_URL` 없음 | "이 방식은 아직 연결되지 않았습니다. 다른 방식을 선택해 주세요." |
| `provider_not_configured` | 해당 공급자의 CLIENT_ID/SECRET 없음 | 위와 같음 |
| `unknown_provider` | 지원하지 않는 provider 값 | 위와 같음 |
| `demo_disabled` | `SAFEHOUR_ALLOW_DEMO_LOGIN` 미설정 상태에서 데모 진입 시도 | 위와 같음 |

- **로그·화면 금지**: 공급자 응답 본문·예외 메시지를 그대로 노출하지 않는다.
  실패는 **코드로만** 전달한다 (클라이언트 정보·인가 코드가 섞일 수 있다)
- 화면 처리: 자격증명이 없는 공급자 버튼은 **"준비 중"으로 비활성** 표시한다. 눌러서 실패하게 두지 않는다
- 서명 키가 없으면 로그인 기능 자체가 비활성이다 — 서명 없는 세션은 위조 가능하므로 켜지 않는 편이 안전하다
- 운영 탐지: `GET /api/auth/session` 의 `auth` 객체
  (`ready` · `sessionSecretConfigured` · `callbackConfigured` · `demoLogin` · `providers[].configured`).
  **`ready` 만 보면 안 된다** — `ready=true` 인데 로그인 수단이 0개인 조합이 존재한다 (§7 D06-INC001)
- Runbook: `docs/DEPLOY_CHECKLIST.md` 환경변수 표 → `npm run verify:deploy -- <URL>` 재실행
- Owner: 개발·운영 · [지정필요]
- QA: `test/auth.test.js` 42건 (서명 위조·만료·키 불일치·state 타이밍 안전 비교·열린 리다이렉트 6종·최소 scope·토큰 미노출)

### D06-E026 연결 게이트가 걸리지 않은 경로 (신설 · 알려진 결함)

### D06-E027 조건이 표시만 되고 판정에 쓰이지 않음 (신설 · 알려진 결함)

  옮겨지지 않아 안전 게이트가 읽지 않는다

- 처리 방향: 판정에 반영하거나, **표시 전용임을 화면에서 구분**한다

## 6. 사용자·시스템·운영 처리 분리

### 사용자

- 기술 코드보다 **지금 가능한 행동**을 먼저 표시
- 재시도, **병원 안내 확인**, 병원 연락, 대기, 즉시 복귀, **재연결** 중 하나를 제공
- **액션은 사라지지 않고 성격이 바뀐다** — 가능 `안전 외출 확인` / 대기 `병원 안내 확인하기` / 불가 `병원에 연락하세요`
- 오류로 안전 차단을 우회하는 CTA 금지
- **조건 수정 CTA 금지** — 병원 조건은 읽기 전용이다. "직접 고칠 수 없습니다"가 화면 문구다

### 시스템

- **연결 게이트 → 안전 게이트 → 후보 판정** 순서를 유지한다
- 세부 순서: 인증 → 입력 검증 → 연결 게이트 → 외부 API → 정규화 → 안전 게이트 → SLA
- 실패가 안전 입력을 훼손하면 추천 생성 금지
- before·after·reason code와 safe log 기록
- secret·PII redaction
- **홈과 결과 화면이 같은 판정 함수를 부른다.** 판정이 두 벌 생기는 것이 이 제품에서 가장 위험한 결함이다

### 운영

- Critical 즉시, High 15분 내 확인 후보, Medium 일일 검토 후보
- On-call 체계와 실제 SLA [확인필요]
- 재현 입력은 **비식별 fixture** 로 남긴다 (`src/recovery/fixtures.js` · `DEMO-A`/`DEMO-B`/`DEMO-C`)
- 수정 후 연결 D09 회귀와 라이브 시나리오 재검증

### 7.1 운영 사고 기록

#### D06-INC001 배포본 로그인 불가를 자동 검증이 잡지 못함 — 해소됨 (2026-08-25)

| | |
| --- | --- |
| 등급 | Critical (제품 전체 도달 불가) |
| 상태 | **해소됨.** 배포 검증 14건 통과 |
| 연결 | `docs/PRD.md` Part 4 ⑤ · `docs/DEPLOYMENT.md` 1절 · `scripts/verify-deployment.mjs` |

**무슨 일이 있었나.** 한동안 배포본에 **로그인 수단이 하나도 설정돼 있지 않았다.**
지침 연결이 로그인을 요구하고, 지침이 없으면 연결 게이트가 관광지 표시를 막는다.
그래서 URL 로 들어온 사람은 **홈 화면과 "연결된 병원 지침이 없습니다"까지만** 볼 수 있었다.
사용자 시나리오 전체가 도달 불가능한 상태였다.

**그런데 배포 검증 13건이 전부 통과했다.** 검증이 관광·기상 키만 확인하고 로그인은 보지 않았다.
제품은 그때도 `GET /api/auth/session` 으로 정확히 보고하고 있었다 —
**사람이 눈으로 볼 때만 보였고, 자동 검증이 그것을 읽지 않았다.**

**무엇을 고쳤나.**

1. 배포 검증에 **"로그인 가능"** 항목을 추가했다 (13건 → 14건).
2. 판정을 `auth.ready` 만으로 하지 않는다. `ready` 는 "세션 키와 콜백 주소가 있다"는 뜻이고
   로그인 **수단**이 있는지는 보지 않아, **`ready=true` 인데 아무도 로그인할 수 없는 조합**이 존재한다.
   검증은 **기반 + 수단 하나 이상**(`providers[].configured` 중 하나 또는 `demoLogin`)을 함께 본다.
3. 실패 시 없는 환경변수를 이름으로 지목한다 — `SAFEHOUR_SESSION_SECRET` / `SAFEHOUR_BASE_URL` /
   로그인 수단(`GOOGLE_`·`KAKAO_CLIENT_ID`·`SECRET` 또는 `SAFEHOUR_ALLOW_DEMO_LOGIN=1`).
4. 경고가 아니라 **실패**로 다룬다. 로그인 불가는 "일부 기능 제한"이 아니기 때문이다.

**재발방지 규칙 — 이 사고에서 뽑은 일반 원칙.**

> **제품이 이미 정확히 보고하고 있어도, 자동 검증이 읽지 않으면 없는 것과 같다.**
> 새 기능이 사용자 여정의 **선행 관문**이 되면 (로그인 → 연결 → 판정),
> 그 관문의 가용성을 배포 검증 항목으로 **함께** 추가한다.
> 그리고 **"설정됨"과 "실제로 통과 가능함"을 구분해 판정한다.**

**남은 것**: 이 규칙을 배포 체크리스트의 상시 항목으로 못 박을지, 관문이 늘 때마다
검증을 추가하는 절차 오너를 누구로 둘지 — [지정필요]

### D06-UNRESOLVED-009 계획 서명·위조 검증 (신설)

- 질문: 위조된 계획으로 판정하는 것을 어떻게 막는가?
- 사실: **없다.** 계획이 판정의 근거이므로 안전 요건인데 미결이다
- Blocking Level: release_blocker
- 상태: **미해결** — 사람 결정 큐 항목

### D06-UNRESOLVED-010 감사 기록 보관 주체 (신설)

- 질문: 누가 언제 계획을 발행·조회했는지의 감사 기록을 병원이 보관하는 것으로 확정할 것인가?
- 사실: 판정 감사 증적(상태·사유 코드·후보 수·조건 신선도 구간)은 서버 로그로 남긴다.
  **병원 측 감사 기록의 경계는 미정**이다. SafeHour 가 보관하면 "서버 무저장"이 조용히 깨진다
- Blocking Level: release_blocker
- 상태: **미해결**

## 10. 이 문서가 사실이 아니라고 적어두는 것

혼동을 막기 위해 **없는 것을 없다고** 적는다.

| 항목 | 사실 |
| --- | --- |
| 보호자 화면 | **없다.** 게이트웨이 축약 함수는 있으나 부르는 서버 경로도 `/share` 화면도 없다 |
| QR 카메라 스캔 | **없다.** 문구로만 안내하고 실제 입력 수단은 텍스트 코드 하나다 |
| 계획 서명·위조 검증 | **없다** |
| 지침 변경 → 재판정 배선 | **미연결** (만료·철회만 감시) |
| 실제 병원 파트너 | **0곳.** 열리는 것은 비식별 데모 계획 3종이고 `병원 연동 데모` 배지를 상시 표시한다 |
| 지도·경로 연동 | **없다 — 의도적으로 멈춤.** 기준점 좌표 복사로 대체 |
| 열 노출 회피·수중 활동 금지 | **화면에만 뜨고 판정에 쓰이지 않는다** (D06-E027) |
| 휴무·교통 자동 감지 공급자 | **없다.** 기상만 실API. 나머지는 시연에서 상황을 넣는다 |
| 전문가 승인 | **0건**, 담당자 미지정 |
| 실제 환자·보호자 인터뷰 | **0건** |
