### D07-POL001 의료 판단 경계 정책

- 목적: SafeHour가 의료진 판단을 대체하거나 증상을 진단하지 않도록 한다.
- 범위: 모든 입력·판정·문구·알림·운영
- 허용:
	- 병원이 **채널 A 로 발행한** 금식·외출·동행·자외선·실내·보행·복귀 조건의 구조화

	- 의료진 판단 우선과 병원 연락 안내
- 금지:
	- 수술·시술 종류나 회복일차로 외출 가능 여부 자동 결정
	- 증상 텍스트 해석·진단·위험도 평가
	- 약물·처치·식사 관련 의료 조언
	- **채널 B 문장 해석 (POL012)**

  **경과 구간**(`conditionAge`)만 남는다 (POL016)
- Owner: 제품 책임자

### D07-POL002 위치정보 최소처리 정책

- 목적: 현재 GPS 서버 전송을 피하고 공모전·위치정보 규제 리스크를 줄인다.

	- **병원 지침에 담겨 온 기준점 좌표** 또는 사용자가 직접 선택한 병원·숙소 고정 좌표

	- 위치 원좌표가 아닌 비식별 계측 구간
- 금지:
	- 브라우저 geolocation으로 얻은 현재 GPS의 서버 전송
	- 사용자 몰래 제3자 지도 API에 현재 위치 전송
	- 위치 이력·동선 저장

	- **TourAPI 호출 로그의 `mapX`/`mapY` 는 `REDACTED` 로 가린다** (ADR-0002 에서 정정·수정)
- 위반 탐지: API schema, 네트워크 QA, 코드 검색
- 처리: 요청 차단·저장 금지·사고 대응
- 현안: 위치정보지원센터 사전검토 문의번호 2540 **답변 여전히 대기**

### D07-POL012 채널 분리·재해석 금지 정책 (신설)

- 근거: `docs/PRODUCT_DEFINITION.md` §2 · §4 (확정 구조)
- 목적: 병원이 판단하고 SafeHour 는 해석하지 않는다는 경계를 **기술 계약으로** 고정한다.

| | **채널 A — 제한조건** | **채널 B — 병원 안내문** |
| --- | --- | --- |
| 형태 | 기계가 읽는 코드값·수치·시각 | 사람이 읽는 문장 (병원이 쓴 그대로) |
| 판정에 쓰이나 | **쓰인다** | **절대 쓰이지 않는다** |
| 서버로 가나 | 간다 (비식별, 계산 후 폐기) | **가지 않는다.** 단말 표시 전용 |
| SafeHour 가 해석하나 | 아니오 — 그대로 적용 | 아니오 — 그대로 출력 |
| 민감정보 등급 | 낮음 (행동 제약) | **높음** (약물·시술 정황) |

- **핵심 규칙**: 판정에 쓰려면 병원이 **채널 A 로 발행해야 한다.** 채널 B 문장을 파싱해
  판정에 쓰는 것이 곧 재해석이며 금지한다
- 적용 예:
	- **식이** — 병원이 `식음제한=true` 또는 `금식종료=HH:MM` 을 채널 A 로 발행하면
	  식음 활동을 제외한다. "매운 음식 주의" 같은 문장은 **표시만** 하고 필터링에 쓰지 않는다
	- **복약** — **복약 시각만** 채널 A 로 받는다. 무슨 약인지 알 필요가 없다. 약물 안내문은
	  채널 B 로 표시
- 표시 규칙:
	- 병원 원문과 SafeHour 문구를 **시각적으로 분리**한다
	- 각 카드에 "병원에서 제공한 안내" 배지 + 발행·수정 시각 + 유효기간 + 새 버전 여부 + 확인 상태
	- **번역·요약·편집·재배열하지 않는다.** 원문 언어를 `lang` 으로 표기하고, 다국어가
	  필요하면 병원이 다국어 원문을 함께 발행한다
- 시스템 강제: `toDecisionPayload` 가 안내문의 `text`·`lang` 을 떼어낸다.
  서버로 가는 것은 `id`·`category`·`acknowledged` 뿐이다 (`src/recovery/plan.js`)
- 위반 탐지: payload schema 검사, 코드 리뷰, 네트워크 QA

- Signoff: 의료 자문, 개인정보 책임자 · \[지정필요\]

### D07-POL015 계정 인증·세션 경계 정책 (신설)

- 근거: **ADR-0004 (Accepted, 2026-08-14)** · AX-219
- 결정: **소셜 로그인(Google · Kakao)을 도입하되 서버 데이터베이스를 만들지 않는다.**
  사용자 신원은 **서명된 쿠키 안에만** 존재한다.
- 규칙:

| # | 규칙 |
| --- | --- |
| 1 | **최소 범위만 요청한다** — Google 은 `openid` 만, Kakao 는 선택 동의 항목 0개 |

| 7 | `returnTo` 는 **같은 출처의 절대 경로만** 허용 (열린 리다이렉트 방어) |
| 8 | **로그아웃은 POST 전용** |
| 9 | **"내 정보 지우기" 가 로그아웃까지 수행한다** — 안 그러면 그 버튼이 거짓말이 된다 |

  뿐이고, **"이 사람이 그 환자다" 는 병원이 발급한 코드가 확인한다.** 인증 주체는
  병원이고 SafeHour 는 검증만 한다. 화면과 고지에 그렇게 명시한다

### D07-POL016 판정 운영 로그 정책 (신설)

- 근거: **ADR-0002 (Accepted, 2026-08-11 · 선택지 B)** · AX-008
- 결정: **운영 로그에 판정 결과를 남기고, 사용자 행동 분석 계측은 구현하지 않는다.**
- 용어 구분: **저장**은 나중에 다시 조회할 수 있는 형태로 상태를 보존하는 것이고,
  **운영 로그**는 되읽지 않는 쓰기 전용 기록이다. 이 구분이 없으면 "서버는 저장하지
  않는다" 와 "로그를 남긴다" 가 모순처럼 보인다
- 이 결정이 D07 에 붙는 이유:
	- **4절이 감사 증적으로 `engine decision log` 를 이미 요구했다.** 새 데이터 종류를
	  만드는 것이 아니라 정책이 요구했으나 만들지 않았던 증적을 만드는 것이다
	- **POL001 의 위반 탐지 수단이 "런타임 reason code 검사"다.** 판정 사유를 남기지
	  않으면 그 정책은 강제 수단 없이 문서로만 존재한다
- 확정 범위:

| 항목 | 결정 |
| --- | --- |
| 기록 위치 | **stdout 한 줄**(JSON). 파일·DB·외부 도구를 새로 만들지 않는다 |
| `session_id` | **남기지 않는다** |
| 조건 발행시각 | 원값 대신 **경과 구간**(`conditionAge`: FRESH·RECENT·AGING·STALE·FUTURE·UNKNOWN) |
| reason code | **닫힌 enum 통과분만** 기록 — 자유 문자열은 버린다 |
| 장소 이름·주소 | **남기지 않는다** — 후보 식별자와 개수만 |
| 좌표·병원 원문·역할 조합 | **남기지 않는다** |
| 외부 오류 원문 | **남기지 않는다** — 인증키·URL 혼입 위험 |

- 남기는 것: `route` `outcome` `state` `reasons` `courseCount` `excludedCount`
  `excludedReasons` `candidateCount` `conditionAge` `trigger` `engine` · 재계산 시
  `stateBefore` `visibleChange` `removed/added/shortenedCount`
- **행동 분석 계측 미구현**: D02-EVT001–EVT007 은 **2차 범위**로 이동한다. 문서에서
  삭제하지 않는다 — 실사용자 트래픽이 생기면 그대로 쓸 수 있는 설계이기 때문이다.
  그 결과 **선택 분석 동의 대상이 없다**
- 검증: `test/decision-log.test.js` 가 개인정보를 잔뜩 담은 요청을 넣고 로그 출력에
  그 값들이 하나도 나타나지 않음을 단언한다. 필드를 늘릴 때 이 테스트가 먼저 막는다
- **미해결 — 사유 코드는 "건강 상세" 인가.** `FASTING_REQUIRED`·`OUTING_FORBIDDEN`·
  `RISK_SIGNAL`·`PATIENT_RECALLED` 같은 코드는 환자 상태를 어느 정도 드러낸다.
  남기는 이유는 POL001 이 이것을 탐지 수단으로 지정했고, 가장 거친 표현이며, 세션
  식별자가 없어 요청 간에 이어붙일 수 없기 때문이다. **개인정보 담당자 판단 필요**
  (`docs/SIGNOFF_CHECKLIST.md` 2.10 · UNRESOLVED-014)
- 재검토 조건: 실사용자 트래픽 발생 시 B→C 재검토 / 심사 요구에 행동 지표가 명시되면
  즉시 재검토 / **기능 동결 이후에는 변경하지 않는다**

### D07-UNRESOLVED-002 데이터 보존기간

  **남은 것은 "플랫폼 기본값을 따른다" 를 정책으로 확인하는 일**이다 (AX-104)
- Blocking Level: release_blocker

### D07-UNRESOLVED-003 관광정보 출처 표기 — **해소**

- 질문(당시): 서비스 내 허용되는 정확한 출처 표기 문구와 위치는 무엇인가?

  오퍼레이션명의 화면 노출을 제거했다. 로고 이미지는 사용하지 않는다
- 번호는 재사용하지 않는다

### D07-UNRESOLVED-004 의료·법무 Signoff

- 질문: 의료관광·의료법·면책 문구를 누가 검토하고 승인할 것인가?
- v1.1 추가: **병원 연동이 알선이 아니라는 전제**(POL003)의 법적 성립 여부도 함께 본다
- 현황: 5개 영역 **승인 0건 · 책임자 전원 미지정.** 자문 섭외 기한 08.31,
  의료 경계 판정은 **09.07 기능 동결 전**
- Blocking Level: release_blocker

### D07-UNRESOLVED-005 민감정보 별도 동의 설계 부재 (신설)

- 사실: 채널 B 를 화면에 표시하는 것만으로 건강정보 처리이고, **개인정보보호법 §23
  별도 동의가 필수**다. 그런데 **동의 문구·시점·철회 방법이 아직 없다**
- 함께 정할 것: 병원 → 앱 제3자 제공의 근거, 보호자 공유 동의 범위, 보호자 공유 기본값
  ("공유 안 함" 을 기본으로 할지)
- 결정 주체: 개인정보 책임자 + 법무 · \[지정필요\]
- Blocking Level: release_blocker

### D07-UNRESOLVED-006 회복 지침 서명·위조 검증 부재 (신설)

- 사실: 회복 지침이 판정의 근거인데 **서명·위조 검증이 없다.** 게이트는 형식과
  만료·철회만 본다
- 영향: 위조된 계획으로 판정하면 안전 사고다. 연결 게이트의 신뢰 전제가 성립하지 않는다
- 결정 주체: 사람 (`docs/PRODUCT_DEFINITION.md` §12 사람 결정 큐)
- Blocking Level: release_blocker

### D07-UNRESOLVED-007 연결 게이트가 판정 API 에 없다 (신설)

- 사실: 화면과 오늘 상태 계산 경로에는 연결 게이트가 있으나 **추천을 생성하는 판정 API 에는
  없다.** API 를 직접 부르면 만료된 지침으로도 추천을 받는다
- 현재 위험: 화면이 유일한 진입점이라 실제 위험으로 이어지지 않는다
- 정책상 문제: "지침이 없으면 관광지를 표시하지 않는다" 가 제품의 **안전 주장**인 이상
  그 강제는 서버에 있어야 한다 (BAN003)
- Blocking Level: development_blocker

### D07-UNRESOLVED-008 열 노출·수중 활동이 판정에 쓰이지 않는다 (신설)

- 사실: `avoidHeat`·`noWater` 는 병원이 발행하고 게이트웨이를 통과해 `/plan` 화면에 배지로
  뜬다. 그러나 조건 객체로 옮기는 단계에서 빠져 **안전 게이트가 읽지 않는다**
- 결과: 병원이 "사우나·찜질 금지" 를 발행해도 찜질방이 후보에서 빠지지 않는다
- 정책 판단: 적용되지 않는 조건을 적용되는 것처럼 보여주는 것은 **아예 안 보여주는 것보다
  나쁘다** — 사용자가 앱이 걸러줬다고 믿는다 (BAN007)
- 선택지: (a) 후보 게이트 사유 코드로 승격 (b) 표시 전용임을 화면에서 구분
- Blocking Level: development_blocker

### D07-UNRESOLVED-009 안전 임계값의 임상 근거 부재 (신설)

- 사실: 코드에 박힌 값 넷 — **조건 유효 24시간 · 최소 활동 45분 · 환자 가산 10분 ·
  교통 변동 25%** — 이 **전부 설계값이며 임상 승인을 받은 적이 없다.** 코드 주석이
  스스로 "현장 측정 후 보정 필요" 라고 적었다
- 포함된 결함: **조건 최신성 24시간 vs 계획 유효기간 72시간 충돌.** 30시간 전 발행된
  계획(유효기간 내)으로 판정하면 `NO_TOURISM` · `STALE_HOSPITAL_CONDITION` 이 나온다.
  **사용자에게는 "유효기간 내" 로 보이는데 아무것도 추천되지 않는다**
- 선택지: (a) 유효기간을 24시간에 맞춘다 (b) 최신성 한도를 계획 유효기간에 위임한다
  (c) 두 기준을 분리하고 화면에 각각 표시한다
- 결정 주체: **의료 자문** — 조건이 며칠까지 유효한가는 의학적 판단이다 · \[지정필요\]
- 기한: **09.07 기능 동결 전**
- Blocking Level: release_blocker

### D07-UNRESOLVED-010 감사 기록 보관 주체 (신설)

- 질문: 누가 언제 계획을 발행·조회했는지의 감사 기록을 **병원이 보관**하는 것으로
  확정할 것인가?
- 근거: 감사 로그는 본질적으로 저장이다. SafeHour 서버가 보관하면 "서버 무저장" 원칙이
  조용히 깨진다 (`docs/PRODUCT_DEFINITION.md` §6.3)
- Blocking Level: release_blocker

### D07-UNRESOLVED-011 이용약관·법적 면책 조항 부재 (신설)

- 사실: **이용약관이 없다.** `/privacy` 는 데이터 처리와 면책 고지이며 계약 조항이 아니다
- 질문: 공모전 제출 범위에 약관이 필요한가? 화면 면책 문구로 충분한가, 별도 조항이 필요한가?
- 함께: **의존성 라이선스 검토 미수행** (`npm run audit` High 이상 0건은 취약점 기준이지
  라이선스 기준이 아니다)
- 결정 주체: 법무 자문 · \[지정필요\]
- Blocking Level: release_blocker

### D07-UNRESOLVED-012 영문 안전 문구 검수 미수행 (신설)

- 사실: AX-209 로 **전 화면 영문**이 생겼는데 **의미 동등성 검수가 0건**이다

  영어 "Companion **may** take a nearby activity"(허가)로 나가 **환자 가부를 말하지 않는다.**
  외국인 환자가 같이 나갈 수 있다

- 기한: 검수자 지정 **08.30** (W2)
- Blocking Level: release_blocker

### D07-UNRESOLVED-013 지침 변경 → 재판정 배선 미연결 (신설)

- 사실: 만료·철회는 3시점 감시가 붙었으나 **"병원이 지침을 바꿨다" 는 신호는 어디에도

- 정책 영향: BAN008(알림만 하는 재계산 금지)의 강제가 이 배선 없이는 불완전하다
- 함께 확인할 것: 기준점 출처 enum 이름 `USER_SELECTED_FIXED` 가 병원 발행 기준점을
  가리키게 된 불일치 — 명칭 정리 여부 \[확인필요\]
- Blocking Level: development_blocker

### D07-UNRESOLVED-014 판정 사유 코드의 개인정보 성격 (신설)

- 질문: `FASTING_REQUIRED`·`OUTING_FORBIDDEN`·`RISK_SIGNAL`·`PATIENT_RECALLED` 같은
  사유 코드를 운영 로그에 남기는 것이 적절한가?
- 남기는 근거: POL001 이 위반 탐지 수단으로 지정했고, 가장 거친 표현이며, 세션 식별자가

- 대안(받아들여지지 않을 경우): 차단 사유를 단일 코드(`BLOCKED`)로 뭉갠다. 대가는
  POL001 탐지 정밀도 하락이며 그 대가를 함께 기록해야 한다
- 결정 주체: 개인정보 담당자 · \[지정필요\] (`docs/SIGNOFF_CHECKLIST.md` 2.10)
