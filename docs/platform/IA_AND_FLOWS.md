# 화면 구조와 흐름 (IA & Flows)

- 기준일: 2026-09-18
- 작업 ID: AX-301
- 연결: `PRODUCT_DEFINITION_V3.md`, `ITINERARY_RULES.md`, ADR-0006(일정 엔진·단일 외출 퇴역),
  ADR-0009(저장·로그인·보호자), ADR-0010(지도·긴급·알림), ADR-0011(병원 지침 v2)

이 문서는 어떤 화면이 있고, 사용자가 어떤 순서로 지나가며, 날짜와 상태를 화면에 어떻게 보여주는지를 정리한다.
화면 문구는 문구 사전이 정본이다. 여기서는 표시 원칙과 흐름만 다룬다.

---

## 1. 화면 목록

### 1.1 경로

| 경로 | 화면 | 비고 |
| --- | --- | --- |
| `/` | 시작 — 언어 선택, 고지 3종, 로그인 유도 | 기존 경로, 새 디자인 |
| `/login` | 로그인 | 기존 |
| `/onboarding` | 체류 설정(단계형) | 신규 |
| `/conditions` | 조건 기간 목록·입력·수정, 동의 | 신규 |
| `/link` | 병원 코드 연결 | 기존, 지침 계약 v2 |
| `/guide` | 병원 안내(연동했을 때) | 기존 |
| `/today` | **홈** — 오늘 상태, 매일 확인, 다음 일정, 복귀 마감, 변경 알림 | 기존 경로, 내용 교체 |
| `/trip` | 전체 일정 — 날짜 목록과 날짜별 상태 | 신규 |
| `/trip/[date]` | 하루 일정 — 타임라인, 환자/보호자 탭, 편집, 전후 비교, 복귀 시트 | 신규. `date`는 `YYYY-MM-DD` |
| `/place/[candidateId]` | 장소 상세 | 기존 |
| `/cards` | 한국어 안내 카드 | 신규 |
| `/emergency` | 긴급 연락 | 신규 |
| `/guardian` | 보호자 링크 만들기 | 신규 |
| `/g` | 보호자 링크 열기(PIN 입력) | 신규 |
| `/more` | 더보기 — 카드·보호자·설정·고지 모음 | 신규 |
| `/help` | 도움말: 앱이 하는 일·홈 화면에 추가하기(`#install`)·알림 문제·자주 묻는 질문·문의(환경변수가 있을 때만). 더보기 '정보' 묶음의 첫 행 | 신규 |
| `/settings` | 언어·알림·동의 철회·데이터 삭제 | 신규 |
| `/privacy` | 개인정보·면책 고지 | 기존, 내용 갱신 |
| `/design-board` | 디자인 시안 보드 | 신규. 내비에 노출하지 않는다 |

### 1.2 고정 요소

- **하단 내비는 5개다**: 오늘(`/today`) · 일정(`/trip`) · 조건(`/conditions`) · 더보기(`/more`) · 긴급(`/emergency`).
  긴급 칸은 긴급 전용 색 + 채운 알약 + 문구 세 겹으로 다른 칸과 구분한다(색 단독 금지).
  칸이 좁아(320px 에서 64px) 보이는 글자는 짧게 쓰지만, 읽히는 이름은 '긴급 연락'으로 온전히 둔다.
- **긴급 연락은 모든 화면에서 바닥에 붙어 있다.** 로그인 전, 로그인 만료, 오프라인 상태에서도 보인다.
  내비가 있으면 다섯째 칸이, 내비가 없는 화면(로그인 전 흐름·보호자 열기)은 하단 긴급 바가 그 역할을 한다.
  **떠 있는 버튼으로 두지 않는다** — 본문 위에 얹히면 누를 수 있는 요소를 덮는다(측정: 주 버튼 131×31px, 언어 칸 41%, 입력 라벨 37%, '다음' 버튼).
  누르면 `/emergency`로 간다.
- 보기 전용 상태일 때는 화면에 '보기 전용 — 로그인이 필요합니다'를 표시한다(5.3절).

### 1.3 퇴역하는 화면

- 기존 단일 외출 흐름의 `/plan`과 `/result`는 퇴역하고, 들어오면 `/today`로 보낸다.
- 단일 외출 API(`POST /api/recommend`, `POST /api/recalculate`, `POST /api/today`)도 함께 퇴역한다.
- 퇴역 이유는 두 가지다. 판정 경로가 두 벌이 되면 결과가 어긋나는데, 이것이 이 제품에서 가장 위험한 결함이다.
  그리고 운영자가 추천 형태로 장소 목록 대신 하루 일정 자동 생성을 골랐다(ADR-0006).

## 2. 기본 흐름

### 2.1 처음 쓰는 사람

```
/ → /login → /onboarding → /conditions(동의 → 본인 체크 기간 입력 또는 /link)
  → 전체 일정 생성 → /today
```

1. **시작(`/`)** — 언어를 고르고 고지 3종을 본 뒤 로그인으로 간다.
2. **로그인(`/login`)** — 구글 또는 카카오. 모든 기능은 로그인 후에 쓴다.
3. **체류 설정(`/onboarding`)** — 입·출국 일시와 공항, 날짜별 숙소(도로명주소 검색), 병원과 병원 일정,
   동반 보호자 여부, 관심사와 이동 강도를 단계별로 입력한다.
   `수술·시술` 일정이 하나도 없으면 저장할 수 없다.
4. **조건(`/conditions`)** — 먼저 민감정보 동의를 받는다. 그다음 본인 체크로 조건 기간을 넣거나,
   `/link`에서 병원 코드를 연결한다.
   - 동의를 거부하면 수술 후 경계일 전 자유일 일정만 쓸 수 있다.
5. **전체 일정 생성** — 체류 설정을 마치면 전체 일정을 한 번 만든다.
   조건을 아직 넣지 않았다면 경계일 이후 날짜는 `NEEDS_INPUT`으로 두고 나머지만 만든다.
6. **오늘(`/today`)** — 이후의 출발점이다.

### 2.2 매일 쓰는 흐름

```
앱 열기 → (필요하면) 매일 확인 → /today 확인 → /trip/[date]에서 일정 보기·편집
       → 장소 상세 → 지도 앱으로 길찾기(목적지만)
```

앱을 열 때와 화면으로 돌아올 때 다음을 확인한다.

- 출국일로부터 7일이 지났으면 그 계정의 체류 데이터를 지운다(자동 삭제).
- 연동한 병원이 있으면 저장된 연결 코드로 지침을 다시 받아 버전 변경, 철회, 만료를 확인한다.
- 단기예보 범위(오늘~모레) 날짜의 기상을 반영한다.
- 오늘이 매일 확인 대상이면 확인 카드를 띄운다(4장).

### 2.3 변화가 생겼을 때

```
변화 감지 → 영향받은 날짜만 재계획(게이트 1단계부터) → 전후 비교 기록 → '변경됨' 표시
         → 사용자가 전후 비교 시트로 확인 → (원하면) 대체된 자리를 다른 후보로 교체
```

- 변화 원천: 체류·숙소·병원 일정·보호자·관심사·강도 수정, 조건 기간 추가·수정·삭제와 동의 철회,
  매일 확인의 '바뀌었어요', 기상, 연동 지침의 버전 변경·철회·만료, 데모 사건, 언어 변경.
- 언어 변경은 예외다. 오늘 이후 날짜의 **표시만 새 언어로 다시 쓴다.** 재판정하지 않고,
  정거장·시각·상태가 그대로이며, 전후 비교를 만들지 않는다.
- '변경됨'은 사용자가 볼 때까지 남는다.

### 2.4 일정 편집

| 동작 | 흐름 |
| --- | --- |
| 교체 | 정거장 선택 → 같은 시간 자리에 넣을 수 있는 후보 최대 5개 → 고르면 외출 전체 재검증 → 통과하면 '고정'으로 표시, 통과하지 못하면 이유를 보여주고 넣지 않음 |
| 삭제 | 정거장 삭제 → 외출 시각 다시 계산. 식사 칸 식당을 지우면 그 칸은 '비움'으로 두고 자동으로 다시 채우지 않음 |
| 다시 만들기 | 범위 선택('이 날짜' 또는 '오늘 이후 전체') → 확인 대화 → 고정·삭제 기록을 지우고 새로 만듦 |

지난 날짜와, 매일 확인 전의 오늘은 편집할 수 없다.

### 2.5 보호자

- **같은 기기**: 하루 일정 화면의 환자/보호자 탭으로 본다.
- **링크 만들기(`/guardian`)**: 공유 동의(담기는 항목 목록 표시) → 6자리 PIN 설정 → 링크 생성·공유.
  - 링크를 만들 때마다 동의를 받는다.
  - PIN은 링크와 따로 알려주라고 안내한다.
  - 완벽한 보호가 아니라 우연한 열람을 막는 수준이라는 점을 화면에 밝힌다.
- **링크 열기(`/g`)**: 로그인 → PIN 입력 → 내용 복호화 → 기기에 저장 → 보호자 일정 보기.
  - 로그인하지 않은 채 링크를 열면, 로그인 왕복 동안 암호문만 탭 저장소에 잠시 둔다.
    가져오기가 끝나거나 1시간이 지나면 지운다.
  - PIN을 5회 연속 틀리면 그 기기에서 그 링크를 1시간 잠근다.
  - 사본은 자동으로 갱신되지 않는다. 보호자 화면 상단에 '○월 ○일 ○시 기준'을 표시하고,
    환자 일정이 바뀌면 환자 화면에 '보호자 링크 다시 보내기'를 안내한다.
  - 출국일 23:59가 지나면 표시하지 않고 삭제한다.

### 2.6 병원 연동(데모)

```
/conditions → (동의) → /link에서 코드 입력(DEMO-A / DEMO-B / DEMO-C)
  → 체류의 기존 병원 중 하나를 고르거나 새 병원으로 추가 → 지침 사본 저장 → 재계획
```

- '병원 연동 데모' 배지를 늘 표시한다.
- 지침의 병원 일정은 연결한 병원의 일정으로 더한다. 같은 날짜·시각·유형의 일정이 이미 있으면 더하지 않는다.
- 안내문은 `/guide`에서 원문 그대로 보여준다. 번역·요약·편집하지 않는다.

### 2.7 동의 철회와 데이터 삭제

- **동의 철회(`/settings`)**: 본인 체크 기간과 연동 지침 사본을 지운다 → 해당 날짜가
  `NEEDS_INPUT`(`SENSITIVE_CONSENT_REQUIRED`)이 된다 → 재계획한다.
- **이 기기에서 내 정보 지우기**: 모든 계정 이름공간, 보호자 사본, 알림 예약, AI 문장 캐시,
  언어 외 설정을 지우고 로그아웃한다.

## 3. 날짜와 상태를 보여주는 원칙

하루 일정에는 두 가지 값이 붙는다. **날짜 분류**(`coverage`)는 그날 일정을 어떤 조건으로 만들었는지,
**날짜 상태**(`dayState`)는 그 결과 외출이 어떻게 나왔는지를 말한다.

### 3.1 날짜 분류 (`coverage`)

| 분류 | 한국어 이름 | 조건 | 화면에서 |
| --- | --- | --- | --- |
| `FREE` | 자유일 | 수술 후 경계일 전이고 적용되는 기간이 없음 | 제한 없이 만든 일정. 회복기 가산 버퍼 없음 |
| `DECLARED_FREE` | 제한 없음 선언일 | 적용되는 기간이 모두 제한 없음 기간 | '본인 체크: 제한 없음'을 표시. 매일 확인 대상 |
| `RESTRICTED` | 제한일 | 적용되는 기간이 있고 합성 결과 외출이 `FORBIDDEN`이 아님 | 적용 조건과 출처를 함께 표시 |
| `REST_DAY` | 휴식일 | 합성 결과 외출이 `FORBIDDEN` | 환자 외출 없음. 병원 일정과 보호자 일정만 |
| `NEEDS_INPUT` | 입력 필요 | 경계일 이후인데 적용되는 기간이 없음, 또는 숙소 없음 | 일정 없음. 사유와 입력할 곳을 안내 |

`NEEDS_INPUT`에는 사유가 하나 붙는다.

| 사유 | 조건 | 안내할 곳 |
| --- | --- | --- |
| `SENSITIVE_CONSENT_REQUIRED` | 민감정보 동의가 없음 | 조건 화면의 동의 단계 |
| `HOSPITAL_PLAN_EXPIRED_INPUT_REQUIRED` | 연동 지침이 만료된 날짜 | "병원에서 새 지침을 받거나 본인 체크로 입력하세요" |
| `LODGING_REQUIRED` | 그날 묵을 숙소가 없음 | 체류 설정의 숙소 구간 |
| `CONDITION_INPUT_REQUIRED` | 그 밖의 경우 | 조건 화면의 기간 입력 |

병원 값을 본인 체크로 자동으로 옮기지 않는다. 사용자가 새 지침을 받거나 직접 입력해야 한다.

### 3.2 날짜 상태 (`dayState`)

기존 4상태를 그대로 쓴다. 앞쪽일수록 보수적이다: `NO_TOURISM` < `STANDBY` < `SPLIT_NEARBY` < `TOGETHER`.

| 상태 | 조건 |
| --- | --- |
| `TOGETHER` | 환자 외출이 1개 이상 |
| `SPLIT_NEARBY` | 환자 외출은 없고 보호자 외출만 있음 |
| `STANDBY` | 외출 가능 구간은 있는데 통과한 후보가 없음(`NO_CANDIDATE`). 오늘 날짜의 매일 확인 대기·병원 중요 안내 미확인도 이 상태로 덧씌운다(4장) |
| `NO_TOURISM` | 그 밖에 외출이 하나도 없음(`REST_DAY`, `NEEDS_INPUT`, 동행 필수 미충족, 서비스 중단 등) |

### 3.3 사유 코드 표시 원칙

- **사유 코드는 상태와 늘 함께 보여준다.** 상태만 보여주고 이유를 숨기지 않는다.
- **안전 문구**(상태 메시지, 사유, 고지, 복귀 안내)는 선택 언어와 한국어를 함께 보여준다.
  - 선택 언어가 `ko`이면 한국어+영어다.
  - `ja`·`zh`는 안전 문구 검수 스위치가 켜지기 전까지 영어+한국어로 보여준다.
- **상태는 색만으로 구분하지 않는다.** 문구와 아이콘을 함께 쓴다.
- **`NO_TOURISM`은 오류 스타일로 그리지 않는다.** 외출이 없는 것은 정상 결과다.
- **적용된 조건 값 옆에 출처를 붙인다**: '병원 발행' / '본인 체크' / '기본값 적용'.
- **출처 영역을 시각적으로 나눈다**: 병원 발행 / 본인 체크 / SafeHour 판정·추정 / 관광공사 원문 / AI 소개.
- **불확실한 것은 표시로 드러낸다.**

| 표시 | 붙는 경우 |
| --- | --- |
| 추정 | 모든 이동 시간, 식이 판단 결과 |
| 기본값 적용 | '모르겠음'에 엄격한 기본값을 쓴 항목 |
| 운영 확인 필요 | 휴무 근거가 없어 열려 있다고 단정할 수 없는 장소 |
| 번역 필요 | 선택 언어·영문 원문이 없어 국문을 보여주는 장소 |
| 주문 카드 | 뜨거운 음식·딱딱한 음식을 피해야 하는 날의 식당(한국어 주문 카드 연결) |
| 예상 종료 | 종료 시각을 입력하지 않은 병원 일정 |
| 병원 연동 데모 | 데모 병원과 연결된 상태(상시 표시) |
| 보기 전용 | 로그인 만료·오프라인에서 보는 화면 |

### 3.4 이번에 새로 쓰는 사유 코드

| 코드 | 뜻 |
| --- | --- |
| `OUTSIDE_STAY_WINDOW` | 입국일 일정 시작 전이거나 출국일 일정 마감 후 |
| `LODGING_REQUIRED` | 그날 숙소가 없음 |
| `CONDITION_INPUT_REQUIRED` | 경계일 이후인데 적용되는 조건 기간이 없음 |
| `SENSITIVE_CONSENT_REQUIRED` | 민감정보 동의가 없음 |
| `HOSPITAL_PLAN_EXPIRED_INPUT_REQUIRED` | 연동 지침이 만료되어 그날을 덮지 않음 |
| `DAILY_CHECK_PENDING` | 오늘 매일 확인을 아직 하지 않음 |
| `HEAT_EXPOSURE` | 열 노출 단서가 있는 장소(열을 피해야 하는 날) |
| `WATER_ACTIVITY` | 물 활동 단서가 있는 장소(물에 들어가면 안 되는 날) |
| `DIET_RESTRICTED` | 식이 제한에 걸리는 식당 |
| `MENU_UNKNOWN` | 매운 음식·날음식을 피해야 하는데 판단할 메뉴 단서가 없는 식당 |

- 기존 `MEDICATION_WINDOW`는 '숙소에서 복용' 복약 마감을 만들 때 실제로 내보낸다.
- 기존 `STALE_HOSPITAL_CONDITION`은 일정 엔진에서 쓰지 않는다(ADR-0011).
- 그 밖에 이 문서에 나오는 기존 코드(`NO_CANDIDATE`, `ESCORT_REQUIRED`, `CONFLICTING_CONDITION`,
  `PLAN_UNCONFIRMED_UPDATE`, `PATIENT_RECALLED`, `RISK_SIGNAL`, `SERVICE_PAUSED`, `CLOSED`,
  `WEATHER_BLOCKED`, `FASTING_REQUIRED`, `DEPARTURE_WINDOW_TOO_SHORT`, `WALK_LIMIT_EXCEEDED`,
  `TRAVEL_LIMIT_EXCEEDED`)는 뜻을 바꾸지 않고 그대로 쓴다.

## 4. 매일 확인과 오늘 게이트 덧씌우기

### 4.1 매일 확인

- **대상**: 오늘이 체류 기간 안이고, 오늘을 덮는 본인 체크 기간이 하나 이상인 날.
  `DECLARED_FREE` 날짜도 포함한다. 미래 날짜는 대상이 아니다.
- 그날 처음 `/today`에 들어오면 "오늘 조건이 그대로인가요?"를 띄운다.
  오늘 적용 항목 요약과 동반 보호자 여부를 함께 보여준다.

```
[오늘 조건이 그대로인가요?]
   ├─ '그대로예요' → 오늘 확인 완료(그날 자정까지 유지)
   └─ '바뀌었어요' → 조건 편집 → 저장 → 재계획 → 확인 완료
```

- **확인 전 화면**
  - 오늘 일정은 보여주되 '확인 필요'를 상단에 고정한다.
  - 길찾기와 장소 이동 동작을 비활성화한다.
  - 오늘 편집도 할 수 없다.
  - 오늘 상태는 `STANDBY`, 사유는 `DAILY_CHECK_PENDING`이다.
- **병원 기간만 덮는 날**은 매일 확인을 하지 않는다. 대신 앱을 열 때 연동 지침을 다시 받아
  버전 변경, 철회, 만료를 확인한다. 확인하지 않은 중요 안내가 있으면 `STANDBY`,
  사유 `PLAN_UNCONFIRMED_UPDATE`다.
  - 같은 안내문이라도 내용이 바뀌어 수정 시각이 달라지면 확인이 풀린다.

### 4.2 오늘 게이트 덧씌우기

매일 확인 대기와 병원 중요 안내 미확인은 **저장된 확정 일정을 바꾸지 않는다.**
오늘 일정을 보여주는 순간에만 덧씌운다.

| | 저장된 확정 일정 | 화면에 보이는 오늘 |
| --- | --- | --- |
| 확인 전 | 그대로 | `dayState`=`STANDBY`, 사유 추가, 길찾기·이동 동작 비활성 |
| 확인 후 | 그대로 | 덧씌우기만 사라지고 저장된 일정이 보인다 |

- 확인 과정에서 조건이 바뀌었다면 재계획은 따로 일어난다.
- 이렇게 나눈 이유: '변화가 없으면 확정 일정을 그대로 쓴다'는 결정과
  '확인 전에는 외출 동작을 막는다'는 결정을 함께 지키기 위해서다(ADR-0006).

## 5. 빈 상태 · 오류 상태 · 보기 전용 상태

### 5.1 빈 상태 — 정상 결과로 보여준다

일정이 비는 것은 대부분 규칙이 정상으로 동작한 결과다. 오류처럼 그리지 않고, 이유와 할 수 있는 일을 보여준다.

| 상황 | 보여줄 것 |
| --- | --- |
| 체류 설정 전 | 아직 일정이 없다. 전체 일정은 체류 설정을 마친 뒤 한 번 만들어진다(2.1절) |
| `NEEDS_INPUT` 날짜 | 사유(3.1절)와 입력할 곳 |
| `REST_DAY` | 환자 외출 없음. 병원 일정과(조건이 맞으면) 보호자 일정 |
| `STANDBY` + `NO_CANDIDATE` | 외출 가능 구간은 있지만 조건을 통과한 장소가 없음 |
| 동행 필수인데 보호자 없음 | 환자 외출 없음, 사유 `ESCORT_REQUIRED` |
| 보호자 탭이 비어 있음 | 동행 필수라서 만들 수 없으면 잠금 표시와 이유. 자유일·제한 없음 선언일에는 보호자가 환자와 함께 다니므로 단독 외출이 없다 |
| 식사 칸 `NONE_AVAILABLE` | '추천 장소 없음'과 사유. 다른 정거장으로 채우지 않는다 |
| 식사 칸 `CLEARED` | 사용자가 비운 칸. 자동으로 다시 채우지 않는다 |
| 입국 전·출국 마감 후 시간 | 일정을 만들지 않는다. 사유 `OUTSIDE_STAY_WINDOW` |
| 복약 시각을 모름 | 복약 마감을 만들지 않고 '복약 시각 미입력' 경고 |
| 장소 이미지 없음 | 유형별 일러스트 |

### 5.2 오류 상태 — 막고 이유를 말한다

| 상황 | 동작 |
| --- | --- |
| 체류 저장 거부 | 출국일이 입국일보다 빠름, 45박 초과, 숙소 구간 날짜 겹침, `수술·시술` 일정 없음 → `SAFEHOUR_STAY_INVALID`와 문제 필드를 필드별 문구로 보여준다 |
| 조건 기간 저장 거부 | 필수 항목(외출 허용 여부, 복귀 시각)이 비어 있으면 저장하지 않는다 |
| 한 병원 기간 안의 모순 | 동행 필수와 보호자 분리 허용이 함께 오면 그 기간의 날짜를 `CONFLICTING_CONDITION`으로 막는다. 본인 체크 화면은 이런 입력이 애초에 만들어지지 않게 한다 |
| 로그인 세션 없음 | 서버가 401 `SAFEHOUR_AUTH_REQUIRED`를 돌려준다. 보기 전용으로 볼 수 있는 화면은 5.3절을 따른다 |
| 주소 검색 키 없음 | 503 `SAFEHOUR_ADDRESS_UNAVAILABLE`. 데모 로그인 모드에서는 고정 데모 주소를 '데모 주소'로 보여준다 |
| 병원 지침 거부 | 형식이 어긋나거나, v1 지침이거나, 기간 날짜가 역순이면 지침 전체를 거부한다 |
| 교체 불가 | 고른 후보를 넣으면 외출 검증(복귀 계산, 보행 누적, 이동 한도)을 통과하지 못할 때. 넣지 않고 이유를 보여준다 |
| 전후 비교가 빔 | 변화가 필요한데 전후 비교가 비어 있으면 실패로 처리한다(알림만 하는 재계산 금지) |
| 기상 조회 실패 | '확인 불가'로 두고 판정에 반영하지 않는다 |
| 선택 언어 관광 데이터 없음 | 영문으로 대체하고, 영문도 없으면 국문과 '번역 필요'를 보여준다 |
| 추천 중단 스위치 | 모든 날짜가 정거장 없이 `NO_TOURISM` + `SERVICE_PAUSED`. 긴급 연락, 카드, 조건 화면은 계속 동작한다 |
| 보호자 PIN 5회 오류 | 그 기기에서 그 링크를 1시간 잠근다 |

### 5.3 보기 전용 상태

로그인이 만료됐거나 오프라인일 때는 다음만 **보기 전용**으로 보여준다.

- 긴급 연락
- 한국어 카드
- 오늘·내일 일정과 복귀 마감(이 기기에 마지막으로 로그인한 계정의 사본)
- 보호자 사본의 안전 정보
- 개인정보 고지

보기 전용일 때의 규칙은 다음과 같다.

- 화면에 '보기 전용 — 로그인이 필요합니다'를 표시한다.
- 생성·편집·연동·공유를 막는다.
- 앱 셸과 위 화면은 오프라인에서 동작한다. API 응답은 서비스 워커 캐시에 넣지 않는다.

## 6. 즉시 복귀

```
환자 호출(데모 사건) / 외출 중 지침 철회 / 외출 중 지침 만료
  → 오늘 남은 일정 비움 → returnNow=true → 즉시 복귀 시트 자동 표시
```

- 이 동작은 끌 수 없다(기존 AX-220).
- 뒤로가기는 시트만 닫는다(기존 AX-011). 복귀 안내를 뒤로가기로 벗어날 수 없다.
- `returnNow`는 그날이 끝날 때까지 유지된다. 다음 경우에만 풀린다.
  - 날짜가 바뀜
  - 데모 사건 초기화(환자 호출이 원인일 때)
  - 유효한 지침이 다시 오늘을 덮음(철회·만료가 원인일 때)
- 데모 사건 `RISK_SIGNAL`은 즉시 복귀와 별개로, 오늘 남은 환자·보호자 외출을 비우고
  오늘을 `NO_TOURISM`(사유 `RISK_SIGNAL`)으로 만든다.
- 데모 사건 패널은 '병원 연동 데모' 모드에서만 보인다.
