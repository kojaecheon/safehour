# 일정 규칙과 조정 가능한 기본값

- 기준일: 2026-09-18 (코드 위치·단서 표·병원 일정 전 외출 규칙 갱신: 2026-09-20, AX-321)
- 작업 ID: AX-301
- 연결: `PRODUCT_DEFINITION_V3.md`, `IA_AND_FLOWS.md`, ADR-0005(조건 기간·합성),
  ADR-0006(일정 엔진), ADR-0011(병원 지침 v2·최신성)

이 문서는 체류 전체 하루 일정을 만드는 규칙을 사람이 읽을 수 있게 정리한 것이다.
체류(1장)부터 사용자 편집(10장)까지 규칙을 차례로 적고, 11장에 조정 가능한 기본값을 모았다.

**읽기 전에 알아 둘 것**

- 모든 시각은 한국 표준시(KST)다.
- '조정 가능'이라고 적은 값은 11장의 기본값이며, 설정 한곳에서 바꿀 수 있어야 한다.
- **'의료진 검토' 표시가 붙은 값은 사람 검토 전 임시값이다.** 의료진이 확인하기 전까지 이 값으로 동작하며,
  확인 없이 더 느슨하게 바꾸지 않는다.
- 조정 가능한 **숫자 기본값은 코드의 한 파일**(`src/stay/defaults.js`)에, **단서 목록**(열·물·매운 음식·날음식·주점·카페,
  관심사 매핑)은 **관광 후보 모듈의 상수 한곳**(`src/tour-api/cues.js`)에 둔다. 이 문서의 11장 표와 값이 같아야 한다.

## 1. 체류

- 계정 하나, 기기 하나에 **활성 체류는 하나**다. 새 여행을 시작하려면 현재 체류를 삭제한다.
- 필수 입력은 다음과 같다.

| 입력 | 내용 |
| --- | --- |
| 입국 | 날짜, 도착 시각, 공항(`ICN` 인천 또는 `GMP` 김포) |
| 출국 | 날짜, 출발 시각, 공항 |
| 동반 보호자 | 있음 또는 없음 |
| 숙소 구간 | 1개 이상 |
| 병원 일정 | `수술·시술` 유형 1개 이상 |
| 관심사 태그 | 0개 이상 |
| 이동 강도 | 느긋하게(`RELAXED`) 또는 보통(`NORMAL`) |

- 출국일이 입국일보다 빠르거나 체류가 **45박**(조정 가능)을 넘으면 저장을 거부한다.
- **입국일 일정 시작 시각** = 도착 시각 + 입국 수속 90분 + 공항→그날 숙소 이동 추정
- **출국일 일정 마감 시각** = 출발 시각 − 공항 도착 여유 3시간 − 그날 숙소→공항 이동 추정 − 여유 30분
  - 수속·도착 여유·출국 여유 값은 조정 가능하다.
- 출국일의 외출은 그날 숙소(짐이 있는 곳)로 돌아오는 것으로 계산한다.
- 입국일 시작 전과 출국일 마감 후에는 일정을 만들지 않는다. 사유는 `OUTSIDE_STAY_WINDOW`다.
- 동반 보호자 여부는 언제든 바꿀 수 있고, 바꾸면 재계획이 일어난다.
- **자동 삭제**: 출국일로부터 7일(조정 가능)이 지난 뒤 앱을 처음 여는 시점에 그 계정의 체류 데이터를 전부 지운다.
  - 지우는 것: 체류, 숙소, 병원, 조건, 일정, 동의 기록, 카드, 알림 예약, AI 문장 캐시
  - 화면 문구는 실제 동작 그대로 "출국 7일이 지난 뒤 앱을 처음 열 때 삭제됩니다"라고 쓴다.
    앱을 열지 않으면 지워지지 않으므로 "자동으로 삭제됩니다"라고 쓰지 않는다.

## 2. 숙소 구간

- 각 구간은 이름(사용자 입력, 최대 40자), 도로명주소 검색 결과(주소·좌표), 체크인 날짜, 체크아웃 날짜로 이루어진다.
- **날짜 D의 숙소**는 D일 밤을 묵는 숙소다(체크인 ≤ D < 체크아웃). 출국일의 숙소는 전날 밤 숙소다.
- 구간끼리 날짜가 겹치면 저장을 거부한다.
- 숙소가 정해지지 않은 날짜는 `NEEDS_INPUT`(사유 `LODGING_REQUIRED`)이고, 일정을 만들지 않는다.

## 3. 병원과 병원 일정

### 3.1 병원

- 병원은 여러 곳일 수 있다. 각 병원은 이름(최대 40자), 도로명주소(좌표), 전화(선택), 연동 여부를 가진다.
- 병원 목록, 검색 추천, 순위는 **보여주지 않는다.** 주소 검색은 사용자가 입력한 검색어로만 한다.

### 3.2 병원 일정

- 병원 일정은 병원, 유형, 날짜, 시작 시각, 종료 시각(선택)으로 이루어진다.
- 유형은 `PROCEDURE`(수술·시술) 또는 `VISIT`(진료·재진·실밥 제거 등)이다.
- 종료 시각이 없으면 `PROCEDURE`는 240분, `VISIT`는 90분으로 보고 화면에 '예상 종료'로 표시한다(조정 가능).

### 3.3 병원 일정 블록

- **블록** = [시작 − 숙소→병원 이동 − 도착 여유 10분, 종료 + 병원→숙소 이동]. 이 구간에는 외출을 만들지 않는다.
- **병원 일정 직전의 마지막 외출만 그 병원에서 끝난다** (2026-09-19 운영자 결정, 규칙 13-2).
  - 그 외출의 복귀 장소는 그 병원이고, 마감(`returnBy`)은 일정 시작 시각, 마감 이유는 `APPOINTMENT`다.
    병원에 일찍 닿아 기다리지 않도록 마감에 맞춰 거꾸로 짠다.
  - 도착 여유 10분은 복귀 계산식에서 한 번만 더한다.
  - 이 경우 블록은 **일정 시작 시각**부터 시작한다. 숙소→병원 이동은 외출의 마지막 구간이 대신하므로 블록에 넣지 않는다.
  - 직전 외출이 없으면 블록은 위 식대로 '시작 − 이동 − 10분'부터다.
  - 45분 최소 창은 이렇게 정한 블록 시작까지로 계산한다.
- **같은 구간의 앞선 외출은 숙소로 돌아온다.** 이전 규칙대로면 오후 진료 전 점심 외출 뒤 병원에서 2시간 넘게 기다려야 했다.
  - 앞선 외출의 안전 마감은 '일정 시작 − 숙소→병원 이동 − 도착 여유 10분'이고 마감 이유는 `APPOINTMENT`다.
    마지막 외출의 계획상 출발 전까지 숙소에 돌아오도록 짜며, 병원 일정 블록과 겹치지 않는다.
  - 화면은 모든 외출에 **예상 귀가 시각**(`plannedReturnAt`)을 복귀 마감과 함께 보여준다(7.2절).
  - 구현: `src/engine/dayPlan.js`(병원에서 끝나는 창 — `planHospitalWindow`).

### 3.4 수술 후 경계일

- **수술 후 경계일** = 가장 이른 `PROCEDURE` 일정의 날짜.
- `PROCEDURE` 일정이 하나도 없으면 체류 설정을 저장할 수 없다.
  경계일을 빼먹으면 수술 뒤 날짜가 제한 없는 자유일로 만들어지기 때문이다.

## 4. 조건 기간

조건 기간은 **날짜 범위 하나에 적용되는 제한조건 묶음**이다.

- 출처는 `SELF`(본인 체크) 또는 `HOSPITAL`(병원 발행)이다.
- 시작일과 종료일은 둘 다 포함한다.
- 같은 날짜에 기간이 여러 개 겹쳐도 된다. 겹치면 5장 규칙으로 합성한다.
- `SELF` 기간은 **제한 없음 기간**(`noRestriction`)으로 저장할 수도 있다.
  모든 항목이 '아니오'이고 복귀 시각이 '병원이 정하지 않음'인 것과 같게 취급한다.
- 자유 서술 입력칸은 없다. 앱은 입력값을 해석하지 않고 그대로 적용한다.

### 4.1 본인 체크의 답 세 가지

| 답 | 적용 |
| --- | --- |
| 값 있음(예/값) | 그 값을 적용한다 |
| 아니오(병원이 그런 안내를 하지 않음) | 제한 없음 |
| 모르겠음 | 가장 엄격한 기본값을 적용하고 '기본값 적용'으로 표시한다 |

### 4.2 본인 체크 항목

'모르겠음' 기본값은 모두 조정 가능하고 의료진 검토 대상이다. **사람 검토 전 임시값**이다.

| 키 | 질문 | 답 | '모르겠음' | '모르겠음' 기본값 |
| --- | --- | --- | --- | --- |
| `outing` | 외출이 허용되나요? | `ALLOWED` / `INDOOR_ONLY` / `FORBIDDEN` | **불가**(필수) | — |
| `returnTime` | 몇 시까지 어디로 돌아와야 하나요? | 시각 `HH:MM` + 장소 `LODGING`(기본) 또는 `HOSPITAL`(등록된 병원 중 하나, 병원이 하나면 자동 선택), 또는 `NOT_SET`(병원이 정하지 않음) | **불가**(필수. `outing`이 `FORBIDDEN`이면 묻지 않음) | — |
| `walkLimit` | 걷는 시간 제한이 있나요? | 분(5–240) / 아니오 | 허용 | 외출 1회 누적 15분 |
| `travelLimit` | 한 번 이동하는 시간 제한이 있나요? | 분(5–240) / 아니오 | 허용 | 구간당 20분 |
| `avoidUv` | 자외선을 피해야 하나요? | 예 / 아니오 | 허용 | 예 |
| `avoidHeat` | 사우나·찜질 등 열을 피해야 하나요? | 예 / 아니오 | 허용 | 예 |
| `avoidWater` | 수영·온천 등 물에 들어가면 안 되나요? | 예 / 아니오 | 허용 | 예 |
| `escortRequired` | 보호자가 꼭 함께 있어야 하나요? | 예 / 아니오 | 허용 | 예 |
| `guardianMustStay` | 환자가 쉬는 동안 보호자가 곁을 지켜야 하나요?('아니오'면 보호자가 따로 나갈 수 있음) | 예 / 아니오. `escortRequired`가 '예'면 묻지 않고 '예'로 고정 | 허용 | 예(보호자 단독 외출 불가) |
| `mealRestriction` | 식사 제한(금식)이 있나요? | `UNTIL HH:MM`(그 시각까지) / `ALL_DAY` / 아니오 | 허용 | `ALL_DAY` |
| `diet.spicy` | 매운 음식을 피해야 하나요? | 예 / 아니오 | 허용 | 예 |
| `diet.alcohol` | 술을 피해야 하나요? | 예 / 아니오 | 허용 | 예 |
| `diet.hard` | 딱딱하거나 질긴 음식을 피해야 하나요? | 예 / 아니오 | 허용 | 예 |
| `diet.hot` | 뜨거운 음식을 피해야 하나요? | 예 / 아니오 | 허용 | 예 |
| `diet.raw` | 날음식(회 등)을 피해야 하나요? | 예 / 아니오 | 허용 | 예 |
| `medication` | 정해진 복약 시각이 있나요? | 시각 목록. 시각마다 '숙소에서 복용'(기본 예) 선택 / 아니오 | 허용 | 마감을 만들지 않고 '복약 시각 미입력' 경고를 표시 |

- 필수 항목이 비어 있으면 그 기간은 저장되지 않는다.
- `returnTime`이 `NOT_SET`이면 그날의 활동 종료 시각이 복귀 마감이 된다.
- 복귀 장소가 병원이면 반드시 등록된 병원 하나를 가리키고, 그 병원 좌표로 복귀를 계산한다.

### 4.3 병원 발행 기간

- 같은 항목 키를 쓰되, 답은 '값 있음' 또는 '아니오'뿐이다. '모르겠음'은 없다.
- 값은 그대로 적용한다.
- 한 병원 기간 안에서 `escortRequired`=예와 `guardianMustStay`=아니오(보호자 분리 허용)가 함께 오면,
  그 기간이 덮는 날짜를 `CONFLICTING_CONDITION`으로 막는다(기존 규칙).
- 본인 체크 화면은 이런 모순 입력이 애초에 만들어지지 않게 한다.

## 5. 날짜별 조건 합성과 날짜 분류

### 5.1 날짜 D에 적용되는 기간

- 민감정보 동의가 유효할 때의 `SELF` 기간
- 철회되지 않았고 `expiresAt`이 D의 활동 종료 시각보다 늦은 `HOSPITAL` 기간
  - 하루 도중에 만료되는 지침은 그날을 덮지 않는 것으로 본다(보수적 처리).

### 5.2 합성 순서

1. 각 기간의 '모르겠음'을 4.2절 기본값으로 바꾸고 '기본값 적용' 표시를 붙인다.
2. 항목마다 가장 엄격한 값을 고른다.

| 항목 | 엄격한 순서 |
| --- | --- |
| `outing` | `FORBIDDEN` > `INDOOR_ONLY` > `ALLOWED` |
| `returnTime` | 설정된 시각 중 가장 이른 것(그 시각의 장소 포함) > `NOT_SET` |
| `walkLimit`·`travelLimit` | 작은 값 > 제한 없음 |
| 예/아니오 항목 | 예 > 아니오(모든 예/아니오 항목은 '예'가 제한이다) |
| `mealRestriction` | `ALL_DAY` > 더 늦은 `UNTIL` > 더 이른 `UNTIL` > 없음 |
| `medication` | 모든 시각의 합집합. 같은 시각에 '숙소에서 복용'이 하나라도 예이면 예 |

3. 적용된 값마다 **출처**를 남긴다: 기간 id, 출처(`SELF`/`HOSPITAL`), 기본값 여부.
   화면에는 항목 옆에 '병원 발행' / '본인 체크' / '기본값 적용'으로 보여준다.

### 5.3 날짜 분류 (`coverage`)

| 분류 | 조건 | 일정 |
| --- | --- | --- |
| `FREE` | D < 수술 후 경계일이고 적용되는 기간이 없음 | 제한 없이 생성. 회복기 가산 버퍼 없음 |
| `DECLARED_FREE` | 적용되는 기간이 모두 제한 없음 기간 | `FREE`처럼 생성하되 '본인 체크: 제한 없음' 표시. 매일 확인 대상 |
| `RESTRICTED` | 적용되는 기간이 있고, 합성 결과 `outing`이 `FORBIDDEN`이 아님 | 합성 조건으로 생성 |
| `REST_DAY` | 합성 결과 `outing`이 `FORBIDDEN` | 환자 외출 없음. 병원 일정과 보호자 일정만 |
| `NEEDS_INPUT` | D ≥ 경계일인데 적용되는 기간이 없음, 또는 숙소 없음 | 일정 없음 |

`NEEDS_INPUT`의 사유

| 사유 | 조건 |
| --- | --- |
| `SENSITIVE_CONSENT_REQUIRED` | 동의가 없음 |
| `HOSPITAL_PLAN_EXPIRED_INPUT_REQUIRED` | 연동 지침이 만료된 날짜 |
| `LODGING_REQUIRED` | 숙소가 없음 |
| `CONDITION_INPUT_REQUIRED` | 그 밖의 경우 |

- 경계일 전 날짜에도 기간(예: 수술 전 금주·금식)을 넣을 수 있다. 넣으면 `RESTRICTED`다.
- 경계일 전 날짜를 덮던 병원 기간이 만료·철회됐고 다른 기간이 없으면 그 날짜는 `FREE`다(빈 날짜 규칙과 같다).
- 경계일 이후 날짜 중 만료된 병원 기간만 덮고 다른 유효 기간이 없는 날짜는
  `NEEDS_INPUT`(`HOSPITAL_PLAN_EXPIRED_INPUT_REQUIRED`)이다. 병원 값을 본인 체크로 자동으로 옮기지 않는다.
- 경계일 전 날짜의 `FREE` 일정은 병원 조건 게이트를 거치지 않는다.
  **이것은 "병원 조건이 없으면 추천하지 않는다" 원칙을 의도적으로 바꾼 것이다(ADR-0005).**
  나머지 후보 게이트(휴무, 관광 활동 아님, 기상, 데이터 신뢰)는 그대로 적용한다.

## 6. 매일 확인

- **대상**: 오늘이 체류 기간 안이고, 오늘을 덮는 `SELF` 기간이 하나 이상인 날. `DECLARED_FREE` 날짜도 포함한다.
- 그날 처음 `/today`에 들어오면 "오늘 조건이 그대로인가요?"를 띄운다. 오늘 적용 항목 요약과 동반 보호자 여부를 함께 보여준다.
  - '그대로예요' → 오늘이 확인 완료가 되고 그날 자정까지 유지된다.
  - '바뀌었어요' → 조건 편집으로 이동한다. 저장하면 재계획을 거친 뒤 확인 완료가 된다.
- **확인 전**: 오늘 일정은 보여주되 '확인 필요'를 상단에 고정하고, 길찾기와 장소 이동 동작을 비활성화한다.
  오늘 상태는 `STANDBY`, 사유는 `DAILY_CHECK_PENDING`이다.
- 미래 날짜는 매일 확인 대상이 아니다.
- `HOSPITAL` 기간만 덮는 날은 매일 확인을 하지 않는다. 대신 앱을 열 때 연동 지침을 다시 받아 버전 변경, 철회, 만료를 확인한다.
  확인하지 않은 중요 안내가 있으면 `STANDBY`, 사유 `PLAN_UNCONFIRMED_UPDATE`다(기존 규칙).
- **최신성**
  - 병원 지침은 "유효기간 안이고 철회되지 않음"이면 최신으로 본다. 기존 24시간 한도는 병원 기간에 적용하지 않는다(ADR-0011).
  - 본인 체크의 최신성은 매일 확인이 대신한다.

## 7. 하루 일정 생성

### 7.1 생성 규칙

| 규칙 | 내용 |
| --- | --- |
| 활동 시간 | 09:00–21:00(조정 가능). 입국일·출국일은 1장에 따라 자른다 |
| 고정 블록 | 병원 일정 블록(3.3절). '숙소에서 복용' 복약 시각은 숙소에 있어야 하는 마감이며, 복약 후 15분(조정 가능)이 지나야 다음 외출을 시작한다 |
| 외출 | 출발지(그날 숙소) → 정거장 1곳 이상 → 복귀 장소. 고정 블록과 마감 사이 빈 구간에만 만든다 |
| 외출 마감 | 7.2절 후보 중 가장 이른 시각. 마감을 만든 이유를 함께 기록한다 |
| 짧은 창 | 외출 가능 구간이 45분 미만이면 외출을 만들지 않는다(기존 `DEPARTURE_WINDOW_TOO_SHORT`) |
| 복귀 계산 | 외출 단위로 계산하며 7.3절 식을 만족해야 한다. 체류를 줄여 맞출 수 있지만 정거장당 15분 미만으로는 줄이지 않는다(기존) |
| 보행 누적 | `walkLimit`이 있는 날에만 적용한다. Σ정거장 보행 부담 추정 + Σ도보 구간 이동 ≤ `walkLimit`. 넘으면 정거장을 줄이거나 뺀다(`WALK_LIMIT_EXCEEDED`). 보행 부담 추정은 기존 유형별 추정과 무장애 보정을 쓴다 |
| 이동 한도 | `travelLimit`이 있는 날에만 적용한다. 출발, 정거장 사이, 복귀의 모든 구간 이동 추정 ≤ `travelLimit`(`TRAVEL_LIMIT_EXCEEDED`) |
| 이동수단 | `RESTRICTED` 날은 택시, 짧은 거리만 도보(기존 추정기). `FREE`·`DECLARED_FREE` 날은 대중교통 추정(직선거리×1.3 ÷ 20km/h + 대기·환승 10분, 짧은 거리는 도보, 조정 가능). 모든 이동 시간에 '추정' 표시 |
| 검색 반경 | 그날 숙소 기준. `RESTRICTED` 3km(기존), 자유일 10km(조정 가능) |
| 정거장 수 | 느긋하게(`RELAXED`) 외출당 최대 2곳·하루 최대 3곳, 보통(`NORMAL`) 외출당 3곳·하루 5곳(조정 가능) |
| 식사 칸 | 점심 11:30–13:30, 저녁 17:30–19:30(조정 가능). 외출이 식사 칸과 겹치고 식사가 가능하면(제한 없음, 또는 `UNTIL` 시각 이후) 그 외출의 식사 칸 시간에 식당 1곳을 넣는다. 통과한 식당이 없으면 '추천 장소 없음'과 사유를 보여준다. 이것은 정상 결과다. 식사 칸에는 카페·전통찻집을 넣지 않는다. 식사 정거장도 정거장 수 한도에 포함된다 |
| 순위 | 게이트를 통과한 후보만 대상이다. 관심사 일치 → 복귀 여유 → 보행 부담 → 같은 날 유형 다양성 순. 인기·광고·제휴 점수는 없다. **같은 입력이면 같은 결과**가 나와야 한다 |
| 중복 | 같은 장소를 체류 중 두 번 넣지 않는다. 사용자가 직접 고른 경우는 예외다 |
| 동행 필수 | `escortRequired`=예인데 동반 보호자가 없으면 그날 환자 외출은 없다(`ESCORT_REQUIRED`) |
| 보호자 일정 | 7.5절 |

### 7.2 외출 마감 후보와 기록할 이유

| 마감 후보 | 이유 |
| --- | --- |
| 합성된 `returnTime`(그 장소로 복귀) | `RETURN_TIME` |
| 다음 '숙소에서 복용' 복약 시각(숙소로 복귀) | `MEDICATION` |
| 다음 병원 일정의 시작 시각(그 병원으로 복귀) | `APPOINTMENT` |
| 활동 종료 | `DAY_END` |
| 출국일 마감 | `DEPARTURE` |

- '숙소에서 복용' 복약 시각이 마감을 만들면 사유 `MEDICATION_WINDOW`를 함께 기록한다.
  '숙소 밖 복용' 시각은 마감을 만들지 않는다.
- 외출마다 **안전 마감**(`returnBy`)과 별도로 **예상 귀가**(`plannedReturnAt`, "HH:MM")를 기록한다.
  예상 귀가 = 마지막 정거장 출발 + 복귀 구간 이동 추정이며 버퍼를 넣지 않는다. 모든 외출에서 `plannedReturnAt` ≤ `returnBy`다.
  한 구간에 외출이 여럿이면 앞 외출도 그 구간의 실제 마감(`returnBy`)을 그대로 갖고, 계획상 귀가는 `plannedReturnAt`이다.

### 7.3 복귀 계산식

```
출발 + 호출·대기 5분 + Σ이동 + Σ체류 + 교통 변동 25%×Σ이동
     + 도착 여유 10분 + (RESTRICTED 날의 환자만) 회복기 가산 10분  ≤  마감
```

### 7.4 날짜 상태 (`dayState`)

기존 4상태를 그대로 쓴다.

| 상태 | 조건 |
| --- | --- |
| `TOGETHER` | 환자 외출이 1개 이상 |
| `SPLIT_NEARBY` | 환자 외출은 없고 보호자 외출만 있음 |
| `STANDBY` | 외출 가능 구간은 있는데 통과한 후보가 없음(`NO_CANDIDATE`). 매일 확인 대기·확인 안 한 병원 중요 안내는 저장값이 아니라 오늘 표시 때 덧씌운다(9.5절) |
| `NO_TOURISM` | 그 밖에 외출이 하나도 없음(`REST_DAY`, `NEEDS_INPUT`, 동행 필수 미충족, 서비스 중단 등) |

사유 코드는 항상 함께 보여준다.

### 7.5 보호자 외출

- 네 조건이 **모두** 맞는 구간에만 보호자 외출을 만든다.
  1. 동반 보호자가 있음
  2. 합성 `guardianMustStay`=아니오
  3. 동행 필수가 아님
  4. 그 구간에 환자가 쉬는 중(`REST_DAY`, 또는 환자 외출이 없는 구간)
- 보호자 외출에는 환자 조건(보행·이동 한도, 식이, 자외선·열·물, 금식, 실내 전용)을 적용하지 않는다.
  기존 보호자 복귀 규칙(그날 환자 숙소로 돌아갈 수 있음)만 적용한다. 환자 조건이 아닌 게이트(관광 활동 아님,
  의료 시설, 휴무, 기상, 혼잡, 데이터 신뢰)는 그대로다(`src/engine/stopCandidate.js` `guardianGateCondition`).
- 동행 필수라서 만들 수 없으면 그 이유를 잠금 표시와 함께 보여준다.
- `FREE`·`DECLARED_FREE` 날에는 보호자 단독 외출을 만들지 않는다. 보호자는 환자와 함께 다닌다.
- 보호자 외출은 환자가 숙소에 있는 구간 안에서만 만들고, 환자 병원 일정 블록과 겹치지 않는다.
- 마감은 그 구간의 끝(환자의 다음 블록·외출 시작, 또는 활동 종료)이다.
- 이동은 택시 추정, 반경은 3km다.

## 8. 장소 후보와 필터

### 8.1 출처와 언어

- 출처는 관광공사 TourAPI뿐이다.
- 항상 국문과 무장애 정보를 조회하고, 선택 언어가 `en`·`ja`·`zh`이면 그 언어 서비스를 더한다.
  선택 언어가 `ko`이면 다른 언어를 조회하지 않는다.
- 선택 언어 서비스가 없거나(키 미신청 포함) 실패하면 영문으로 대체한다.
  영문도 없으면 국문을 보여주고 '번역 필요'를 표시한다(기존).
- 언어 간 매칭은 같은 `contentId`이거나, 같은 유형이면서 20m 이내일 때만 한다. 제목 유사도로는 매칭하지 않는다(기존).

### 8.2 호출 방식

- **숙소 기준점과 반경 조합마다 한 번** 목록을 조회하고 캐시를 쓴다. 날짜마다 반복 조회하지 않는다.
- 상세(개요·운영·이미지·메뉴) 보강은 일정에 들어갈 후보와 교체 후보에만 한다. 예외가 하나 있다: 식사 칸이 비어 있는 날은
  '메뉴 모름'만으로 빠진 식당 가운데 숙소에서 가까운 몇 곳의 상세도 확인해 그 칸을 채울 수 있는지 다시 판정한다.
  오늘 이후 날짜만 본다. 보강 상한은 배치된 정거장의 보강과 함께 쓴다. 숫자는 `lib/server/itinerary-service.js`에 있다:
  한 번에 6곳, 다시 판정 2회, 요청 하나의 보강 상한 60건(2026-11-12 코드에 맞춰 적음).

### 8.3 후보 게이트

| 게이트 | 규칙 |
| --- | --- |
| 관광 활동 아님 | 숙박은 제외한다(기존) |
| 휴무 | 기존 '닫힘 근거만 읽기' 규칙을 **그 일정 날짜 기준**으로 적용한다. 정기 휴무 요일이 그 날짜 요일과 정확히 맞거나, 행사 기간 밖이면 제외한다(`CLOSED`). 열려 있다고 단정하지 않고 '운영 확인 필요'로 표시한다 |
| 실내 전용·자외선·기상 | 기존 게이트를 그대로 쓴다. 실내 여부를 모르는 후보는 실내 전용이거나 기상 악화일 때 제외한다 |
| 열 노출(`avoidHeat`=예) | 유형·이름 단서(사우나, 찜질, 스파, 온천, 한증 등)가 있는 장소를 제외한다(`HEAT_EXPOSURE`) |
| 물(`avoidWater`=예) | 수영장, 워터파크, 온천, 수상레저 등 단서가 있는 장소를 제외한다(`WATER_ACTIVITY`) |

- 열·물 단서 목록은 조정 가능하다. 단서가 없으면 해당 노출이 없는 것으로 본다.

### 8.4 식이 필터 — 식당·카페 후보에만 적용

| 항목 | 규칙 |
| --- | --- |
| `diet.alcohol`=예 | **주점 유형** 식당을 제외한다(`DIET_RESTRICTED`) |
| `diet.spicy`=예, `diet.raw`=예 | 대표 메뉴, 취급 메뉴, 식당 이름, 세부 유형 단서로 판단한다. 해당 음식 단서가 있으면 제외한다(`DIET_RESTRICTED`). **판단할 단서가 없으면 제외한다**(`MENU_UNKNOWN`). 카페·전통찻집 유형은 '매운 음식·날음식 아님' 단서로 본다. 판단 결과는 '추정'으로 표시한다. 단서 목록은 조정 가능하다 |
| `diet.hot`=예, `diet.hard`=예 | **제외하지 않는다.** 해당 식당 카드에 '주문할 때 보여줄 한국어 카드'를 연결한다 |
| 식사 제한 | 식사 제한 시간 동안 식음 후보를 제외한다(기존 `FASTING_REQUIRED`) |

### 8.5 관심사와 이미지

- 관심사 태그: `SHOPPING`, `KBEAUTY`, `PALACE_HISTORY`, `CAFE`, `EXHIBITION`, `FOOD`, `NATURE`, `FESTIVAL`.
  - 태그를 관광 유형·단서로 바꾸는 규칙은 조정 가능하다.
  - 0개를 고르면 모든 유형을 같게 본다.
- 이미지는 URL과 저작권 구분만 쓰고 파일을 내려받지 않는다(기존). 이미지가 없으면 유형별 일러스트를 쓴다.

## 9. 전체 일정 확정과 변화 대응

### 9.1 생성

- 체류 설정을 마치면 전체 일정을 **한 번** 만든다.
  조건 입력 전이면 경계일 이후 날짜는 `NEEDS_INPUT`으로 두고 나머지만 만든다.
- 만든 일정은 **확정 일정**으로 기기에 저장한다. 변화가 감지되지 않으면 당일에도 그대로 쓴다.

### 9.2 변화 원천

감지 시점은 앱을 열 때, 화면으로 돌아올 때, 사용자가 조작할 때다.

| # | 원천 | 영향 날짜 |
| --- | --- | --- |
| 1 | 체류, 숙소, 병원 일정, 동반 보호자, 관심사, 강도 수정 | 영향받는 날짜 |
| 2 | 조건 기간 추가·수정·삭제, 동의 철회 | 영향받는 날짜 |
| 3 | 매일 확인에서 '바뀌었어요' | 오늘과 수정된 기간의 날짜 |
| 4 | 기상: 단기예보 범위(오늘~모레) 날짜의 실외 부적합 예보 | 그 날짜의 실외·실내불명 정거장(`WEATHER_BLOCKED`) |
| 5 | 연동 지침의 버전 변경·철회·만료(앱을 열 때 저장된 연결 코드로 다시 받음) | 해당 날짜 |
| 6 | 데모 사건('병원 연동 데모' 모드에서만, 9.3절) | 오늘 |
| 7 | 언어 변경 | 오늘 이후 모든 날짜의 **표시만 다시 쓴다.** 재판정하지 않는다. 정거장 `contentId`·시각·상태는 그대로이고 이름·주소·번역 표시만 새 언어로 바뀐다. 전후 비교를 만들지 않는다 |

### 9.3 데모 사건

기존 `/api/recalculate` 사건 계약을 하루 단위로 옮긴 것이다.

| `type` | 매개변수 | 오늘 일정에 주는 효과 |
| --- | --- | --- |
| `CLOSURE` | `closedIds`(`contentId` 1–20개) | 해당 장소를 닫힘으로 보고 재계획 |
| `WEATHER` | 없음 | 실외 부적합으로 보고 재계획 |
| `TRAFFIC_SURGE` | `extraMin`(5–120, 누적 상한 120) | 오늘 모든 외출의 복귀 계산에 추가 버퍼 |
| `APPOINTMENT` | `deltaMin`(±240, 누적) | 오늘 병원 일정 블록을 그만큼 옮기고 재계획 |
| `PATIENT_RECALL` | 없음 | 오늘 남은 일정 비움, `returnNow`=true, 사유 `PATIENT_RECALLED` |
| `RISK_SIGNAL` | 없음 | 오늘 남은 환자·보호자 외출 비움, `dayState`=`NO_TOURISM`, 사유 `RISK_SIGNAL` |

- 오늘 들어온 데모 사건은 기기에 누적 저장하고, 오늘 날짜를 재계획할 때마다 **모두 다시 보낸다.**
- 날짜가 바뀌면 지운다. 데모 패널의 '사건 초기화'로도 지울 수 있고, 초기화하면 오늘을 재계획한다.
- `returnNow`는 그날이 끝날 때까지 유지된다. 다음 경우에만 풀린다.
  - 날짜가 바뀜
  - 데모 사건 초기화(환자 호출이 원인일 때)
  - 유효한 지침이 다시 오늘을 덮음(철회·만료가 원인일 때)

### 9.4 재계획 규칙

1. 영향받은 날짜를 **게이트 1단계부터** 다시 판정한다.
2. 지난 날짜와, 오늘 중 시작 시각이 이미 지난 정거장은 건드리지 않는다.
3. 사용자가 직접 고른(고정) 장소는 여전히 통과하면 유지한다.
4. 사용자가 삭제한 장소는 그날 자동 채움에 다시 넣지 않는다.
5. 통과하지 못한 정거장은 **자동으로 다른 후보로 대체**한다.
   대체 후보가 없으면 체류를 줄이거나 정거장을 빼고, 외출 자체가 불가능하면 외출을 취소한다.

### 9.5 전후 비교와 오늘 게이트 덧씌우기

**전후 비교**

- 날짜별로 빠진 곳, 들어온 곳, 대체된 곳, 줄어든 곳, 취소된 외출, 상태 변경, 새 마감, 사유를 기록한다.
- 사용자가 볼 때까지 '변경됨'을 표시한다.
- 사용자는 대체된 자리를 다른 후보로 다시 바꿀 수 있다(10장).
- **변화가 필요한데 전후 비교가 비어 있으면 실패로 처리한다**(기존 "알림만 하는 재계산 금지").

**오늘 게이트 덧씌우기**

- 매일 확인 대기(`DAILY_CHECK_PENDING`)와 확인하지 않은 병원 중요 안내(`PLAN_UNCONFIRMED_UPDATE`)는
  **저장된 확정 일정을 바꾸지 않는다.** 오늘 일정을 보여주는 시점에 같은 순수 함수로 덧씌운다.
- 덧씌운 결과: 오늘 `dayState`=`STANDBY`, 해당 사유 추가, 이동 동작 비활성.
- 확인이 끝나면 덧씌우기만 사라진다. 조건이 바뀌어 재계획이 필요하면 재계획을 따로 한다.

### 9.6 즉시 복귀

- 환자 호출(데모 사건), 외출 중 지침 철회, 외출 중 지침 만료가 일어나면
  오늘 남은 일정을 비우고 `returnNow`=true로 표시하며 **즉시 복귀 시트를 자동으로 띄운다.**
- 이 동작은 끌 수 없다(기존 AX-220).
- 뒤로가기는 시트만 닫는다(기존 AX-011).

## 10. 사용자 편집

- **교체**
  - 정거장을 고르면 같은 시간 자리에 넣을 수 있는 게이트 통과 후보를 최대 5개 보여준다.
  - 후보를 고르면 외출 전체를 다시 검증한다(복귀 계산, 보행 누적, 이동 한도).
  - 통과하지 못하면 넣을 수 없고, 그 이유를 보여준다.
  - 교체한 장소는 '고정'으로 표시한다.
- **삭제**
  - 정거장을 지우면 외출 시각을 다시 계산한다.
  - 식사 칸 식당을 지우면 그 칸은 '비움'(`CLEARED`)으로 두고 자동으로 다시 채우지 않는다.
  - 고정·삭제·비움 기록은 날짜별로 장소 `contentId`와 식사 칸 이름으로 남긴다.
- **다시 만들기**
  - 범위는 '이 날짜' 또는 '오늘 이후 전체'다. 확인 대화를 거친다.
  - 고정·삭제 기록을 지우고 새로 만든다.
- 지난 날짜는 편집할 수 없다. 매일 확인 전인 오늘도 편집할 수 없다.

### 11.3 공항 이동 추정 (`lib/server/airports.js` `AIRPORT_TRANSFER`)

입국일 시작·출국일 마감(1장)에 쓰는 공항↔숙소 이동 추정이다. **세 값 모두 사람 검토 전 임시값이다** — 실제 공항버스·택시 소요와 비교해 사람이 확인한다(`HUMAN_ACTIONS.md` 12번).

```
분 = 올림(공항–숙소 직선거리 km × 1.3 ÷ 60km/h × 60 + 15분)
```

| 값 | 기본값 | 상태 |
| --- | --- | --- |
| 도로 우회 계수 `detourFactor` | 직선거리 × 1.3 | **사람 검토 전 임시값** |
| 평균 속도 `speedKmh` | 60km/h | **사람 검토 전 임시값** |
| 승차 대기·터미널 이동 `terminalMin` | +15분 | **사람 검토 전 임시값** |

- 공항 기준점은 인천(`ICN`)·김포(`GMP`) 좌표 한 점씩이다. 입국 수속 90분·공항 도착 여유 3시간·출국 여유 30분은
  `src/stay/defaults.js`의 별도 값이며 이 식에 더하지 않는다.
- 그날 숙소가 없으면 등록된 숙소 중 가장 먼 곳으로 계산한다(창을 넓히는 쪽으로 틀리지 않게).
