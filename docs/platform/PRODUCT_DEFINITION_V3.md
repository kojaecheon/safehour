# SafeHour 제품 정의 v3 — 대중형 체류 동반 플랫폼

- 기준일: 2026-09-18
- 상태: 1차 기획 확정본 (운영자 대화 결정 반영)
- 작업 ID: AX-301
- 이전 판: `docs/PRODUCT_DEFINITION.md` (v2, 2026-08-14). v2는 기록으로 남기고 고치지 않는다. 두 문서가 다르면 이 문서를 따른다.
- 함께 읽을 문서: `IA_AND_FLOWS.md`(화면·흐름), `ITINERARY_RULES.md`(일정 규칙·기본값),
  `HUMAN_ACTIONS.md`(사람이 할 일), `docs/decisions/0005`–`0011`(결정 기록)

> **제품 정의**
> SafeHour는 해외에서 성형외과·피부과 수술·시술을 받으러 온 환자와 동반 보호자 1명이
> **입국부터 출국까지** 쓰는 여행 동반 모바일 웹이다.
> 날짜마다 관광지·쇼핑·카페·맛집으로 하루 일정을 자동으로 짜 주되,
> 병원 주의사항(병원 발행 또는 본인 체크)을 어기지 않는 범위에서만 짠다.
>
> 앱은 의료 판단을 하지 않는다. 일정이 '조건을 통과했다'는 것은 입력된 조건을 만족한다는 뜻일 뿐,
> 안전을 보장한다는 뜻이 아니다.

---

## 1. 대상 — 누가 쓰는가

| 역할 | 설명 |
| --- | --- |
| **환자** | 수술·시술을 받은 외국인. 로그인한 기기의 주인이며 모든 입력을 직접 한다 |
| **동반 보호자** (0명 또는 1명) | 환자 기기에서 함께 보거나, 환자가 보낸 PIN 잠금 링크로 자기 기기에서 본다 |
| **병원** (연동할 때만) | 기간별 제한조건과 안내문을 발행한다. 이번 차례에는 데모 병원만 있다 |

앱이 묻지 않는 것도 분명히 해 둔다.

- 증상, 시술 종류, 회복 단계는 묻지 않고 해석하지도 않는다.
- 병원 일정은 `수술·시술` 또는 `진료`라는 **일정 유형**만 받는다.

---

## 2. 문제 — 왜 넓히는가

지금의 SafeHour(v2)에는 두 가지 한계가 있다.

1. **연동 병원이 있어야만 쓸 수 있다.** 그런데 연동 병원은 0곳이다. 결국 실제로 쓸 수 있는 사람이 없다.
2. **회복 대기 중 짧은 외출 하나만 판정한다.** 환자와 보호자가 실제로 보내는 시간은
   입국부터 출국까지의 체류 전체인데, 그중 한 순간만 다룬다.

이번 작업은 SafeHour를 **병원 연동 없이도 본인 체크로 바로 쓰는 대중형 제품의 첫 공개 버전**으로 넓힌다.
새 브랜드를 만들거나 처음부터 다시 짜는 것이 아니다.
기존 판정 엔진(안전 게이트·복귀 계산)과 관광공사 연동을 재사용하고, 안전 원칙은 그대로 둔다.

## 3. 가치 — 사용자가 얻는 것

| 가치 | 내용 |
| --- | --- |
| 체류 전체 일정 | 체류 설정만 마치면 입국일부터 출국일까지 날짜별 하루 일정이 자동으로 만들어진다 |
| 주의사항 안에서만 | 병원 발행 조건이나 본인 체크 조건을 날짜마다 합쳐 가장 엄격한 값으로 일정을 짠다. 어떤 값이 어디서 왔는지(병원 발행 / 본인 체크 / 기본값 적용) 항목마다 보여준다 |
| 바뀌면 다시 짬 | 조건·일정·기상·지침이 바뀌면 영향받은 날짜를 다시 짜고, 무엇이 바뀌었는지 전후 비교로 보여준다 |
| 보호자와 함께 | 같은 기기의 보호자 탭, 또는 PIN으로 잠근 공유 링크로 보호자 몫 일정과 환자 복귀 마감을 나눈다 |
| 현장에서 쓰는 도구 | 한국어 안내 카드(식이·이동·복귀·병원), 긴급 연락, 지도 앱 길찾기(목적지만), 기기 알림 |
| 네 가지 언어 | 한국어·영어·일본어·중국어(간체). 안전 문구는 선택 언어와 한국어를 함께 보여준다 |
| 중립 추천 | 수익화하지 않는다. 제휴·광고·순위 노출이 없고 인기 점수도 쓰지 않는다 |
| 내 기기에만 저장 | 체류·조건·일정은 사용자 기기에만 둔다. 서버는 계산만 하고 저장하지 않는다 |

## 4. 범위

### 4.1 포함

- 로그인 → 체류 설정(입·출국 일시, 날짜별 숙소, 병원·병원 일정, 동반 보호자, 관심사·이동 강도)
- 민감정보 동의 → 조건 기간 입력(본인 체크) 또는 병원 코드 연동(데모)
- 입국~출국 전체 하루 일정의 자동 생성·확정과 날짜별 보기
- 매일 확인, 변화 감지 시 자동 재계획과 전후 비교
- 일정 편집(교체·삭제·다시 만들기)
- 보호자 일정(같은 기기)과 PIN 잠금 공유 링크
- 한국어 안내 카드, 기기 알림, 지도 앱 길찾기(목적지만), 긴급 연락
- AI 일정 소개 문장(기본 꺼짐)과 그 평가 도구
- 한국어·영어·일본어·중국어(간체)
- 홈 화면 설치, 보기 전용 오프라인 화면
- 도로명주소 검색으로 숙소·병원 위치 입력
- 기획 문서, 디자인 시스템, 시안 보드

### 4.2 제외 — 이번 차례에 하지 않는다

| 제외 | 이유 |
| --- | --- |
| 서버 저장(계정 DB·일정 동기화)·서버 푸시 알림 | 기기에만 저장하기로 했다 |
| 보호자 실시간 동기화·환자→보호자 호출 메시지·보호자 2명 이상 | 서버가 없어 동기화할 수 없다. 보호자는 1명 기준이다 |
| 현재 위치(GPS)·경로 API·지도 내장 화면 | 숙소·병원 기준점만 쓴다 |
| 관광공사 외 장소 데이터(구글·카카오·네이버)·평점·리뷰 | 관광공사 데이터만 쓰기로 했다 |
| 제휴·광고·예약·결제 | 당분간 수익화하지 않는다 |
| 네이티브 앱·앱스토어 | 모바일 웹과 홈 화면 설치로 대신한다 |
| 병원 안내문 사진 인식·번역·요약 | 안내문을 재해석하지 않는다는 기존 금지를 유지한다 |
| 애플·라인·위챗 로그인 | 구글·카카오를 유지한다 |
| 실제 병원 연동 | 파트너가 없다. 데모 연동만 한다 |
| 노션·피그마 반영, main 병합, 운영 배포, 원격 push | 운영자가 따로 결정할 사항이고 일정 제약이 있다 |
| 숙소 이동일의 체크아웃·체크인 시각 처리 | 숙소는 날짜 단위로만 다룬다 |

### 4.3 이번 차례의 결과물

1. **기획 문서**(저장소 안) — 이 문서, 화면 구조·흐름, 일정 규칙, 결정 기록(ADR 0005–0011),
   AI 사용 문서, 사람이 할 일 목록
2. **디자인** — 밝은 여행앱 스타일의 코드 디자인 시스템과 시안 보드 페이지
3. **핵심 구현** — 위 포함 범위가 모바일 웹에서 처음부터 끝까지 동작

## 5. 핵심 개념

| 용어 | 뜻 |
| --- | --- |
| 체류 | 한 사람의 한 번의 방한. 계정 하나, 기기 하나에 활성 체류는 하나다 |
| 숙소 구간 | 체크인~체크아웃 날짜 동안 묵는 곳. 날짜 D의 숙소는 D일 밤을 묵는 곳이다 |
| 병원 일정 | `수술·시술`(PROCEDURE) 또는 `진료`(VISIT)의 시간 블록. 앞뒤 이동을 포함해 외출을 막는다 |
| 수술 후 경계일 | 가장 이른 `수술·시술` 일정의 날짜. 이날부터는 조건 기간이 있어야 일정을 만든다 |
| 조건 기간 | 날짜 범위 하나에 적용되는 제한조건 묶음. 출처는 본인 체크 또는 병원 발행이다 |
| 본인 체크 | 환자가 병원 안내를 보고 정해진 항목을 직접 고르는 것. 앱의 해석이 아니다 |
| 날짜 분류 | 그날 일정을 어떤 조건으로 만드는지: 자유일 / 제한 없음 선언일 / 제한일 / 휴식일 / 입력 필요 |
| 확정 일정 | 체류 설정 후 한 번 만들어 기기에 저장한 전체 일정. 변화가 없으면 당일에도 그대로 쓴다 |
| 조건 통과 | 입력된 조건을 만족한다는 뜻. '안전'과 같은 말이 아니다 |
| 복귀 장소 | 숙소(기본) 또는 병원 |
| 병원 연동 데모 | 실제 연동이 아니라는 뜻. 화면에 늘 표시한다 |

세부 규칙과 기본값은 `ITINERARY_RULES.md`에 있다.

## 6. v2와 달라진 점

| 구분 | v2 (2026-08-14) | v3 (이번) |
| --- | --- | --- |
| 제품의 중심 | 병원이 발행한 회복 지침을 확인하고, 지침을 지킬 수 있을 때만 외출 선택지를 준다 | 입국~출국 날짜별 하루 일정을 자동으로 짜고, 주의사항 범위 안에서만 짠다 |
| 조건 출처 | 병원 발행만. 수기 입력은 철회했다 | 병원 발행 **또는** 동의 후 본인 체크. 정해진 항목만 받고 자유 서술은 없다 (ADR-0005) |
| 조건이 없을 때 | 유효한 병원 계획이 없으면 관광지를 보여주지 않는다 | 수술 후 경계일 전 빈 날짜는 자유일, 경계일부터 빈 날짜는 입력 필요 (ADR-0005) |
| 조건 충돌 | 상충하면 추천하지 않는다 | 항목별로 가장 엄격한 값을 합성한다. 한 병원 기간 안의 모순은 계속 막는다 (ADR-0005) |
| 추천 형태 | 회복 대기 중 단일 외출 판정(`/plan` → `/result`) | 체류 전체 하루 일정. 단일 외출 흐름과 API는 퇴역한다 (ADR-0006) |
| 조건 최신성 | 24시간 | 병원 발행은 유효기간·철회 여부, 본인 체크는 매일 확인 (ADR-0011) |
| 병원 지침 계약 | v1 (단일 조건 묶음) | v2 (기간 목록). v1은 더 이상 받지 않는다 (ADR-0011) |
| 환자 호출 | 지침의 호출 플래그(이벤트) | 이번 차례에는 데모 사건으로만 다룬다 (ADR-0011) |
| 화면 구조 | 홈 · 회복 안내 · 안전 외출 · 보호자 | 하단 내비 오늘 · 일정 · 조건 · 더보기, 모든 화면에 긴급 버튼 (`IA_AND_FLOWS.md`) |
| 보호자 | 게이트웨이가 축약한 정보를 보호자 모드로 본다 | 같은 기기의 보호자 탭, 또는 병원 정보를 뺀 PIN 암호화 사본 링크. 자동 갱신은 없다 (ADR-0009) |
| 저장 | 탭 단위 저장(`sessionStorage`) | 기기 영구 저장(계정 이름공간). 출국 7일 후 첫 실행 때 삭제 (ADR-0009) |
| 로그인 | 병원 지침을 다시 불러오는 데 쓴다 | 모든 기능에 로그인. 로그인 만료·오프라인에서도 안전 정보는 보기 전용으로 보여준다 (ADR-0009) |
| 언어 | 한국어·영어. 언어를 서버로 보내지 않는다 | 한국어·영어·일본어·중국어(간체). 관광 데이터 언어를 고르려고 서버에 `lang`을 보낸다 (ADR-0007) |
| 식이 | 식음 제한·금식 종료 시각만. "매운 음식 주의" 같은 안내문은 표시만 한다 | 식이 5항목을 조건 항목으로 받고 항목별 기준으로 거른다. 안내문을 판정에 쓰지 않는 원칙은 그대로다 (ADR-0005, ADR-0006) |
| 지도 | 연동 보류 | 목적지만 담은 외부 지도 링크 (ADR-0010) |
| AI | 런타임 AI 없음 | 하루 일정 소개 문장에 한해 허용. 기본 꺼짐, 승인 전 운영 금지 (ADR-0008) |
| 디자인 | 클리닉 프리미엄(웜 아이보리 + 딥그린 + 골드) | 밝은 여행앱 스타일로 대체 (`DESIGN_SYSTEM.md`) |

## 7. 불변조건

### 7.1 유지하는 것

- 의료 판단을 만들지 않는다. 증상, 시술 종류, 회복 단계를 묻거나 해석하지 않는다.
- 현재 위치를 수집하지 않는다. 기준점은 사용자가 고른 숙소·병원의 고정 좌표뿐이다.
- 병원 목록, 순위, 평점, 제휴, 광고를 두지 않는다.
- `unknown`, 폴백, 추정 값을 긍정 사실로 바꾸지 않는다. 영업 중이라고 단정하지 않는다.
- 관광공사 원문과 SafeHour 추정값을 같은 필드에 섞지 않는다. 이미지를 내려받지 않는다.
- API 키, 전체 조회 URL, 병원 안내문 원문, 이름·연락처·증상 원문을 코드·로그·문서·테스트 데이터에 남기지 않는다.
- 변화가 생기면 게이트부터 다시 판정한다. 필요한 변화가 화면에 반영되지 않으면 실패다.
- 병원 안내문을 번역, 요약, 편집하지 않는다. 판정에 쓰지 않는다.
- 데모를 실제 연동처럼 보이게 하지 않는다.
- 서버에 계정, 세션, 체류, 조건, 일정 저장소를 만들지 않는다. 토큰을 보관하지 않는다.
- '안전합니다'라는 표현을 쓰지 않는다. 조건 통과와 안전은 다르다.

### 7.2 바뀌는 것 (이번 결정)

| 이전 | 이후 | 결정 기록 |

## 8. 기술 구조 요약

- 기존 Next.js 모바일 웹을 넓힌다. 홈 화면 설치와 보기 전용 오프라인을 지원한다.
- 서버 라우트는 **무상태 계산기**다. 체류·조건·편집·이전 일정을 받아 관광공사·기상청을 조회하고,
  규칙 엔진으로 하루 일정과 전후 비교를 돌려준다. 받은 조건 값은 계산 뒤 버리고 로그에도 남기지 않는다.
- 클라이언트는 기기 영구 저장소(계정 이름공간)에 체류와 확정 일정을 두고, 변화 감지와 재계획 요청을 맡는다.
- 규칙 엔진은 기존 안전 게이트·복귀 계산을 재사용한 **결정적 함수**다. 같은 입력이면 같은 결과가 나온다.
  AI는 일정 배치에 관여하지 않는다.
- 외부 데이터는 관광공사 TourAPI, 기상청 단기예보, 행정안전부 도로명주소 검색·좌표 API,
  Gemini(선택, 기본 꺼짐)만 쓴다. 지도 앱은 목적지만 담은 외부 링크로만 연다.

## 9. 아직 사람 확인을 기다리는 것

의료·법무·위치정보·번역 검수가 모두 사람 승인 대기 상태다. 그래서 실제 환자를 대상으로 한 운영은
아직 할 수 없다. 또 키가 없으면 꺼져 있는 기능(AI 소개 문장, 실제 주소 검색, 일본어·중국어 관광 데이터)이 있다.
항목별 담당·상태·막히는 기능은 `HUMAN_ACTIONS.md`에서 관리한다.
