# 복귀 마감이 지난 외출: 즉시 복귀와 보호자 알림 설계

- 작성일: 2026-11-06
- 브랜치: `claude/overdue-return` (PR #31 브랜치 `claude/retire-legacy-judgment` 위에서 시작. 로컬 커밋만, push·PR·병합은 운영자 확인 뒤)
- 근거: `docs/tracking/status.md` 남은 것 1번, `docs/tracking/findings.md` 4번 '옮기지 않은 규칙' 표의 마지막 줄
- 시안: 보호자 휴대폰 화면 세 장(잠금 화면 알림, 앱 안 배너, 받은 일정 화면)을 운영자가 보고 승인했다(2026-11-06). 이 문서의 4.1절이 그 시안을 글로 옮긴 것이다.

## 1. 왜 하는가

예전 단일 외출 판정에는 "복귀 시각이 지나면 즉시 복귀만 보인다"는 출시 차단 규칙이 있었다. 지금 하루 일정
엔진에는 같은 동작이 없다. 마감을 넘긴 외출에는 '시간 부족'(`SLA_INSUFFICIENT`) 사유만 붙고, 즉시 복귀
시트는 뜨지 않는다. 마감 60분 전·30분 전 알림은 있지만 마감 시각 자체에는 아무 일도 일어나지 않는다.

운영자가 원하는 것은 두 가지다.

1. 환자가 복귀 마감을 넘기면 **보호자 휴대폰**에 알림이 와 있어야 한다.
2. **환자 휴대폰**에는 즉시 복귀 시트가 떠야 한다.

## 2. 앱이 알 수 있는 것과 없는 것

앱은 현재 위치를 모으지 않는다(절대 넘지 않는 선 2). 그래서 마감 시각이 지났을 때 환자가 이미 돌아왔는지
아직 밖인지 **알 수 없다.** 앱이 말할 수 있는 것은 "마감 시각이 지났다"와 "아직 밖이라면/함께 있지 않다면
이렇게 하라"까지다. "환자가 복귀하지 않았다"고 단정하지 않는다(절대 넘지 않는 선 5).

지금 기기 알림은 서버 없이 그 휴대폰 안에서만 울린다(`lib/notify/runtime.js`). 앱이 열려 있거나 실행 중일
때만 확실하다. 다른 휴대폰으로 보내거나 앱이 닫힌 상태까지 보내려면 서버가 알림 주소와 마감 시각을 보관해야
하는데, 운영자는 이번에는 **서버 없이** 가기로 정했다(2026-11-06, '갈래 1'). 서버 푸시는 9절로 미룬다.

보호자 휴대폰에는 이미 PIN으로 잠근 환자 일정 사본이 있고, 날짜별 `patientReturn[]`에 환자 외출의 복귀 마감
시각(`by`, "HH:MM")이 들어 있다(`src/guardian/snapshot.js`). 보호자 알림은 이 값만으로 만든다. 스냅샷에 필드를
더하지 않는다.

## 3. 목표와 범위

**목표**

- **G1 보호자 휴대폰:** 받은 사본에 있는 오늘 환자 복귀 마감 시각에 기기 알림과 앱 안 배너를 낸다. 받은 일정
  화면에 '마감 지남' 표시와 할 일, 긴급 연락을 보인다.
- **G2 환자 휴대폰, 경우 1 (시간이 흘러 마감이 지남):** 마감 시각에 기기 알림을 하나 더 내고 즉시 복귀 시트를
  띄운다. **일정은 바꾸지 않는다.**
- **G3 환자 휴대폰, 경우 2 (외출 중 재계획으로 이미 늦음):** 지금의 즉시 복귀와 똑같이 오늘 남은 일정을 비우고
  시트를 띄운다. 새 사유 코드를 둔다.

**하지 않는 것**

- 서버 푸시, 서버 저장소, 예약 작업(크론)
- 환자가 누르는 '돌아왔어요' 확인 버튼
- 보호자 사본 자동 갱신 (사본은 받은 시점 그대로다. 이미 화면에 밝히고 있다)
- 보호자 외출(`guardianOutings`)의 마감 알림
- 보호자 휴대폰에서의 경우 2 반영 (사본이 바뀌지 않으므로 보호자 쪽은 받은 마감 시각 기준으로만 움직인다)

**실패로 보는 것 (동작은 해도)**

- 화면이나 알림이 "환자가 돌아오지 않았다", "안전합니다"처럼 모르는 것을 단정한다.
- 잠금 화면 문구에 환자·보호자·병원이라는 말이나 장소 이름·주소가 나온다.
- 경우 1에서 그날 남은 외출이 사라진다. (하루에 외출이 둘이면 첫 외출 마감이 지나는 순간 오후 외출까지
  잃게 된다. 제때 돌아온 환자도 일정을 잃는다.)
- 즉시 복귀 판정이 두 곳에서 따로 이루어진다. 엔진의 `returnNow` 원인은 `src/engine/tripPlan.js`의
  `returnNowCauses` 한곳에서만 정한다.
- 위치 권한을 묻는 코드 경로가 생긴다.

## 4. 동작

### 4.1 보호자 휴대폰 (G1)

**알림 대상과 시각**

- 이 기기에 저장된 만료 전 보호자 사본 가운데 **가장 최근에 가져온 사본 하나**(`store.readGuardianCopies()`의
  첫 항목, `/g`가 기본으로 보여 주는 사본)에서 **오늘(KST) 날짜**의 `patientReturn[].by`를 모은다.
  - 환자는 일정이 바뀌면 링크를 다시 보내므로 같은 여행의 예전 사본이 기기에 쌓인다. 예전 사본까지 쓰면 이미 바뀐
    마감으로 알림이 나간다. 제품 전제가 '환자 1명 + 동반 보호자 1명'이므로 최신 사본 하나만 쓴다.
- 마감 시각 `by`에 **한 번** 울린다. 같은 마감으로 다시 울리지 않는다. 미리 알림(60·30분 전)은 보호자 쪽에 두지
  않는다. 미리 알림은 환자 휴대폰의 몫이다.
- 앱이 마감 시각에 닫혀 있었다면, 마감 뒤 **60분 안에** 앱이 열리거나 깨어날 때 그때 한 번 낸다(기기 알림과 앱 안
  배너). 60분이 지났으면 내지 않는다. 예약 항목의 `expiresAt`은 `by + 60분`이다.
  - 지금 실행기는 예약을 다시 만들 때 지난 시각 항목을 버린다. 이 새 알림 종류는 시각이 지났어도 `expiresAt` 전이면
    예약에 남긴다.
  - '한 번만'을 새로 고침·다시 열기 뒤에도 지키려면 이미 낸 알림을 기기에 기억해야 한다. 지금은 실행기 메모리에만
    있다. 이미 낸 알림의 id만 `safehour.v2.` 아래(계정 이름공간)에 두고 날짜가 바뀌면 지운다.
- 같은 시각이 둘 이상이면 알림은 하나로 합친다(지금 '같은 시각은 하나로' 규칙).
- 이 기기에 보호자 자신의 체류 일정이 있으면, 그 일정의 알림과 보호자 알림을 모두 낸다.

**켜는 법**

- 받은 일정 화면 맨 위에 **'복귀 마감 알림 받기'** 스위치를 둔다. 기본은 꺼짐이다.
- 켤 때 브라우저 알림 권한을 묻는다. 권한은 사용자가 직접 누르는 순간에만 물을 수 있어서 화면 진입 때 묻지 않는다.
- 이 스위치는 설정 화면의 알림 스위치와 **같은 기기 설정**(`prefs.notifications`)을 쓴다. 알림을 내는 조건
  (`lib/notify/device.js`: 설정 켜짐 + 권한 허용)은 그대로다.
- 스위치 아래 안내: "이 휴대폰에서 앱이 완전히 닫혀 있으면 알림이 오지 않을 수 있어요." 사본이 자동으로 바뀌지
  않는다는 기존 안내(`guardian.notAutoUpdated`)는 그대로 둔다.

**잠금 화면 알림 (문구 A, 운영자 선택)**

- 제목: 기존 `notifications.title` ("SafeHour 알림").
- 본문: "일행의 복귀 마감 {time}이 지났어요. 함께 있지 않다면 지금 연락해 보세요"
- 잠금 화면은 남도 볼 수 있으므로 '환자'를 쓰지 않고 '일행'이라고 쓴다. 지금 알림 규칙(규칙 47)과 금지어 검사를
  그대로 따른다. 넣는 값은 `{time}` 하나다.

**앱 안 배너**

- 지금 알림 배너 자리(`components/pwa/NotificationBanner.js`)에 같은 문구를 주 언어와 병기 언어 두 줄로 보인다.
- 배너 링크는 '오늘 일정 보기' 대신 **'받은 일정 보기'**이고 보호자 사본 화면(`/g`)으로 간다.
- 닫기로 닫을 수 있다.

**받은 일정 화면 (`components/guardian/GuardianCopyView.js`)**

- 오늘 날짜의 환자 복귀 마감 항목에 표시를 붙인다. 다른 날짜에는 붙이지 않는다.
  - 마감 시각이 지났으면(지금 ≥ `by`): **'마감 지남'** 표시(기호 + 글자, 대기 상태 색). 색만으로 구분하지 않는다.
    그 아래에 "함께 있지 않다면 환자에게 연락해 돌아왔는지 확인해 주세요." 한 줄과 **119 전화**, **긴급 안내**
    (`/emergency`) 버튼을 둔다.
  - 아직이면: **'예정'** 표시(회색).
- '마감 지남' 표시는 **그날이 끝날 때까지** 남는다. 앱은 환자가 돌아왔는지 모르므로 지울 근거가 없다.
- 화면을 열어 둔 채 마감 시각이 지나면 1분 안에 표시가 바뀐다.

### 4.2 환자 휴대폰, 경우 1: 시간이 흘러 마감이 지남 (G2)

**기기 알림**

- 오늘 저장 일정의 환자 외출(`outings`)마다 `returnBy` 시각에 알림을 하나 더 낸다. 기존 60·30분 전 알림은 그대로다.
- 본문: "{time} 복귀 마감이 지났어요. 아직 밖이라면 지금 돌아가세요". 숙소로 돌아가는 외출이든 아니든 같은 문구다
  (장소를 적지 않는다).
- `expiresAt`은 `returnBy + 60분`. 같은 시각 합치기에서는 지금처럼 복귀 마감 종류가 이긴다.
- 앱이 닫혀 있다가 60분 안에 열리면 그때 한 번 내는 규칙과 '이미 낸 알림' 기억은 4.1절과 같다. 기존 60·30분 전
  알림의 동작은 바꾸지 않는다.

**즉시 복귀 시트 (마감 지남)**

- 앱이 열려 있으면 `returnBy`가 되는 순간(1분 안) 자동으로 뜬다. 앱을 그 뒤에 열었으면 `returnBy + 60분` 전까지만 뜬다.
- **외출마다 한 번**이다. '확인했어요'·Escape·뒤로 가기로 닫으면 그 외출로는 다시 뜨지 않는다. 새로 고쳐도
  다시 뜨지 않도록 기기에 기억하고, 날짜가 바뀌면 지운다. 기억하는 값은 `safehour.v2.` 아래(계정 이름공간) 두어
  '이 기기에서 내 정보 지우기'가 함께 지우게 한다.
- **저장 일정을 바꾸지 않는다.** `returnNow`를 켜지 않고, 남은 정거장도 그대로다. 오늘 화면의 '복귀 안내 다시
  보기' 배너도 만들지 않는다. 기존 '오늘 게이트 덧씌우기'처럼 표시만 하는 동작이다. 판정(어느 장소가 조건을
  통과하는지)을 새로 하지 않으므로 두 번째 판정 경로가 아니다.
- 그날이 이미 즉시 복귀(`returnNow`) 중이면 이 시트는 띄우지 않는다. 기존 즉시 복귀 시트가 우선이다.
- 매일 확인 대기 중이어도 띄운다(안전한 쪽).
- 내용:
  - 제목: "복귀 마감 시각이 지났어요"
  - 본문: "아직 밖이라면 아래 장소로 바로 이동하세요. 이미 돌아왔다면 아래 버튼을 눌러 닫으세요."
  - 돌아갈 곳: 그 외출의 `returnPlace`를 따른다.
    - 숙소면 지금 시트처럼 그날 숙소의 이름·주소 글자.
    - 병원이면 그 외출의 병원 이름·주소 글자. 병원은 `hospitalId`로만 찾는다(`tripPlan.js`의
      `returnHospitalOf`와 같은 규칙). 찾지 못하면 "정해 둔 장소"라고만 쓰고 추측하지 않는다.
  - 한국어 복귀 카드 링크, 119 전화, 긴급 안내 링크, '확인했어요' 버튼은 지금 시트(`components/ReturnSheet.js`)와 같다.
  - 제목·본문은 지금 시트처럼 안전 문구 두 줄(주 언어 + 병기 언어)이다.

### 4.3 환자 휴대폰, 경우 2: 외출 중 재계획으로 이미 늦음 (G3)

**켜지는 조건**

- 오늘 날짜를 다시 계산할 때(`planDate`, 이전 오늘 일정 `prevDay`가 있을 때), 이전 일정 기준으로 **외출 중이던**
  환자 외출(출발 시각 ≤ 지금 < 그 외출의 `occupancyEnd`, `planLostDuringOuting`과 같은 기준)이
  다시 계산한 결과 **여유(`slackMin`)가 음수**가 되면 켜진다.
- 여유가 음수라는 것은 남은 정거장을 줄이고도 마감을 맞출 수 없다는 뜻이다. 지금 엔진은 이미 출발한 외출의
  새 마감이 출발보다 이르면 마감을 지금으로 두어 여유를 음수로 만든다(`dayContext.js`의 `overdueSafe`).
- 원인은 가리지 않는다. 병원 일정이 앞당겨진 경우, 병원 복귀 시각이 바뀐 경우, 교통 지연 사건으로 복귀 계산에
  버퍼가 붙은 경우 모두 해당한다.
- 이동 중(출발했고 첫 정거장 도착 전)인 외출도 같은 조건으로 켜진다(2026-11-08 추가, findings 10). 예전에는 시작된
  정거장이 없어 맞출 수 없는 외출을 취소해 여유가 음수인 외출이 남지 않았고, 사유는 `APPOINTMENT_DELAYED`뿐이었다.
- 정거장 0개 규칙: 고치는 쪽(`dayRepair.js`의 `repairOuting`)은 이미 출발한 외출을 시작된 정거장이 없어도 취소하지
  않는다. 남은 정거장을 비운 정거장 0개 외출로 남기고, 마감은 지금 창에서 `overdueSafe`로 다시 정한다. 복귀 구간은
  출발지(숙소)에서 복귀 장소까지로 계산한다(`manualEvaluation`). 판정은 그대로 `returnNowCauses` 한곳이고, 유지·해제
  (`overdueOutingId`, `heldSlack`)와 시트의 돌아갈 곳(그 외출의 `returnPlace`)도 그대로 쓴다. 전후 비교에서 그 외출은
  '취소된 외출'이 아니라 빠진 곳과 새 마감으로 보인다.

**동작**

- 새 사유 코드 **`OUTING_OVERDUE`**를 원인으로, 지금 즉시 복귀와 똑같이 처리한다. 오늘 남은(시작하지 않은)
  정거장을 비우고, 날짜 상태는 `NO_TOURISM`, `returnNow`는 `true`, 시트가 자동으로 뜨고, 오늘 화면에
  '복귀 안내 다시 보기'가 남는다.
- 판정은 `returnNowCauses`에 원인 하나를 더하는 것으로만 한다. 다른 곳에서 따로 판정하지 않는다.
- 시트는 지금 즉시 복귀 시트(제목 "지금 돌아가세요", "오늘 남은 일정을 비웠어요" 본문)를 쓰고, 원인 문구로 새
  사유 문구를 보인다.
- **돌아갈 곳은 경우 1과 같은 규칙**이다. 지금 시트는 원인과 상관없이 그날 숙소만 보이는데, 경우 2의 대표 원인
  (병원 일정 앞당김, 병원 복귀 시각 변경)은 병원으로 돌아가는 외출에서 자주 생긴다. 병원 일정 직전의 환자에게
  숙소로 가라고 하지 않도록 한다.
  - 기준은 **다시 계산해 저장한 오늘 일정**에 남아 있는 그 외출의 `returnPlace`다. 엔진이 다시 정한 복귀 장소를
    그대로 따르고, 이전 일정의 복귀 장소로 되돌리지 않는다(판정은 엔진 한곳).
  - 숙소면 지금 시트와 같다. 숙소가 아니면 4.2절처럼 병원을 `hospitalId`로만 찾아 이름·주소를 보이고, 못 찾으면
    "정해 둔 장소"라고만 쓴다. 본문은 "아래 숙소로" 대신 "아래 장소로" 문구(`return.bodyPlace`)를 쓴다.
  - 환자 호출·지침 철회·만료로 뜨는 시트는 지금처럼 숙소를 보인다. 이번 범위에서 바꾸지 않는다.
- 원인 목록을 들고 있는 곳(`tripPlan.js`의 `IMMEDIATE_RETURN_CAUSES`, `lib/trip/local.js`·`lib/trip/runtime.js`·
  `app/today/page.js`의 `RETURN_CAUSES`, `ReturnSheet`의 `cause` 설명)에 모두 더한다. 한곳에서 가져오게 정리할지는
  빌더가 정한다(7절).

**유지와 해제**

- 이전 오늘 일정이 이 원인으로 `returnNow`이면, 다음 재계획에서도 이미 출발해 남아 있는 그 외출의 여유가
  여전히 음수인 동안 유지한다. 외출 시간이 지났다고 저절로 풀리지 않는다.
- 바뀐 일정이 되돌려져(예: 데모 사건 초기화) 여유가 0 이상이 되면 원인이 사라진다. 그때는 지금의 해제 흐름
  (`LIFTABLE_CAUSES`)대로 지금 이후를 다시 짠다. `OUTING_OVERDUE`를 `LIFTABLE_CAUSES`에 더한다.
- 해제 흐름(`planStructural`의 `adopt`)은 마감이 당겨진 환자 외출(`overdueSafe`로 마감이 복귀 도착보다 이르게
  저장됨)을 '다시 잴 외출'로 다룬다(2026-11-08 추가, findings 9). 시작된 정거장은 그대로, 마감과 여유는 출발 시각이
  든 지금 창(`patientDeadlineAt`, `heldSlack`과 같은 창)으로 다시 잰다. 아직 밖에 있으면 원인 없는 하루에서 같은
  정거장 id 를 든 외출의 남은 정거장(지금 뒤에 도착하는 것)을 되살리고 `repairDay`가 다시 검증한다. 출발 시각은
  옮기지 않는다. 그 외출이 차지하는 시간에는 새 외출을 짜지 않는다(예전에는 마감이 당겨진 외출을 끝난 외출로 두고
  병원 외출을 하나 더 짰다). 판정은 그대로 `returnNowCauses` 한곳이다.
- 해제 뒤 보호자 외출은 원인 없는 하루의 보호자 외출 중 지금 이후에 출발하고 겹치지 않는 것을 더해 다시 검증한다.
- 날짜가 바뀌면 풀린다.

## 6. 제약

- 서버 저장소, 서버 푸시, 예약 작업을 만들지 않는다. 새 패키지를 들이지 않고 잠금 파일을 바꾸지 않는다.
- 알림 예약 항목은 허용 목록 필드(`NOTIFY_ITEM_FIELDS`: id, kind, key, time, at, expiresAt)만 가진다.
  사본 id·장소 이름·주소가 항목에 들어가지 않는다. 항목 id는 결정적이어야 하고 사본 내용을 드러내지 않아야 한다.
- 보호자 스냅샷에 필드를 더하지 않는다(링크 길이 그대로).
- 시각 계산은 KST 오프셋을 붙인 값으로 한다(`kstInstantMs` 등). 오프셋 없는 문자열을 직접 파싱하지 않는다.
- 화면: 본문 16px 이상, 누르는 곳 44px 이상, 색 단독 구분 금지, WCAG AA, 색은 `app/globals.css` 토큰만.
- 문구는 i18n 사전에만 둔다. 새 글에 엠대시·엔대시를 쓰지 않는다.
- 관문: `npm run lint`, `npm test`, `npm run build`, `npm run e2e`. 로컬 커밋만 하고 push·PR·병합은 운영자 확인 뒤에 한다.
- 함께 고칠 문서:
  - `docs/business-rules.md`: 즉시 복귀 절에 경우 2 원인, 경우 1 시트(일정 유지), 보호자 알림
  - `docs/contracts.md`: 새 사유 코드
  - `lib/notify/schedule.js` 머리 주석의 알림 대상 표
  - `docs/security.md`: 기기에 새로 기억하는 값(경우 1 시트 닫음 기록, 이미 낸 알림 id)과 그 삭제
  - `docs/tracking/status.md`: 남은 것 1 완료, 서버 푸시(9절)를 남은 것에 추가
  - `docs/tracking/findings.md`: 4번 표의 마지막 줄 해결 표시

## 7. 빌더에게 맡기는 것

- 함수와 파일 구성, 경우 1 시트를 `ReturnSheet` 확장으로 만들지 따로 만들지
- 원인 목록 중복(4곳)을 한곳으로 모을지
- 경우 1 닫음 기록의 저장 모양(어느 기록에 어떤 필드로 둘지)
- 알림 항목 id 규칙과 보호자 알림의 `kind` 이름
- 병원으로 돌아가는 외출에서 한국어 복귀 카드 링크를 어떻게 둘지(카드가 숙소용뿐이면 기존 카드 동작을 따른다)
- 경우 1 시트를 언제 다시 확인할지(알림 실행기 시계에 붙일지 따로 둘지). 단, 열린 화면에서 1분 안에 떠야 한다
- 테스트 구성. 다만 아래 확인은 빠지면 안 된다
  - 4개 언어 새 알림 문구의 금지어·자리표시자 검사
  - 경우 1에서 저장 일정이 바뀌지 않는다
  - 경우 2의 켜짐·유지·해제(되돌리면 풀림, 시간이 지나도 저절로 풀리지 않음)
  - 시간이 그냥 흘러 마감이 지난 뒤의 재계획이 경우 2를 켜지 않는다
  - 보호자 알림이 최신 사본 하나의 오늘 날짜만 쓰고, 예전 사본·만료된 사본은 쓰지 않는다
  - 마감 뒤 60분 안에 다시 열면 한 번 내고, 60분이 지났거나 이미 냈으면 내지 않는다(새로 고침 뒤에도)
  - 경우 2 시트가 병원으로 돌아가는 외출에서 병원을, 숙소로 돌아가는 외출에서 숙소를 보인다

## 8. 설계자가 정한 것 (운영자 확인 대상)

대화에서 운영자가 정한 것: 서버 없이 간다, 보호자 휴대폰에 알린다, 문구 A, 시안 화면 구성, 두 경우 모두 시트,
경우 1은 일정 유지·경우 2는 남은 일정 비움, 4.1절의 1~5번 추측(마감 때 한 번, 오늘 날짜 전부, 스위치 기본 꺼짐,
60분 넘으면 기기 알림 생략, 표시는 그날 끝까지).

설계자가 정한 것:

1. 환자 휴대폰에도 마감 시각 기기 알림을 하나 더 둔다(4.2).
2. 경우 1 시트도 늦게 열었을 때 60분 기준을 보호자 쪽과 같게 둔다.
3. 경우 1에서는 오늘 화면에 '복귀 안내 다시 보기' 배너를 만들지 않는다.
4. 매일 확인 대기 중이어도 경우 1 시트를 띄운다.
5. 경우 2는 원인을 가리지 않는다. 교통 지연 사건으로 늦어진 경우도 포함한다.
6. 보호자 화면 스위치는 설정 화면 알림 스위치와 같은 기기 설정을 쓴다.
7. 사유 코드 이름 `OUTING_OVERDUE`와 5절의 문구.
8. 보호자 알림은 가장 최근에 가져온 사본 하나만 쓴다(같은 여행의 예전 사본으로 바뀐 마감이 울리지 않게).
9. 앱이 닫혀 있었으면 마감 뒤 60분 안에 열릴 때 한 번 알린다. 이를 위해 이미 낸 알림 id를 기기에 기억한다.
10. 경우 2 시트도 경우 1처럼 그 외출의 복귀 장소(병원이면 병원)를 보인다. 기준은 엔진이 다시 정한 복귀 장소다.

## 9. 미뤄 둔 것 ('갈래 2')

서버가 보호자에게 푸시를 보내는 방식이다. 환자가 '돌아왔어요'를 누르지 않은 채 마감이 지나면 앱이 닫혀 있어도
보호자에게 "복귀 확인이 없다"고 알릴 수 있다. 서버가 보호자 알림 주소·환자 마감 시각·복귀 확인 여부를 보관해야
하므로 서버 저장소 결정(절대 넘지 않는 선 4)과 함께 따로 설계한다. 필요한 것: 푸시 서명 키, 1분 단위 예약 작업
(Vercel 요금제 확인), 아이폰은 홈 화면 설치가 있어야 푸시를 받는다.
