  일정, 교체 후보, 장소 상세, 소개 문장. **지침 연결과 주소 검색은 아직 양쪽이 각자의 값으로만
  검증된다** — 모양이 어긋나도 검사·테스트·빌드·화면 테스트가 모두 통과한다
- 경고·표시 라벨 허용 목록이 엔진 정본에서 온다는 것을 묶는 테스트

**클라이언트·화면**

- 시작, 로그인, 체류 설정, 조건 입력·동의, 병원 연결, 병원 안내, 오늘, 전체 일정, 하루 일정,
  장소 상세, 한국어 카드, 긴급 연락, 더보기, 설정, 개인정보 고지, 보호자 링크 만들기·열기, 시안 보드
- 기기 저장소와 계정 이름공간, 보기 전용 모드, 출국 7일 후 삭제, 내 정보 지우기
- 보호자 스냅샷 최소화·PIN 암호화·잠금·만료
- 4개 언어와 안전 문구 병기, 홈 화면 설치와 보기 전용 오프라인, 기기 알림
- AI 소개 문장(기본 꺼짐)과 평가 도구

## 만들었지만 실제로 확인하지 못한 것

키가 없어 **꺼진 상태로만** 검증했다. 코드 경로와 가짜 응답 테스트는 있지만 실제 응답으로 확인하지
못했다.

| 기능 | 왜 |
| --- | --- |
| 도로명주소 검색과 좌표 변환 | 행정안전부 키 2종 미발급. 변환 정확도는 알려진 지점 좌표로만 검증 |
| 일본어·중국어 관광 데이터 | 관광공사 해당 서비스 활용신청 전 |
| AI 소개 문장 | Gemini 키 미발급 + 사용 승인 전 |
| 소셜 로그인 | 제공자 자격증명이 없는 환경에서는 데모 로그인으로만 검증 |

의존성 취약점 점검(`npm run audit`)은 해결되지 않은 권고 3건 때문에 계속 실패한다. 잠금 파일은
기준 시점과 같고 이번 작업이 만든 문제가 아니다 — 아래 '진행을 막는 것'을 본다.

## 남은 것

우선순위 순. 지금 구현이 이쪽을 막지 않도록 저장 모델에 스키마 버전을 두고, 서버 라우트를 무상태로
두고, 지침을 어댑터로 받게 해 두었다.

1. **예전 판정 경로 정리** — 단일 외출 흐름 시절의 판정 모듈과 그것이 쓰는 퇴역 함수들을 지우고,
   거기 얹혀 있는 여섯 개 시나리오 테스트를 현재 일정 엔진 위로 옮긴다. 공모전 심사 증빙이
   이 모듈을 쓰고 있어 시상(2026-11-05) 이후로 미뤘다
2. **사람 승인 대기 항목 반영** — 의료진이 확정한 '모르겠음' 기본값·식이 목록·버퍼, 법무 검토를 마친
   동의 문구, 검수를 마친 일본어·중국어 안전 문구, 확인된 관광 안내 전화 발신 형식
3. **서버 저장과 동기화** — 계정별 서버 저장, 기기 간 동기화, 서버 푸시 알림
4. **보호자 실시간** — 보호자 실시간 동기화, 환자→보호자 호출, 보호자 2명 이상
5. **실제 병원 연동** — 병원 전용 어댑터와 표준 의료 데이터 매핑, 병원 발행 콘솔, 병원 측 감사 기록,
   지침 서명·위조 검증, 병원 안내문 다국어 원문 발행
6. **위치정보 검토 후 기능** — 경로 API, 지도 내장 화면, 숙소 출발 경로
7. **데이터 확장** — 관광공사 외 장소 데이터, 숙소 이동일의 체크아웃·체크인 시각 처리
8. **플랫폼 확장** — 추가 로그인 수단, 언어 추가와 번역 검수 체계, 네이티브 앱
9. **사업 모델** — 도입한다면 중립 추천·광고 표시 원칙을 먼저 정한 뒤에 한다
