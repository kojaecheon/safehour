# 기기 저장소 (`lib/store/`)

## 맡는 것

브라우저 영구 저장소에 계정별로 데이터를 두는 계층이다.

- 키 이름 규칙과 계정 이름공간
- 읽기·쓰기·구독, 다른 탭 변경 반영
- 앱 열기 정리(출국 7일 후 삭제)
- 보기 전용 상태 신호(로그인 만료·오프라인)
- '이 기기에서 내 정보 지우기'와 로그아웃 미전송 표시
- 일정 지문 계산
- 서버 알림 기기 상태: 계정 레코드 `guardianWatch`와 기기 키 `pendingServerDelete`(서버 삭제 대기), 삭제 대기 보내기

## 맡지 않는 것

- 무엇을 언제 다시 계산할지 — `lib/trip/`
- 서버 호출 — `lib/trip/`, `app/api/`
- 서버 호출의 예외는 둘이다: 로그아웃 미전송 다시 보내기와 서버 삭제 대기(`DELETE /api/watch`). 둘 다 화면이나 실행기가 떠 있지
  않아도 빠지면 안 되는 지우기라 저장소가 직접 보낸다
- 화면 상태 — `components/`

## 항상 지켜야 하는 것

- 모든 키는 `safehour.v2.` 아래에 둔다. 계정 데이터는 `safehour.v2.<계정 키>.<항목>`,
  기기 기록은 `safehour.v2.device.<항목>`이다. **새 항목도 이 접두사 아래 두면 삭제 대상에
  자동으로 들어간다** — 밖에 두면 '내 정보 지우기'가 지우지 못한다.
- 계정 키는 서버가 주는 **불투명 값**이다. 원래 계정 식별자를 저장하지 않는다.
- 탭 단위 저장소는 **보호자 링크 암호문 임시 보관 한 가지**에만 쓴다. 가져오기가 끝나거나 1시간이
  지나면 지운다. 다른 용도로 늘리지 않는다.
- '내 정보 지우기'는 접두사 아래 영구 저장 키를 **언어, 로그아웃 미전송 표시, 서버 삭제 대기만 남기고 전부** 지우고
  로그아웃한다. 모든 계정의 지켜보기 식별 값을 먼저 모아 두고, 키를 지운 뒤 서버 삭제 대기에 쓴다.
- 서버 렌더링 중에는 **비어 있는 잠긴 인스턴스**를 돌려준다. 요청 사이에 데이터가 섞이면 안 된다.
- 저장 모델에는 스키마 버전을 둔다. 나중에 서버 저장을 붙일 때 이 값이 이행의 기준이 된다.
- 로그인이 확인되기 전까지는 보기 전용이다. 조용히 쓰기를 허용하지 않는다.
- 오프라인에서 '내 정보 지우기'를 하면 로그아웃 요청이 서버에 닿지 못한 표시를 남기고, 그동안은
  세션이 남아 있어도 **로그인 상태로 보지 않는다.** 온라인이 되면 다시 보낸다.
- **서버 알림 레코드의 보기 전용 예외는 `writeBackQueue` 하나다.** 이미 있는 `guardianWatch`의 `backQueue`와 `confirmed`만 바꾼다.
  그 밖 필드는 `writeGuardianWatch`로 쓰기 가능할 때만 바꾼다. `writeGuardianWatch`는 같은 `watchId` 레코드가 있으면 저장된
  `backQueue`를 그대로 두고(올리기 결과를 쓰는 동안 눌린 '돌아왔어요'를 덮지 않게), 새로 만들 때만 받은 대기열을 쓴다.
- 레코드는 허용 목록 필드만 새로 만들어 담고(`guardianWatch.js`), 형식이 틀리면 `null`로 읽는다. 일부만 살리면 지난 마감이 서버에서
  지워질 수 있다. 대기열·보낸 확인·삭제 대기는 틀린 항목만 버리고 상한(20·20·10)을 넘으면 오래된 것부터 버린다.
- **지켜보기를 지우는 길 다섯**(끄기 `retireGuardianWatch`, 내 정보 지우기, 출국 7일 후 자동 삭제, 체류 삭제, 민감정보 동의 철회)은
  모두 저장소 안에서 식별 값을 읽어 두고 레코드를 지운 뒤 서버 삭제 대기에 넣는다. `writeGuardianWatch(null)`은 삭제 대기를 만들지
  않으므로 끄기에 쓰지 않는다. 삭제 대기는 200·404·400이면 빼고 그 밖은 남겨 온라인 복귀와 앱 열기 때 다시 보낸다(10초 한도).
- 이 폴더는 `lib/trip/`을 불러오지 않는다. 삭제 요청은 `src/guardian/watchRequests.js`(모양)와 `src/guardian/watchSend.js`(보내기와 결과
  판정)를 쓴다. 실행기와 같은 함수다.

## 구현 방식

- 저장소 구현을 주입받는 형태다. 테스트는 메모리 저장소를 넣어 브라우저 없이 돈다.
- 항목마다 구독 주제가 있고, 주제 이름은 항목 이름과 같다.
- 앱 열기 정리는 **어느 화면이 먼저 열려도 한 번** 실행된다. 삭제가 화면 순서에 좌우되면 안 된다.

## 테스트

- 계정이 다르면 데이터가 섞이지 않는지 확인한다.
- '내 정보 지우기' 뒤에 접두사 아래 키가 언어, 로그아웃 미전송 표시, 서버 삭제 대기만 남는지 단언한다.
- 보기 전용에서 `writeBackQueue`만 되고 다른 서버 알림 쓰기는 막히는지, 지우는 길 다섯이 모두 서버 삭제 대기를 남기는지 확인한다
  (`test/store-guardian-watch.test.js`).
- 출국일 + 7일이 지난 뒤 앱을 열면 그 계정 데이터가 모두 지워지는지 확인한다.
- 보기 전용 상태에서 쓰기가 막히는지 확인한다.
- 저장소가 없는 환경(서버 렌더링)에서 예외 없이 빈 인스턴스가 나오는지 확인한다.
