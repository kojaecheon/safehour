# 일정 조정 (`lib/trip/`)

## 맡는 것

기기 저장소와 일정 API 사이의 클라이언트 조정 계층이다. **언제 무엇을 다시 판정할지**를 여기서 정한다.

- 체류를 판정 요청 모양으로 깎기(허용 목록)
- 날짜별 입력 지문으로 **영향 날짜만** 골라내기
- 앱 열기 순서: 자동 삭제 정리 → 지침 재확인 → 기상 → 매일 확인
- 재계획 요청 조립과 결과 저장, 편집 기록(고정·삭제·비운 식사 칸)
- 데모 사건 누적과 날짜 전환 시 정리
- 표시용 선택자
- 서버 알림 환자 쪽(ADR-0012, A-2): 무엇을 올리고 무엇을 누르는가(`watchPlan.js`, 순수), 계기를 받아 요청을 하나씩 보내고 결과를
  반영하는 실행기(`watchSync.js`), 요청 함수(`watchApi.js`, `src/guardian/watchSend.js`를 다시 내보낸다), 화면 훅(`useWatch.js`)

## 맡지 않는 것

- 판정 규칙 — 서버가 부르는 엔진이 한다
- 저장소 키와 삭제 규칙 — `lib/store/`
- 서버 알림 레코드 정규화와 서버 삭제 대기 보내기: `lib/store/`가 한다
- 날짜별 환자 복귀 마감 계산: `src/guardian/deadlines.js`(보호자 사본과 함께 쓴다)
- 화면 상태와 그리기 — `components/`, `app/`

## 항상 지켜야 하는 것

- 요청은 **허용 목록을 통과한 값만** 담는다. 이름·주소 글자, 전화, 연동 코드, 병원 안내문을 보내지 않는다.
- 영향 날짜는 **날짜별 입력 지문 비교**로 정한다. 이름·주소 글자·전화·연동 사본·보호자 공유·수정
  시각이 바뀌었다고 재계획하지 않는다 — 판정 입력이 아니기 때문이다.
- 동반 보호자·관심사·이동 강도는 **모든 날짜**의 지문에 들어간다. 이 값이 바뀌면 전체가 다시 판정된다.
- 변화가 없으면 저장된 확정 일정을 그대로 쓴다. 열 때마다 새로 만들지 않는다.
- **언어 변경은 재판정이 아니다.** 표시만 다시 쓰는 요청을 보내고 전후 비교를 만들지 않는다.
- 매일 확인 대기와 확인하지 않은 병원 중요 안내는 **저장본을 고치지 않는다.** 표시 시점에 덧씌운다.
- 데모 사건은 오늘에 누적되고, 오늘을 다시 판정할 때마다 **전부 다시 보낸다.** 날짜가 바뀌면 지운다.
- 보기 전용일 때는 재계획·편집·연동·공유를 하지 않는다.
- 지난 날짜의 일정은 고치지 않는다.
- 닫은 마감 지남 시트는 **외출 id 와 마감 시각을 함께**(`${outingId}@${returnBy}`) 기억한다. 전체 재계획이
  외출 id 를 다시 매기므로 id 만으로 기억하면 다른 외출의 시트를 막거나 닫은 시트를 다시 띄운다.
- **서버 알림 요청은 지켜보기 하나에 한 번에 하나다.** 등록, 올리기, '돌아왔어요', 되돌리기, 끄기, 서버 지우기를 한 약속 사슬로
  줄 세우고 늘 그때의 최신 전체를 보낸다. 서버의 날짜 기록 바꾸기와 다시 등록이 원자적이지 않다.
- 응답을 받으면 레코드를 다시 읽고 `watchId`나 쓰기 토큰이 바뀌었으면 결과를 쓰지 않는다. 대기열은 `writeBackQueue`로만, 그 밖은
  `writeGuardianWatch`로만 쓴다.
- **오늘 지난 마감은 고정이다**(D1). 이미 올린 지난 시각은 일정에서 빠져도 남기고, 올린 적 없는 지난 시각은 새로 더하지 않는다.
  어제는 올리지 않는다. 일정이나 체류의 날짜를 읽지 못하면 올리지 않는다(빈 목록이 서버 기록을 지운다).
- 마감이 당겨진 외출의 판정은 `src/domain/states.js`(`isClampedOverdueOuting`, `isPulledDeadlineOuting`) 하나를 쓴다. 같은 판정의
  두 번째 경로를 만들지 않는다.
- 보기 전용에서는 마감을 올리지 않고 '돌아왔어요' 대기열만 보낸다. '전달했어요' 단계는 메모리에만 두고 `recorded: true` 전에는 만들지 않는다.
- 같은 마감의 외출이 여럿이면 '돌아왔어요'는 마지막 외출에만 있고, 앞 외출에서 보낸 확인은 나중 외출이 생기면 되돌린다. 대기열과
  `confirmed` 항목이 기기에만 들고 있는 누른 시각·출발 시각은 요청 본문에 싣지 않는다(`docs/business-rules.md` '서버 알림의 돌아왔어요').
- `watchId`, 쓰기 토큰, 날짜, 시각을 `console`, 오류 메시지, URL에 싣지 않는다. 실행기는 던지지 않는다.

## 구현 방식

- 순수 계층과 실행기를 나눈다. 순수 계층(지문, 요청 조립, 편집 기록, 선택자)은 저장소 없이 테스트할
  수 있고, 실행기는 저장소 구독과 호출 순서를 맡는다.
- 브라우저에는 기본 저장소를 쓰는 실행기가 **하나만** 있다. 여러 개를 만들면 같은 변화에 요청이 겹친다.
- 재계획 요청에는 이전 일정과 편집 기록, 다른 날짜에 이미 쓴 장소 목록을 함께 보낸다. 그래야 최소
  변경으로 고치고 같은 장소를 두 번 넣지 않는다.
- 리액트 훅은 별도 파일에 두고 공개 진입점에서 내보내지 않는다 — 서버 컴포넌트가 훅을 불러오면 깨진다.
- 서버 알림 실행기도 브라우저에 하나다(`client.js` `getWatchSync()`). 일정·체류 레코드 구독에 붙어 다른 탭의 변경도 받는다. 앱 열기·
  화면 복귀 계기는 `useTrip.js`가 건다. 저장소·요청 함수·시계·타이머·난수는 주입한다.

## 테스트

- 지문 비교는 "바꿔도 재계획되지 않아야 하는 것"을 함께 확인한다: 숙소 이름만 고치기, 전화 고치기.
- 동반 보호자를 켜고 끌 때 모든 날짜가 영향 날짜가 되는지 확인한다.
- 동의를 철회하면 해당 날짜가 입력 필요가 되는지 확인한다.
- 데모 사건이 오늘 재계획마다 다시 적용되고, 날짜가 바뀌면 사라지는지 확인한다.
- 언어를 바꿨을 때 정거장 장소 id·시각·상태가 그대로이고 전후 비교가 생기지 않는지 단언한다.
- 서버 알림: 올릴 상태와 '돌아왔어요' 대상은 `test/watch-plan.test.js`, 실행기(요청 하나씩, 404, 재시도, 대기열, 보기 전용)는
  `test/watch-sync.test.js`, 실제 처리기와 이은 요청은 `test/watch-client-seam.test.js`. 훅(`useWatch.js`)에는 단위 테스트가 없고
  화면 테스트(`e2e/server-push.spec.js`)가 결과를 본다.
