# 로그인과 세션 (`src/auth/`)

## 맡는 것

- 소셜 로그인 흐름(구글·카카오): 검증값·상태값 생성, 인가 코드 교환
- HMAC 서명 쿠키 세션 발급·검증·만료
- **불투명 계정 키** 유도 — 기기 저장소의 이름공간이 된다
- 설정값 읽기(제공자 자격증명, 서명 키, 배포 주소, 데모 로그인 스위치)

## 맡지 않는 것

- 라우트 핸들러와 응답 조립 — `app/api/auth/`, `lib/server/`
- 로그인 화면 — `app/login/`
- 보기 전용 상태 판단과 로그아웃 미전송 처리 — `lib/store/`

## 항상 지켜야 하는 것

- **제공자 토큰을 저장하지 않는다.** 인가 코드를 교환해 신원을 확인한 뒤 토큰은 즉시 버린다.
  서버가 만드는 것은 서명 쿠키 하나뿐이다.
- **계정 식별자를 저장하지 않는다.** 기기에 나가는 것은 서버 비밀값으로 유도한 되돌릴 수 없는 값뿐이다.
- 서명 키가 없거나 너무 짧으면 **로그인 기능 자체를 끈다.** 약한 키로 서명한 쿠키를 발급하지 않는다.
- 콜백 주소는 **설정된 배포 주소**로 조립한다. 요청 헤더로 만들면 호스트 헤더를 조작해 인가 코드를
  다른 주소로 보낼 수 있다.
- 상태값이 쿠키와 일치하지 않으면 거부한다.
- 요청하는 권한 범위를 넓히지 않는다. 이메일·프로필을 받지 않는 것이 의도다 — 안 쓸 정보를 받으면
  그 순간부터 지켜야 할 자산이 된다.
- 데모 로그인 경로는 환경변수가 **정확히 `1`**일 때만 연다.
- 서명 비교는 시간 일정 비교 함수를 쓴다.

## 구현 방식

- 세션 수명은 12시간이다. 회복기 사용자가 하루에 여러 번 열어도 재로그인이 잦지 않을 길이로 잡았다.
- 로그인 흐름용 짧은 수명 값과 세션 값은 다른 쿠키다. 섞지 않는다.
- 계정 키 유도는 순수 함수다 — 같은 계정·같은 비밀값이면 같은 키가 나와야 기기 데이터를 다시 찾는다.

## 테스트

- 서명 위조·만료·형식 오류가 각각 "로그인하지 않음"으로 처리되는지 확인한다.
- 서명 키가 짧을 때 로그인이 꺼지는지 확인한다.
- 계정 키가 같은 입력에 대해 안정적이고, 다른 계정끼리 겹치지 않는지 확인한다.
- 실제 제공자 자격증명을 테스트 데이터에 넣지 않는다.
