# 언어 (`src/i18n/`)

## 맡는 것

- 네 언어(한국어·영어·일본어·중국어 간체) 문구 사전과 기능별 이름공간
- 언어 결정: 사용자가 고른 값 우선, 없으면 브라우저 언어
- **안전 문구 병기 규칙** — 어떤 두 언어를 함께 보여줄지 정하는 한 곳
- 고지 문구

## 맡지 않는 것

- 문구를 화면에 그리는 일 — `components/`, `app/`
- 병원 안내문. 안내문은 번역 대상이 아니다
- 사유 코드 집합 자체. 코드는 도메인 계층이 갖고 여기는 그 문구만 채운다

## 항상 지켜야 하는 것

- **안전 문구는 선택 언어와 한국어를 함께** 보여준다. 선택 언어가 한국어면 한국어+영어다.
  환자와 보호자의 언어가 다를 수 있기 때문이다.
- 일본어·중국어 안전 문구는 **검수 스위치가 켜지기 전까지 영어+한국어로** 보여준다. 검수 전 번역으로
  안전 판정을 전하면 오역이 그대로 판정이 된다. 일반 화면 문구는 번역을 그대로 쓴다.
- 병기 규칙은 **함수 하나에만** 있다. 화면마다 조건문을 복제하면 한 화면만 검수 전 번역을 노출한다.
- 검수 스위치는 빌드 때 번들에 새겨지는 공개 값이다. 값이 **정확히 `1`**일 때만 켜진 것으로 읽는다.
- 브라우저 언어 매핑은 접두사로 한다: `ko*`→한국어, `ja*`→일본어, `zh*`→중국어, 나머지 전부 영어.
  지역 변종을 따로 나누지 않는다.
- 언어를 바꿔도 **판정은 달라지지 않는다.** 이 모듈의 값이 게이트·순위·시각 계산에 들어가면 안 된다.
- 모든 사유 코드는 네 언어가 다 있어야 한다. 빠진 언어가 있으면 그 사용자는 상태를 이해할 수 없다.

## 구현 방식

- 문구는 기능별 이름공간 파일로 나눈다. 화면 작업은 자기 이름공간 파일만 고치고, 등록 파일은
  따로 관리한다 — 여러 작업이 한 파일에 몰리면 충돌한다.
- 문구 키는 안전 문구인지 아닌지 구분할 수 있게 둔다. 그래야 병기 규칙을 자동으로 적용한다.
- 치환값은 문구 안에서 이름으로 받는다. 문장을 조각내 이어 붙이면 언어마다 어순이 달라 깨진다.

## 테스트

- 네 언어 사전에 키가 모두 있는지, 빠진 키가 없는지 단언한다.
- 병기 규칙을 스위치 꺼짐·켜짐 두 상태로 각각 확인한다. 일본어 사용자는 꺼짐에서 영어+한국어,
  켜짐에서 일본어+한국어다.
- 브라우저 언어 매핑을 지역 변종(`ja-JP`, `zh-CN`, `zh-TW`, `fr`, `ko-KR`)으로 확인한다.
