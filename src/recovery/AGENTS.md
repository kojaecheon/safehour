# 병원 지침 (`src/recovery/`)

## 맡는 것

병원이 발행하는 회복 지침을 받아들이는 경계다.

- 지침 계약 검증과 **게이트웨이 허용 목록** — 목록 밖 필드를 버린다
- 지침의 기간 목록을 조건 기간으로 바꾸는 변환
- 안내문(표시 전용 채널)과 확인 기록
- 데모 코드 연결과 데모 지침 3종

## 맡지 않는 것

- 조건 합성과 날짜 적용 판정 — `src/stay/`가 날짜마다 판정한다
- 지침 사본 저장 — `lib/store/`
- 재확인 시점 결정(앱 열기 흐름) — `lib/trip/`

## 항상 지켜야 하는 것

- **형식이 어긋나면 지침 전체를 거부한다.** 일부만 받아들이면 어떤 값이 적용됐는지 알 수 없다.
  기간의 날짜가 역순이면 전체 거부다.
- **허용 목록 밖 필드는 버린다.** 목록을 넓히는 것은 계약 변경이므로 문서와 테스트를 함께 고친다.
- **기간을 유효기간에 맞춰 잘라내지 않는다.** 그대로 저장하고 유효기간·철회 여부를 함께 담는다.
  적용 여부는 날짜마다 판정한다.
- 병원 안내문은 **표시 전용**이다. 번역·요약·편집하지 않고 판정 입력으로 쓰지 않는다.
  안내문 원문을 서버로 보내거나 로그·테스트 데이터에 남기지 않는다.
- 같은 안내문 id라도 갱신 시각이 바뀌면 확인이 풀린다. 내용이 바뀌었는데 확인이 유지되면
  사용자가 못 본 안내를 본 것으로 처리된다.
- 지침에 환자 호출 필드는 없다. 만들지 않는다.
- 지침 원문의 복귀 장소가 '병원'이면 **발행 병원**을 뜻하고 병원 id가 비어 있다. 연결할 병원이
  정해진 뒤에 채운다 — 미리 변환하면 어느 병원인지 알 수 없는 복귀 지점이 생긴다.
- 데모 지침은 **데모임을 표시**할 수 있는 형태로만 들어온다. 실제 연동처럼 보이게 하지 않는다.

## 구현 방식

- 계약 검증 → 허용 목록 통과 → 조건 기간 변환 순서다. 검증을 건너뛰고 변환하지 않는다.
- 데모 코드는 세 가지 상황을 덮는다: 외출 허용 기간을 담은 정상 지침, 외출 제한 기간을 담은 지침,
  이미 만료된 지침. 만료된 지침도 기간은 저장되고 날짜별 판정에서 걸러진다.
- 확인 기록의 정본은 `안내문 id@갱신시각` 형태의 키다. 받은 지침 안의 확인 표시는 버린다.

## 테스트

- 예전 계약(기간 목록이 없는 형태) 코드를 연결하면 거부되는지 확인한다.
- 허용 목록 밖 필드를 섞은 지침을 넣고 결과에 그 필드가 없는지 단언한다.
- 이미 만료된 지침을 연결해도 기간이 저장되고, 경계일 이후 날짜가 '입력 필요'가 되는지 확인한다.
- 안내문 갱신 시각을 바꾸면 확인이 풀리는지 확인한다.
