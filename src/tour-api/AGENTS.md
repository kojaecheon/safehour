# 관광 후보 (`src/tour-api/`)

## 맡는 것

관광공사 데이터를 받아 **장소 후보**로 바꾸는 계층이다.

- 조회와 캐시, 하루 호출 한도(경고·차단), 응답 파싱
- 언어별 서비스 선택(국문 + 무장애는 항상, 선택 언어가 영어·일본어·중국어면 그 서비스를 더함)과
  언어 간 매칭, 같은 장소 중복 제거
- 후보 신호 추정: 실내 여부, 보행 부담, 식이 단서(매운·날것·주점·카페), 열·물 노출 단서, 관심사 매핑
- 날짜 기준 휴무 판정과 '운영 확인 필요' 표시
- 장소 상세 보강(개요·운영·이미지·메뉴)
- **단서 목록과 관심사 매핑의 정본** — 이 모듈 상수 한곳에 둔다

## 맡지 않는 것

- 후보를 일정에 넣을지 판단하는 일 — 게이트와 배치는 `src/engine/`
- 조건 값 해석 — `src/stay/`
- 숫자 기본값(반경·한도 등)은 체류 도메인의 기본값 파일이 정본이다. 여기에 복제하지 않는다

## 항상 지켜야 하는 것

- **관광공사 원문과 앱의 추정값을 같은 필드에 섞지 않는다.** 원문은 원문 필드에, 추정은 추정 필드에
  두고 화면이 '추정' 표시를 붙일 수 있게 한다.
- **열려 있다고 단정하지 않는다.** 닫힘 근거가 있을 때만 제외하고, 근거가 없으면 '운영 확인 필요'다.
- 언어 간 매칭은 같은 장소 id이거나 **같은 유형이면서 20m 이내**일 때만 한다. 제목 유사도로 같은
  장소라고 보지 않는다 — 다른 장소를 합치면 잘못된 주소로 사람을 보낸다.
- 이미지는 URL과 저작권 구분만 쓴다. **파일을 내려받지 않는다.**
- 캐시에 저장하는 값에 **기준점 좌표를 남기지 않는다.** 파일 이름이 해시여도 본문이 그대로면 소용없다.
- 전체 조회 URL을 로그·테스트 데이터·문서에 남기지 않는다. 질의 문자열에 인증키가 들어 있다.
- 숙박 유형은 후보에서 제외한다(관광 활동이 아니다).
- 단서 목록을 화면이나 엔진에 복제하지 않는다. 복제하면 한쪽만 고쳐졌을 때 판정과 표시가 어긋난다.

## 구현 방식

- 기준점과 반경 조합마다 **한 번** 목록을 조회하고 캐시를 쓴다. 날짜마다 다시 조회하지 않는다.
- 상세 보강은 일정에 들어갈 후보와 교체 후보에만 한다. 목록 전체를 보강하면 호출량이 폭발한다.
- 선택 언어 서비스가 없거나 실패하면 영문으로, 영문도 없으면 국문을 보여주고 '번역 필요'를 붙인다.
- 호출 한도는 환경변수로 조정할 수 있게 두고, 잘못된 값이 들어오면 기본값으로 돌아간다.

## 테스트

- 모든 테스트는 **가짜 응답**으로 돈다. 실제 호출을 하는 테스트를 만들지 않는다.
- 캐시를 만든 뒤 저장된 파일 안에 기준점 좌표가 없는지 단언한다. 새 캐시를 도입하면 같은 테스트를
  함께 만든다.
- 휴무는 **일정 날짜의 요일 기준**으로 판정하는지 확인한다. 오늘 기준으로 판정하면 미래 날짜가 틀린다.
- 식이 필터는 항목마다 기준이 다르다: 주점은 유형으로 제외, 매운·날것은 단서가 없어도 제외,
  뜨거운·딱딱한 것은 제외하지 않고 주문 카드를 붙인다. 네 가지를 각각 고정한다.
- 카페·전통찻집 유형이 매운 음식·날음식 필터에서 제외되지 않는지 확인한다.
